# Mr. Robot CTF (TryHackMe): Εγχειρίδιο Δοκιμής Διείσδυσης

![Mr. Robot CTF](images/img-01.jpg)

*Εικόνα 1. Η επίσημη απεικόνιση της αίθουσας Mr. Robot στην πλατφόρμα TryHackMe.*

Η παρούσα μελέτη συνιστά εγχειρίδιο δοκιμής διείσδυσης (penetration testing manual) για την εικονική μηχανή Mr. Robot. Η δομή ακολουθεί το μεθοδολογικό πλαίσιο του Penetration Testing Execution Standard (PTES) και τις κατευθύνσεις του NIST SP 800-115, καλύπτοντας διαδοχικά τις φάσεις του reconnaissance, του enumeration, του initial access, του user pivoting και του privilege escalation. Κάθε εντολή εξετάζεται σε δύο επίπεδα: στο επίπεδο του πρωτοκόλλου και της συμπεριφοράς του λειτουργικού συστήματος, και στο επίπεδο της μεθοδολογικής της αναγκαιότητας, δηλαδή του λόγου για τον οποίο η συγκεκριμένη ενέργεια καθιστά εφικτή την επόμενη.

Αντικείμενο της άσκησης είναι ο εντοπισμός τριών συμβολοσειρών ελέγχου (key 1, key 2, key 3), οι οποίες αντιπροσωπεύουν ισάριθμα επίπεδα πρόσβασης: το επίπεδο του ανώνυμου επισκέπτη της web εφαρμογής, το επίπεδο του τοπικού χρήστη συστήματος και το επίπεδο του root. Η πορεία από το πρώτο στο τρίτο επίπεδο δεν προϋποθέτει την ύπαρξη ενιαίας κρίσιμης ευπάθειας, αλλά τον συνδυασμό επιμέρους αδυναμιών διαμόρφωσης, γεγονός που καθιστά το σενάριο διδακτικά αντιπροσωπευτικό πραγματικών περιστατικών.

Σημειώνεται ότι το σύνολο των τεχνικών εκτελείται αποκλειστικά εντός περιβάλλοντος για το οποίο υφίσταται ρητή άδεια διενέργειας δοκιμών. Η εφαρμογή των ιδίων τεχνικών σε συστήματα τρίτων, άνευ εγγράφου εξουσιοδότησης, συνιστά ποινικά κολάσιμη πράξη και αντιβαίνει στους κώδικες δεοντολογίας του επαγγέλματος.

> **Ορολογία:** οι καθιερωμένοι τεχνικοί όροι (reconnaissance, enumeration, wordlist, brute-force, hash, salt, rainbow tables, reverse shell, payload, shell, PTY, SUID bit, EUID, proxy, privilege escalation) αποδίδονται στην αγγλική τους μορφή, όπως άλλωστε χρησιμοποιούνται στην τεχνική βιβλιογραφία, στις προδιαγραφές και στα εργαλεία. Η ελληνική απόδοση δίνεται μόνο όπου απαιτείται για την κατανόηση της έννοιας.

## 1. Χάρτης της επίθεσης

| Φάση | Ενέργεια | Τεχνικό αποτέλεσμα | Κρίσιμο εύρημα |
| :--- | :--- | :--- | :--- |
| Reconnaissance | Port και service scanning | Ταυτοποίηση Apache και WordPress | Θύρες 80 και 443 |
| Enumeration | Directory scanning, ανάγνωση robots.txt | Αποκάλυψη πόρων | Key 1 και wordlist |
| Credentials | Ανάλυση error messages, brute-force | Έγκυρος λογαριασμός admin | elliot και password |
| Initial access | Επεξεργασία theme template | Απομακρυσμένη εκτέλεση κώδικα | Shell ως daemon |
| User pivoting | Ανάκτηση hash, αλλαγή χρήστη | Αύξηση επιπέδου πρόσβασης | Key 2 |
| Privilege escalation | Κατάχρηση SUID bit | Πρόσβαση root | Key 3 |

Η ανωτέρω αλληλουχία καταδεικνύει ότι η ασφάλεια ενός πληροφοριακού συστήματος δεν εξαρτάται από την ισχύ ενός μεμονωμένου μηχανισμού, αλλά από τη συνέπεια του συνόλου των μέτρων. Η αστοχία ενός εκ των σταδίων θα ήταν αρκετή για τη διακοπή της αλυσίδας.

## 2. Φάση πρώτη: Reconnaissance και χαρτογράφηση

### 2.1 Εκτέλεση της σάρωσης

```bash
nmap <target-ip> -sV -T4 -oA nmap-scan -open
```

Η εντολή `nmap` αποτελεί το καθιερωμένο εργαλείο network mapping και αξιολογείται, στο πλαίσιο της παρούσας άσκησης, ως το σημείο εκκίνησης κάθε δοκιμής. Η παράμετρος `<target-ip>` προσδιορίζει τη διεύθυνση IPv4 του υπό εξέταση κόμβου και αποτελεί τη μοναδική μεταβλητή της εντολής που εξαρτάται από το περιβάλλον εκτέλεσης. Σημειώνεται ότι η σάρωση πραγματοποιείται επί του TCP, καθώς οι υπηρεσίες που ενδιαφέρουν τη συγκεκριμένη ανάλυση είναι κατά κανόνα connection-oriented.

Η σημαία `-sV` ενεργοποιεί το service και version detection. Το εργαλείο δεν αρκείται στον καθιερωμένο από την IANA συσχετισμό port και service, αλλά αποστέλλει σειρά εξειδικευμένων probes, συλλέγει τα banners και τις αποκρίσεις και τις αντιπαραβάλλει με τη βάση υπογραφών `nmap-service-probes`. Αποτέλεσμα της διαδικασίας είναι η ταυτοποίηση της υλοποίησης και, συχνά, της ακριβούς version του λογισμικού, στοιχείο καθοριστικό για τη συνέχεια, καθώς η γνώση της version επιτρέπει τον εντοπισμό γνωστών CVEs.

Η σημαία `-T4` ρυθμίζει το timing template σε επίπεδο aggressive. Η ρύθμιση μειώνει τα timeouts και αυξάνει τον ρυθμό αποστολής πακέτων, με αποτέλεσμα τη δραστική συντόμευση της διαδικασίας. Η επιλογή τεκμηριώνεται από τη φύση του περιβάλλοντος, το οποίο είναι τοπικό, ελεγχόμενο και χαμηλής καθυστέρησης. Αντιθέτως, σε δίκτυα παραγωγής η ίδια ρύθμιση ενδέχεται να προκαλέσει packet loss και να καταστήσει τη σάρωση ανιχνεύσιμη από IDS.

Η σημαία `-open` λειτουργεί ως φίλτρο παρουσίασης, περιορίζοντας την έξοδο στις θύρες που βρίσκονται σε κατάσταση listening. Η επιλογή δεν επηρεάζει τη διενέργεια της σάρωσης, αλλά διευκολύνει την ερμηνεία των αποτελεσμάτων, αποκλείοντας τις closed και τις filtered θύρες από την αναφορά. Τέλος, η παράμετρος `-oA nmap-scan` παράγει τρία αρχεία ταυτόχρονα, σε μορφή απλού κειμένου, XML και μορφή κατάλληλη για grep, διασφαλίζοντας το audit trail των ευρημάτων.

Η υπόθεση αυτή επιβεβαιώνεται στην επόμενη φάση.

## 3. Φάση δεύτερη: Web enumeration

### 3.1 Directory scanning

```bash
gobuster dir -u http://<target-ip> -w /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt
```

Το `gobuster` αποτελεί εργαλείο content discovery, υλοποιημένο στη γλώσσα Go, και βασίζεται στην αρχιτεκτονική των goroutines για την παράλληλη εκτέλεση μεγάλου αριθμού requests. Η υποεντολή `dir` ενεργοποιεί τη λειτουργία directory scanning, κατά την οποία το εργαλείο αποστέλλει διαδοχικά HTTP requests προς τη βασική διεύθυνση, προσαρτώντας σε αυτήν κάθε λέξη του wordlist. Η προσέγγιση στηρίζεται στην εμπειρική παρατήρηση ότι τα ονόματα των πόρων ακολουθούν συνήθως συγκεκριμένα πρότυπα, τα οποία απαντούν σε στατιστικά καταρτισμένα wordlists.

Η παράμετρος `-u` προσδιορίζει το base URL του στόχου, ενώ η παράμετρος `-w` δηλώνει το αρχείο λέξεων. Το συγκεκριμένο wordlist περιλαμβάνει paths προερχόμενα από καταγραφές πραγματικών συστημάτων και καλύπτει, κατά τεκμηριωμένη εκτίμηση, μεγάλο μέρος των συνηθισμένων ονοματολογιών. Η αξιολόγηση των αποτελεσμάτων βασίζεται στα HTTP status codes: απόκριση `200` ή `301`/`302` τεκμηριώνει την ύπαρξη πόρου, ενώ απόκριση `404` δηλώνει απουσία.

Η μέθοδος ενέχει περιορισμούς που οφείλεται να αναγνωρίζονται. Πρώτον, η επιτυχία της εξαρτάται άμεσα από την ποιότητα του wordlist. Δεύτερον, παράγει σημαντικό όγκο requests και, ως εκ τούτου, είναι ανιχνεύσιμη από logging systems. Τρίτον, η απόκριση `403` δεν σημαίνει απουσία πόρου, αλλά ύπαρξη πόρου με απαγορευμένη πρόσβαση, στοιχείο το οποίο οφείλεται επίσης να καταγράφεται.

Η παρουσία των συγκεκριμένων paths συνιστά ασφαλή ένδειξη ότι ο στόχος φιλοξενεί content management system και όχι στατική ιστοσελίδα. ### 3.3 Το αρχείο robots.txt και η ανάκτηση του key 1

![Περιεχόμενο του robots.txt](images/img-04.png)

*Εικόνα 5. Το περιεχόμενο του αρχείου robots.txt, με δύο καταχωρίσεις σε κατάσταση αποκλεισμού.*

Το αρχείο `robots.txt` θεσπίστηκε στο πλαίσιο του Robots Exclusion Protocol και αποσκοπεί στη ρύθμιση της συμπεριφοράς των web crawlers. Πρόκειται για δημόσια προσβάσιμο αρχείο, το περιεχόμενο του οποίο διαβάζεται από οποιονδήποτε διαθέτει πρόσβαση στον server, ανεξαρτήτως δικαιωμάτων. Η συγκεκριμένη ιδιότητα καθιστά το αρχείο πηγή πληροφόρησης για τον ελεγκτή και, ταυτοχρόνως, παράγοντα διακινδύνευσης για τον διαχειριστή.

Στην υπό εξέταση περίπτωση, το αρχείο περιλαμβάνει δύο καταχωρίσεις αποκλεισμού: το path `/fsocity.dic` και το path `/key-1-of-3.txt`. Το πρώτο αντιστοιχεί σε wordlist και το δεύτερο σε αρχείο κλειδιού. Εφόσον η πρόσβαση στα εν λόγω paths δεν προστατεύεται από authentication mechanism, η αναγραφή τους στο `robots.txt` λειτουργεί ως υπόδειξη προς τον ελεγκτή, αντιστρέφοντας τον σκοπό για τον οποίο δημιουργήθηκε το αρχείο.

```bash
curl http://<target-ip>/key-1-of-3.txt
```

Η ανάκτηση του key 1 πραγματοποιείται με απλό HTTP request, χωρίς την αξιοποίηση ευπάθειας λογισμικού. Το εύρημα κατατάσσεται στην κατηγορία της information disclosure και καταδεικνύει ότι η απόκρυψη πόρων δεν συνιστά μέτρο ασφάλειας. Η ορθή πρακτική συνίσταται στην προστασία των πόρων μέσω authorization mechanisms και στην αποφυγή αναγραφής ευαίσθητων paths σε δημόσια αρχεία.

## 4. Φάση τρίτη: Επεξεργασία δεδομένων και απόκτηση credentials

### 4.1 Βελτιστοποίηση του wordlist

```bash
wc -w fsocity.dic
sort fsocity.dic | uniq -d > fs-list
sort fsocity.dic | uniq -u >> fs-list
wc -w fs-list
```

Η εντολή `wc` με τη σημαία `-w` υπολογίζει τον αριθμό των λέξεων ενός αρχείου. Η αρχική μέτρηση ανέρχεται σε 858.160 λέξεις, μέγεθος το οποίο, εάν χρησιμοποιηθεί αυτούσιο σε brute-force attack, θα συνεπαγόταν υπέρμετρη διάρκεια και σημαντικό φόρτο για τον server. Η προεπεξεργασία του wordlist αποτελεί, επομένως, αναγκαίο στάδιο για τη βελτιστοποίηση της επίθεσης.

Η εντολή `sort` αναδιατάσσει τις γραμμές σε λεξικογραφική σειρά. Η ταξινόμηση δεν αποτελεί αισθητική επιλογή, αλλά αυστηρή προϋπόθεση για τη λειτουργία της επόμενης εντολής, καθώς η `uniq` εντοπίζει duplicates συγκρίνοντας αποκλειστικά γειτονικές γραμμές. Χωρίς προηγούμενη ταξινόμηση, πανομοιότυπες εγγραφές που δεν γειτονεύουν θα παρέμεναν απαρατήρητες. Το pipe `|` επιτρέπει την απευθείας τροφοδότηση της επόμενης διεργασίας, χωρίς ενδιάμεση εγγραφή στον δίσκο.

Η εντολή `uniq -d` απομονώνει τις εγγραφές που εμφανίζονται περισσότερες από μία φορές, ενώ η `uniq -u` απομονώνει όσες εμφανίζονται άπαξ. Ο συνδυασμός των δύο, με χρήση του τελεστή `>` για δημιουργία και του `>>` για append, παράγει αρχείο μίας εγγραφής ανά διακριτή λέξη. Η τελική μέτρηση ανέρχεται σε 11.451 λέξεις, μείωση της τάξεως του 98,6 τοις εκατό. Ισοδύναμο, και απλούστερο, αποτέλεσμα παράγει η εντολή `sort -u fsocity.dic > fs-list`.

### 4.2 Η θεωρία του user enumeration μέσω error messages

Το user enumeration συνιστά τεχνική κατά την οποία ο ελεγκτής συνάγει την ύπαρξη λογαριασμών από διαφορές στη συμπεριφορά της εφαρμογής. Η πλέον συνήθης ένδειξη είναι η διαφοροποίηση των error messages κατά την αποτυχημένη authentication. Η πρακτική αυτή καταγράφεται ως αδυναμία observable response discrepancy (CWE-204) και αξιολογείται ως μεσαίας σοβαρότητας, διότι διευκολύνει τελικώς brute-force επιθέσεις.

Στην περίπτωση του WordPress, η εφαρμογή επιστρέφει διακριτά μηνύματα ανάλογα με την ύπαρξη του λογαριασμού. Όταν το username δεν υφίσταται, το μήνυμα αναφέρει «Invalid username». Όταν το username υφίσταται αλλά το password είναι εσφαλμένο, το μήνυμα αναφέρει ότι το password για τον συγκεκριμένο χρήστη είναι λανθασμένο. Η διαφορά είναι επαρκής ώστε να καταστεί δυνατή η διάκριση των έγκυρων λογαριασμών.

Η ορθή πρακτική συνίσταται στην επιστροφή ενιαίου μηνύματος, ανεξαρτήτως της αιτίας αποτυχίας, σε συνδυασμό με σταθερό response time. Περαιτέρω μέτρα περιλαμβάνουν το rate limiting, το account lockout μετά από σειρά αποτυχιών και την εφαρμογή multi-factor authentication για λογαριασμούς admin.

### 4.3 Καταγραφή του authentication request

![Μήνυμα σφάλματος για άκυρο χρήστη](images/img-06.jpg)

*Εικόνα 7. Αποτυχημένη login attempt με τυχαία credentials και εμφάνιση του μηνύματος «ERROR: Invalid username».*

Η εικόνα τεκμηριώνει την πρώτη ένδειξη της αδυναμίας. Η απόπειρα πραγματοποιείται με αυθαίρετα credentials και το σύστημα αποκρίνεται με μήνυμα το οποίο δηλώνει ρητώς την ανυπαρξία του λογαριασμού. Η πληροφορία αυτή είναι αξιοποιήσιμη ως failure condition σε αυτοματοποιημένη επίθεση, καθώς επιτρέπει τη διάκριση μεταξύ ανύπαρκτου και υφιστάμενου λογαριασμού.

![Καταγραφή αιτήματος μέσω proxy](images/img-07.png)

*Εικόνα 8. Καταγραφή του login request στο περιβάλλον του Burp Suite Proxy.*

### 4.4 Απόκτηση έγκυρου username

Η εντολή αξιοποιεί το εργαλείο `hydra`, το οποίο εξειδικεύεται στην αυτοματοποιημένη δοκιμή credentials σε δικτυακά πρωτόκολλα. ### 6.2 Η αδυναμία του MD5 ως αλγορίθμου αποθήκευσης passwords

Ο αλγόριθμος MD5 σχεδιάστηκε ως συνάρτηση σύνοψης και όχι ως password hashing function. Χαρακτηρίζεται από υψηλή ταχύτητα υπολογισμού και απουσία μηχανισμού επιβράδυνσης, ιδιότητες οι οποίες τον καθιστούν ακατάλληλο για την αποθήκευση passwords. Η ταχύτητα, η οποία αποτελεί πλεονέκτημα σε εφαρμογές data integrity, μετατρέπεται σε μειονέκτημα ασφάλειας, καθώς επιτρέπει τη μαζική δοκιμή υποψηφίων passwords σε ελάχιστο χρόνο.

Περαιτέρω, η απουσία salt συνεπάγεται ότι το ίδιο password παράγει το ίδιο hash σε κάθε σύστημα. Το γεγονός επιτρέπει τη χρήση rainbow tables και διαδικτυακών βάσεων, στις οποίες αντιστοιχίζονται γνωστά hashes με τα πρωτότυπα κείμενα. Η πρακτική της αναζήτησης σε τέτοια βάση ισοδυναμεί, ως προς το αποτέλεσμα, με άμεση ανάκτηση password.

Η σύγχρονη πρακτική συνίσταται στη χρήση key derivation functions με σκόπιμη υπολογιστική επιβάρυνση, όπως οι bcrypt, scrypt και Argon2, σε συνδυασμό με μοναδικό salt ανά εγγραφή. Οι συναρτήσεις αυτές καθιστούν τη μαζική δοκιμή οικονομικά ασύμφορη.

![Ανάκτηση password μέσω διαδικτυακής βάσης](images/img-18.png)

*Εικόνα 19. Η ανάκτηση του plaintext μέσω διαδικτυακής βάσης hashes.*

Η εικόνα τεκμηριώνει την άμεση ανάκτηση του password. Το αποτέλεσμα καταδεικνύει ότι το hash περιλαμβανόταν σε διαρρεύσα σύνολο δεδομένων και ότι η απουσία salt κατέστησε δυνατή την αντιστοίχιση. Η σύντομη διάρκεια της διαδικασίας υπογραμμίζει την πρακτική σημασία της επιλογής αλγορίθμου.

### 7.1 Αναζήτηση εκτελέσιμων με SUID bit

```bash
find / -perm -u=s -type f 2>/dev/null
```

Η εντολή `find` πραγματοποιεί αναδρομική διάσχιση του filesystem, ξεκινώντας από τον root directory. Το κριτήριο `-perm -u=s` περιορίζει τα αποτελέσματα σε αρχεία των οποίων τα permissions περιλαμβάνουν το SUID bit (Set User ID). Το κριτήριο `-type f` αποκλείει directories, symbolic links και special devices.

Η ανακατεύθυνση `2>/dev/null` οδηγεί το stderr στην ειδική συσκευή απόρριψης. Η ενέργεια είναι αναγκαία, διότι η διάσχιση προστατευμένων directories από μη προνομιούχο χρήστη παράγει πλήθος μηνυμάτων permission denied, τα οποία θα καθιστούσαν την έξοδο δυσανάγνωστη.

Το SUID bit συνεπάγεται ότι η διεργασία εκτελείται με τα δικαιώματα του ιδιοκτήτη του αρχείου και όχι του χρήστη που την εκκίνησε. Η δυνατότητα είναι απαραίτητη για προγράμματα όπως η αλλαγή password, πλην όμως καθίσταται επικίνδυνη όταν αποδίδεται σε εργαλεία γενικής χρήσης, τα οποία επιτρέπουν την εκτέλεση αυθαίρετων εντολών.


Η κλήση ενεργοποιεί την interactive console του εργαλείου. Η χρήση absolute path είναι αναγκαία, προκειμένου να διασφαλιστεί η εκτέλεση του συγκεκριμένου αρχείου και όχι ενδεχομένως διαφορετικής version ευρισκόμενης στο PATH.

Εντός της console εκτελείται η εντολή διαφυγής:

```bash
!sh
```

Η εντολή αναθέτει στο εργαλείο την εκκίνηση shell μέσω της system() function του λειτουργικού συστήματος. Επειδή η μητρική διεργασία φέρει ενεργό EUID 0, η θυγατρική διεργασία κληρονομεί ισοδύναμα δικαιώματα. Κατά συνέπεια, το shell που αποκτάται είναι root shell.

![Απόκτηση root shell](images/img-23.png)

*Εικόνα 24. Η εκτέλεση της τεχνικής και η επιβεβαίωση των δικαιωμάτων root.*

Η εικόνα τεκμηριώνει την επιτυχή κλιμάκωση. Η επιβεβαίωση πραγματοποιείται με την εντολή αναγνώρισης ταυτότητας, η οποία επιστρέφει το όνομα του root. Από το σημείο αυτό, η πρόσβαση στο σύνολο του filesystem καθίσταται εφικτή.

### 7.4 Ανάκτηση του key 3

![Ανάγνωση του τελικού κλειδιού](images/img-24.png)

*Εικόνα 25. Η ανάγνωση του τελικού key από τον home directory του root.*

Η εικόνα ολοκληρώνει την αλυσίδα της επίθεσης. Το τελικό key ευρίσκεται εντός του home directory του root, του οποίου η πρόσβαση προϋποθέτει root δικαιώματα. Η ανάκτησή του επιβεβαιώνει την πλήρη κατάληψη του συστήματος και την ολοκλήρωση της δοκιμής.

## 8. Εναλλακτικές τεχνικές

### 8.1 Επίθεση μέσω intercepting proxy

![Αποστολή αιτήματος προς αυτοματοποίηση](images/img-25.png)

*Εικόνα 26. Η αποστολή του καταγεγραμμένου request στη μονάδα αυτοματοποιημένων requests.*

Η εικόνα τεκμηριώνει τη δυνατότητα μεταφοράς καταγεγραμμένου request από το HTTP history του proxy προς τη μονάδα αυτοματοποίησης. Η δυνατότητα αυτή επιτρέπει την επανάχρηση του request χωρίς εκ νέου σύνταξη, μειώνοντας την πιθανότητα σφάλματος.

![Ορισμός θέσεων μεταβλητών](images/img-26.png)

*Εικόνα 27. Ο ορισμός των θέσεων στις οποίες εισάγονται οι υποψήφιες τιμές.*

Η εικόνα παρουσιάζει τον ορισμό των payload positions. Η παράμετρος του username τίθεται σε σταθερή τιμή, ενώ η παράμετρος του password περιβάλλεται από ειδικούς δείκτες, οι οποίοι δηλώνουν τη θέση εισαγωγής των υποψηφίων τιμών. Η διάκριση μεταξύ σταθερών και μεταβλητών θέσεων αποτελεί προϋπόθεση ορθής εκτέλεσης.

![Φόρτωση wordlist](images/img-27.jpg)

*Εικόνα 28. Η φόρτωση του βελτιστοποιημένου wordlist ως πηγής υποψηφίων τιμών.*

Η εικόνα τεκμηριώνει τη φόρτωση του wordlist. Η χρήση του βελτιστοποιημένου αρχείου περιορίζει τον αριθμό των requests και, κατά συνέπεια, τη διάρκεια της διαδικασίας. Η επιλογή του αρχείου αποτελεί το τελευταίο στάδιο πριν την εκτέλεση της επίθεσης.

![Ανάλυση αποτελεσμάτων](images/img-28.png)

*Εικόνα 29. Η ταξινόμηση των αποτελεσμάτων και ο εντοπισμός της επιτυχούς απόπειρας.*

Η εικόνα παρουσιάζει την ανάλυση των αποτελεσμάτων. Η επιτυχής απόπεια διακρίνεται είτε από μεταβολή του status code είτε από μεταβολή του response length. Η δυνατότητα διάκρισης καθιστά την τεχνική λειτουργική, πλην όμως η απόδοσή της περιορίζεται από το rate limiting της δωρεάν έκδοσης του εργαλείου.

### 8.2 Επίθεση μέσω εξειδικευμένου scanner

```bash
wpscan --url http://<target-ip> -t 50 -U elliot -P fs-list
```

Το εργαλείο αξιολογεί την ασφάλεια εγκαταστάσεων WordPress και αναγνωρίζει εγγενώς τη δομή των μηνυμάτων και των forms της πλατφόρμας. Κατά συνέπεια, δεν απαιτείται ο χειροκίνητος ορισμός failure condition, όπως στην περίπτωση του γενικού credential testing εργαλείου. Η σημαία `-U` ορίζει το username και η `-P` τον κατάλογο passwords.

Η σημαία `-t 50` ορίζει τον αριθμό των ταυτόχρονων threads. Εφόσον η XML-RPC interface της πλατφόρμας είναι ενεργή, το εργαλείο δύναται να χρησιμοποιήσει την τεχνική multi-call και να περιορίσει τον αριθμό των απαιτούμενων requests. Η δυνατότητα αυτή καθιστά την επίθεση αποδοτικότερη, πλην όμως προϋποθέτει τη σχετική διαμόρφωση.

![Επιτυχής επίθεση μέσω εξειδικευμένου scanner](images/img-29.png)

*Εικόνα 30. Η επιβεβαίωση των credentials μέσω του εξειδικευμένου scanner.*

Η εικόνα τεκμηριώνει την επιτυχία της εναλλακτικής μεθόδου. Το αποτέλεσμα ταυτίζεται με το αποτέλεσμα της γενικής μεθόδου, γεγονός το οποίο επιβεβαιώνει την αρχή ότι τα εργαλεία διαφέρουν ως προς την υλοποίηση και όχι ως προς το μεθοδολογικό αποτέλεσμα.

### 8.3 Password cracking μέσω εξειδικευμένου εργαλείου

```bash
john --format=Raw-MD5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

Η παράμετρος format δηλώνει ρητώς τον hash algorithm, αποτρέποντας τη χρονοβόρα αυτόματη αναγνώριση. Η παράμετρος wordlist ορίζει την πηγή των υποψηφίων passwords. Το εργαλείο υπολογίζει το hash εκάστης λέξεως και το συγκρίνει με το ζητούμενο digest.

![Ανάκτηση password μέσω εργαλείου λεξικού](images/img-30.png)

*Εικόνα 31. Η επιτυχής ανάκτηση του password μέσω τοπικής επεξεργασίας.*

Η εικόνα τεκμηριώνει την επιτυχία της τοπικής μεθόδου. Η ταχύτητα της διαδικασίας οφείλεται αφενός στην απλότητα του αλγορίθμου και αφετέρου στην ύπαρξη του password εντός του wordlist. Το αποτέλεσμα επιβεβαιώνει την ανάλυση περί καταλληλότητας των αλγορίθμων.

### 8.4 Επιτάχυνση μέσω GPU

```bash
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
```

Η παράμετρος `-m 0` δηλώνει τον αλγόριθμο MD5. Το εργαλείο κατανέμει τους υπολογισμούς στις compute units της GPU, επιτυγχάνοντας ρυθμούς υπερκείμενους των συμβατικών CPUs κατά τάξεις μεγέθους.

![Επιτάχυνση μέσω GPU](images/img-31.png)

*Εικόνα 32. Η ολοκλήρωση της διαδικασίας με χρήση GPU.*

Η εικόνα τεκμηριώνει την ολοκλήρωση της διαδικασίας σε ελάχιστο χρόνο. Το παράδειγμα καθιστά εμφανή την επίπτωση της επιλογής αλγορίθμου: αλγόριθμος σχεδιασμένος για ταχύτητα καθίσταται, υπό συνθήκες μαζικού παραλληλισμού, πρακτικώς ανίσχυρος.

## 9. Αξιολόγηση ευρημάτων και μέτρα αποκατάστασης

| Φάση | Μέσο | Αδυναμία | Αποτέλεσμα |
| :--- | :--- | :--- | :--- |
| Reconnaissance | Port scanning | Περιορισμένο attack surface, μη ενημερωμένη στοίβα | Ταυτοποίηση πλατφόρμας |
| Enumeration | Directory scanning | Μη ευρετηριασμένοι πόροι | Key 1 και wordlist |
| Information disclosure | Δημόσιο configuration file | Αναγραφή ευαίσθητων paths | Αποκάλυψη πόρων |
| Enumeration | Error messages | Observable response discrepancy (CWE-204) | Έγκυρο username |
| Brute-force | Wordlist | Αδύναμο password | Admin credentials |
| Initial access | Theme editor | Ενεργή δυνατότητα επεξεργασίας κώδικα | Remote code execution |
| User pivoting | MD5 hash | Αδύναμος αλγόριθμος, χωρίς salt | Key 2 |
| Privilege escalation | SUID bit | Απονομή ειδικών δικαιωμάτων σε γενικό εργαλείο | Key 3 |

Η συνολική αξιολόγηση καταδεικνύει αποτυχία της αρχής της άμυνας σε βάθος (defense in depth). Ουδέν εκ των ευρημάτων θα ήταν, μεμονωμένως, ικανό να οδηγήσει σε πλήρη κατάληψη. Ο συνδυασμός τους, εντούτοις, κατέστησε εφικτή τη σταδιακή μετάβαση από το επίπεδο του ανώνυμου επισκέπτη στο επίπεδο του root.

### 9.1 Προτεινόμενα μέτρα

1. Αφαίρεση ευαίσθητων καταχωρίσεων από το `robots.txt` και προστασία των σχετικών πόρων μέσω authorization mechanisms.
2. Ενοποίηση των error messages κατά την authentication, με σταθερό response time, ώστε να μην καθίσταται δυνατό το user enumeration.
3. Εφαρμογή rate limiting και account lockout, καθώς και multi-factor authentication για admin λογαριασμούς.
4. Απενεργοποίηση της δυνατότητας επεξεργασίας theme και plugin files μέσω της σταθεράς `DISALLOW_FILE_EDIT`.
5. Εφαρμογή password policy και περιοδικός έλεγχος ανθεκτικότητας με password cracking εργαλεία.
6. Αντικατάσταση απαρχαιωμένων hash functions με σύγχρονες key derivation functions, εφοδιασμένες με μοναδικό salt.
7. Αφαίρεση του SUID bit από εκτελέσιμα γενικής χρήσης και περιοδικός έλεγχος του συνόλου των σχετικών αρχείων.
8. Εγκατάσταση web application firewall με κανόνες κατά brute-force επιθέσεων και ενεργοποίηση logging των αποτυχημένων attempts.
9. Εφαρμογή της αρχής των ελαχίστων προνομίων στα δικαιώματα του service user και στα file permissions.

## Παράρτημα Α. Γλωσσάρι

| Όρος | Ερμηνεία |
| :--- | :--- |
| Reconnaissance | Συλλογή πληροφοριών για τον στόχο, παθητική ή ενεργητική |
| Enumeration | Συστηματική καταγραφή πόρων, λογαριασμών και versions |
| Wordlist | Αρχείο λέξεων για brute-force και dictionary attacks |
| Brute-force | Εξαντλητική δοκιμή συνδυασμών credentials |
| Hash | Αποτύπωμα μονόδρομης συνάρτησης, μη αντιστρέψιμο |
| Salt | Τυχαία τιμή που καθιστά μοναδικό έκαστο hash |
| Rainbow tables | Προϋπολογισμένοι πίνακες αντιστοίχισης hashes με plaintext |
| Reverse shell | Shell όπου η connection αρχικοποιείται από τον στόχο προς τον ελεγκτή |
| Payload | Κώδικας που εκτελείται στον στόχο |
| PTY | Pseudo-terminal, εικονική τερματική συσκευή |
| SUID bit | Δικαίωμα εκτέλεσης με τα προνόμια του ιδιοκτήτη |
| EUID | Effective User ID, τα πραγματικά δικαιώματα της διεργασίας |
| Intercepting proxy | Εργαλείο παρεμβολής και καταγραφής requests |
| Privilege escalation | Αύξηση επιπέδου πρόσβασης εντός του συστήματος |
| Defense in depth | Πολλαπλά, ανεξάρτητα μέτρα άμυνας |

## Παράρτημα Β. Ερωτήσεις αυτοελέγχου

1. Ποιος ο ρόλος του `robots.txt` ως πηγής πληροφορίας και γιατί δεν συνιστά μέτρο ασφάλειας.
2. Πώς η διαφοροποίηση των error messages διευκολύνει το user enumeration και το brute-force.
3. Γιατί απαιτείται ταξινόμηση πριν την αφαίρεση duplicates από ένα wordlist.
4. Γιατί η αλλαγή χρήστη απαιτεί PTY και πώς αποκαθίσταται.
5. Πώς ένα SUID bit σε εργαλείο γενικής χρήσης οδηγεί σε root shell.
6. Ποια η διαφορά μεταξύ MD5 και Argon2 ως προς την καταλληλότητα για password storage.
7. Ποια τρία μέτρα θα διέκοπταν την αλυσίδα και σε ποιο στάδιο.

## Παράρτημα Γ. Κατάλογος ελέγχου

- Port και service scanning με τεκμηρίωση εξόδου
- Directory scanning με κατάλληλο wordlist
- Έλεγχος δημόσιων configuration files και sitemaps
- Καταγραφή authentication requests μέσω intercepting proxy
- Αξιολόγηση διακριτών responses για user enumeration
- Βελτιστοποίηση wordlists πριν το brute-force
- Έλεγχος file permissions σε home directories
- Έλεγχος hashes με τοπικά και διαδικτυακά μέσα
- Αποκατάσταση PTY πριν από authentication εντολές
- Αναζήτηση SUID bit και διασταύρωση με βάσεις τεχνικών
- Σύνταξη αναφοράς με ευρήματα, impact και προτάσεις διόρθωσης
