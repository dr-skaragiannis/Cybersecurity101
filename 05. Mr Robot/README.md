# Mr. Robot CTF (TryHackMe) — Εγχειρίδιο Δοκιμής Διείσδυσης

> **Σύνοψη:** Το παρόν τεχνικό εγχειρίδιο συνιστά μια αναλυτική, μεθοδολογικά τεκμηριωμένη καταγραφή της διαδικασίας διεξαγωγής δοκιμής διείσδυσης (penetration testing) στην ευπαθή εικονική μηχανή **Mr. Robot** της πλατφόρμας TryHackMe. Η διάρθρωση της ανάλυσης ακολουθεί αυστηρά τις προδιαγραφές του **Penetration Testing Execution Standard (PTES)** και ενσωματώνει τις κατευθυντήριες οδηγίες του **NIST SP 800-115**. Η πορεία της επίθεσης καλύπτει διαδοχικά τις φάσεις της παθητικής και ενεργητικής συλλογής πληροφοριών (reconnaissance), της απαρίθμησης πόρων (enumeration), της αρχικής απόκτησης πρόσβασης (initial access), της οριζόντιας μετακίνησης προνομίων (user pivoting), καθώς και της τελικής κάθετης κλιμάκωσης (privilege escalation). Κάθε ενέργεια και τεχνική εντολή αναλύεται σε δύο αλληλένδετα επίπεδα: αφενός στο επίπεδο λειτουργίας του λειτουργικού συστήματος και των δικτυακών πρωτοκόλλων, και αφετέρου στο επίπεδο της τακτικής αναγκαιότητας — αποσαφηνίζοντας δηλαδή πώς η εκάστοτε πληροφορία ξεκλειδώνει το επόμενο στάδιο της επιθετικής αλυσίδας (kill chain).

## 1. Εισαγωγή και Μεθοδολογικό Πλαίσιο

### 1.1 Αντικείμενο και Στόχοι της Άσκησης

Αντικείμενο της παρούσας τεχνικής δοκιμής διείσδυσης αποτελεί η προσομοιωμένη επίθεση κατά της εικονικής μηχανής **Mr. Robot**, η οποία φιλοξενείται στην εκπαιδευτική πλατφόρμα TryHackMe. Πρωταρχικός σκοπός του ελέγχου είναι ο εντοπισμός, η επαλήθευση και η εκμετάλλευση διαδοχικών αδυναμιών ασφαλείας με απώτερο στόχο την άντληση τριών μοναδικών συμβολοσειρών ελέγχου (**flags / keys**). 

Κάθε κλειδί σηματοδοτεί την επιτυχή επίτευξη ενός διακριτού επιπέδου εξουσιοδότησης εντός του πληροφοριακού συστήματος:

| Σύμβολο Ελέγχου | Απαιτούμενο Επίπεδο Πρόσβασης | Τεχνική Απόδειξη και Επιχειρησιακή Σημασία |
| :--- | :--- | :--- |
| **Key 1** | Ανώνυμος Εξωτερικός Χρήστης (Unauthenticated Web Access) | Αποδεικνύει την έκθεση ευαίσθητων αρχείων και δεδομένων διαμόρφωσης στο δημόσιο διαδίκτυο χωρίς απαίτηση ταυτοποίησης. |
| **Key 2** | Τοπικός Χρήστης Συστήματος (`robot`) | Επιβεβαιώνει την επιτυχή παράκαμψη των μηχανισμών αυθεντικοποίησης της εφαρμογής και τη δυνατότητα τοπικής αλληλεπίδρασης με το λειτουργικό σύστημα. |
| **Key 3** | Διαχειριστής Συστήματος (`root`) | Τεκμηριώνει την πλήρη κατάληψη του συστήματος (Full System Compromise), επιτρέποντας την πλήρη παράκαμψη κάθε μηχανισμού ασφαλείας. |

Η δομή του σεναρίου αναδεικνύει μια θεμελιώδη αρχή της κυβερνοασφάλειας: η πλήρης κατάληψη μιας υποδομής σπανίως προκύπτει από μία μεμονωμένη, καταστροφική ευπάθεια. Αντιθέτως, αποτελεί συνήθως το αποτέλεσμα μιας αλυσίδας επιμέρους, φαινομενικά ασήμαντων αδυναμιών διαμόρφωσης (misconfigurations), η διαδοχική αξιοποίηση των οποίων καταλύει την άμυνα του συστήματος.

### 1.2 Πρότυπα και Μεθοδολογική Προσέγγιση (PTES / NIST)

Η δοκιμή διείσδυσης διενεργήθηκε σύμφωνα με το επιχειρησιακό πρότυπο **Penetration Testing Execution Standard (PTES)**, διασφαλίζοντας επαγγελματική συνέπεια, αναπαραγωγιμότητα και δομημένη τεκμηρίωση. Οι ενότητες του παρόντος εγγράφου συνδέονται άμεσα με τις επίσημες φάσεις του PTES:

```
[Intelligence Gathering] ──> [Threat Modelling] ──> [Vulnerability Analysis]
                                                              │
[Reporting] <── [Post-Exploitation] <── [Exploitation] <──────┘
```

| Φάση κατά PTES | Ενότητα Εγγράφου | Επιχειρησιακός Σκοπός και Παραδοτέα |
| :--- | :--- | :--- |
| **Pre-engagement Interactions** | 1.1, 1.3 | Καθορισμός κανόνων εμπλοκής (Rules of Engagement), εμβέλειας (scope) και νομικού πλαισίου. |
| **Intelligence Gathering** | 3.1, 3.2, 4.1 | Παθητική και ενεργητική συλλογή στοιχείων για την υποδομή, τα πρωτόκολλα και τις υπηρεσίες. |
| **Threat Modelling** | 2.0, 10.1 | Αναγνώριση πιθανών διανυσμάτων επίθεσης και ιεράρχηση των δυνητικών απειλών. |
| **Vulnerability Analysis** | 4.2, 5.2, 8.1 | Εντοπισμός, επικύρωση και συσχέτιση των ευπαθειών λογισμικού και σφαλμάτων παραμετροποίησης. |
| **Exploitation** | 5.4, 5.5, 6.1 | Παραβίαση των ορίων ασφαλείας και απόκτηση αρχικού μη εξουσιοδοτημένου ελέγχου. |
| **Post-Exploitation** | 7.1, 7.3, 8.3 | Εσωτερική αναγνώριση, οριζόντια μετακίνηση (pivoting), κλιμάκωση προνομίων και διασφάλιση αποδείξεων. |
| **Reporting** | 10.1, 10.2, 10.3 | Σύνταξη τεχνικής αναφοράς, εκτίμηση κινδύνου και παροχή διορθωτικών μέτρων αντιμετώπισης. |

Παράλληλα, ενσωματώνονται οι διακρίσεις της τεχνικής οδηγίας **NIST SP 800-115** (*Technical Guide to Information Security Testing and Assessment*), η οποία διαχωρίζει με σαφήνεια:
- Την **Παθητική Αναγνώριση (Passive Reconnaissance):** Συλλογή δεδομένων μέσω παρατήρησης δημόσια διαθέσιμων πηγών (π.χ. επιθεώρηση κώδικα HTML, HTTP response headers) χωρίς την πρόκληση ασυνήθιστης δραστηριότητας στα συστήματα του στόχου.
- Την **Ενεργητική Αναγνώριση (Active Reconnaissance):** Άμεση αλληλεπίδραση με τις δικτυακές θύρες και τις υπηρεσίες του στόχου (π.χ. port scanning, directory fuzzing), δραστηριότητα η οποία παράγει εγγραφές στα αρχεία καταγραφής (logs) και δύναται να ανιχνευθεί από συστήματα IDS/IPS.

### 1.3 Παραδοχές, Περιορισμοί και Περιβάλλον Ελέγχου

Η διενέργεια της παρούσας δοκιμής υπόκειται στις ακόλουθες αυστηρές παραδοχές:
- **Νομικό Πλαίσιο και Ηθική:** Όλες οι ενέργειες πραγματοποιήθηκαν αποκλειστικά εντός ενός απομονωμένου, ελεγχόμενου εργαστηριακού περιβάλλοντος με ρητή, προηγούμενη εξουσιοδότηση. Η εκτέλεση παρόμοιων τεχνικών σε υποδομές τρίτων άνευ εγγράφου συμφωνίας συνιστά σοβαρό ποινικό αδίκημα.
- **Επιθετική Πλατφόρμα (Attacker Machine):** Το σύστημα του ελεγκτή λειτουργεί σε περιβάλλον Linux (Kali Linux / Parrot OS) και διαθέτει εγκατεστημένα τα εργαλεία: `nmap`, `gobuster`, `hydra`, `netcat`, `john the ripper`, `hashcat`, καθώς και τον διερμηνέα Python 3.
- **Συμβολισμός Στόχου:** Η διεύθυνση IP του στόχου αναγράφεται ως `<target-ip>` ώστε να επιτρέπει την άμεση προσαρμογή των εντολών σε οποιαδήποτε παραλλαγή του περιβάλλοντος.
- **Περιορισμοί Εργαλείων:** Όπου χρησιμοποιούνται σύνθετα εμπορικά ή γραφικά εργαλεία (όπως Burp Suite Professional ή WPScan), παρέχονται ισοδύναμες λύσεις βασισμένες σε εργαλεία γραμμής εντολών ανοικτού κώδικα.

### 1.4 Ονοματολογία και Συμβάσεις Ορολογίας

Προς αποφυγή παρανοήσεων και χάριν της ορολογικής ακρίβειας, οι καθιερωμένοι όροι της διεθνούς βιβλιογραφίας κυβερνοασφάλειας (όπως *Reconnaissance*, *Enumeration*, *Wordlist*, *Brute-Force*, *Hash*, *Salt*, *Rainbow Tables*, *Reverse Shell*, *Payload*, *PTY*, *SUID bit*, *EUID*, *Privilege Escalation*) παρατίθενται με την αγγλική τους ονομασία ή με άμεση αναφορά σε αυτή. Πλήρεις εννοιολογικοί ορισμοί και αντιστοιχίσεις παρέχονται στο [Παράρτημα Α](#παράρτημα-α-ολοκληρωμένο-τεχνικό-γλωσσάρι).

### 1.5 Τεκμηρίωση Οπτικών Αποδείξεων (Images)

Όλα τα ψηφιακά πειστήρια (screenshots) φυλάσσονται στον σχετικό υποκατάλογο `images/` και φέρουν συστηματική αρίθμηση (`img-02.png` έως `img-31.png`, καθώς και `nmap-scan.png`). Κάθε εικόνα συνοδεύεται από αναλυτική λεζάντα που επεξηγεί τα τεχνικά ευρήματα και το αποδεικτικό τους βάρος στο πλαίσιο της αξιολόγησης.

## 2. Χάρτης της Επιθετικής Αλυσίδας (Attack Surface & Kill Chain)

Ο παρακάτω πίνακας αποτυπώνει συνοπτικά τη ροή της επίθεσης, καταγράφοντας τη μετάβαση από το ένα στάδιο στο επόμενο και αναδεικνύοντας τα κρίσιμα ευρήματα:

| Στάδιο | Τεχνική Ενέργεια | Άμεσο Αποτέλεσμα | Κρίσιμο Εύρημα / Ευπάθεια |
| :--- | :--- | :--- | :--- |
| **Reconnaissance** | TCP Port Scanning (`nmap`) | Ταυτοποίηση ανοικτών θυρών και Apache Server | Ανοικτές θύρες `80/TCP` και `443/TCP` |
| **Enumeration** | Directory Fuzzing & ανάλυση `robots.txt` | Εντοπισμός κρυφών αρχείων και καταλόγων CMS | Ανάκτηση **Key 1** & λεξικού `fsocity.dic` |
| **Data Processing** | Καθαρισμός και αποδιπλασιασμός wordlist | Συρρίκνωση όγκου υποψηφίων κωδικών κατά 98,7% | Δημιουργία βελτιστοποιημένης λίστας `fs-list` |
| **Credential Access** | Εκμετάλλευση CWE-204 & Brute-force | Ανακάλυψη έγκυρων διαπιστευτηρίων διαχειριστή | Χρήστης: `elliot`, Password: `[REDACTED]` |
| **Initial Access** | Επεξεργασία Theme Template WordPress | Εισαγωγή PHP κώδικα για απομακρυσμένη εκτέλεση | Reverse Shell ως χρήστης `daemon` |
| **User Pivoting** | Εντοπισμός MD5 hash και κρυπτανάλυση | Ανάκτηση κωδικού πρόσβασης τοπικού λογαριασμού | Μετάβαση στον χρήστη `robot` & ανάκτηση **Key 2** |
| **Privilege Escalation**| Κατάχρηση SUID binary (`nmap`) | Εκτέλεση εντολών με αυξημένα δικαιώματα | Πλήρης πρόσβαση ως `root` & ανάκτηση **Key 3** |

Η αλληλουχία αυτή αποδεικνύει εμπράκτως ότι η ασφάλεια ενός συστήματος είναι τόσο ισχυρή όσο ο πιο αδύναμος κρίκος του. Εάν έστω και ένα εκ των επιμέρους μέτρων προστασίας είχε λειτουργήσει αποτελεσματικά (π.χ. περιορισμός πρόσβασης στο `robots.txt`, απενεργοποίηση της επεξεργασίας θεμάτων ή αφαίρεση του SUID bit), η αλυσίδα της επίθεσης θα είχε διακοπεί.

Σε ένα απομονωμένο εργαστηριακό περιβάλλον (Local/Lab Environment), η απαιτούμενη διάρκεια για κάθε φάση εκτιμάται ως εξής:

## 3. Φάση Πρώτη: Reconnaissance και Χαρτογράφηση Δικτύου

### 3.1 Στρατηγική και Εκτέλεση της Δικτυακής Σάρωσης

Η διαδικασία δοκιμής διείσδυσης ξεκινά υποχρεωτικά με τη χαρτογράφηση της επιφάνειας επίθεσης του στόχου μέσω του εργαλείου `nmap`. Η σάρωση στοχεύει στον εντοπισμό ανοικτών θυρών TCP και την εξαγωγή των εκδόσεων των ενεργών υπηρεσιών:

```bash
nmap <target-ip> -sV -T4 -oA nmap-scan -open
```

#### Τεχνική Ανάλυση Παραμέτρων της Εντολής

| Παράμετρος | Λειτουργική Περιγραφή | Τεχνική και Μεθοδολογική Σκοπιμότητα |
| :--- | :--- | :--- |
| `<target-ip>` | Διεύθυνση IPv4 του Στόχου | Ορίζει το τελικό σημείο δικτυακού προορισμού για την αποστολή των ανιχνευτικών πακέτων. |
| `-sV` | Service Version Detection | Εκτελεί αναγνώριση εκδόσεων αποστέλλοντας εξειδικευμένα probes και συγκρίνοντας τα ληφθέντα banners με τη βάση δεδομένων `nmap-service-probes`. Επιτρέπει τη συσχέτιση των υπηρεσιών με γνωστές ευπάθειες (CVEs). |
| `-T4` | Timing Template (Aggressive) | Βελτιστοποιεί τις παραμέτρους χρονισμού (μείωση timeouts, ταχύτερη επανεκπομπή πακέτων). Ενδείκνυται για σταθερά, τοπικά εργαστηριακά δίκτυα. |
| `-oA nmap-scan` | Output in All Formats | Εξάγει τα αποτελέσματα ταυτόχρονα σε τρεις μορφές αρχείων: κανονικό κείμενο (`.nmap`), δομημένη XML (`.xml`) και grepable μορφή (`.gnmap`), διασφαλίζοντας πλήρες ιστορικό ελέγχου (audit trail). |
| `-open` | Filter Open Ports Only | Φιλτράρει την έξοδο, αποκρύπτοντας τις θύρες που βρίσκονται σε κατάσταση `closed` ή `filtered`, επιτρέποντας την άμεση εστίαση στους πραγματικούς στόχους. |

**Μεθοδολογική Αναγκαιότητα:** Η αναγνώριση ανοικτών θυρών αποτελεί το θεμέλιο της δοκιμής διείσδυσης. Χωρίς αυτήν, είναι αδύνατος ο προσδιορισμός του attack surface, καθώς κάθε επόμενη ενέργεια εξαρτάται άμεσα από τις υπηρεσίες που εκτίθενται στο δίκτυο.

## 4. Φάση Δεύτερη: Web Enumeration και Ανακάλυψη Πόρων

### 4.1 Μέθοδοι Καταλόγων και Αρχιτεκτονική Directory Brute-Force

Για τον εντοπισμό μη δημοσιοποιημένων αρχείων και υποκαταλόγων στον web server, επιστρατεύεται το εργαλείο υψηλής ταχύτητας `gobuster`:

```bash
gobuster dir -u http://<target-ip> -w /usr/share/wordlists/dirbuster/directory-list-2.3-small.txt
```

#### Τεχνική Ανάλυση Παραμέτρων της Εντολής

| Παράμετρος | Λειτουργική Περιγραφή | Τεχνική Σκοπιμότητα |
| :--- | :--- | :--- |
| `dir` | Directory Mode | Ενεργοποιεί τη λειτουργία σάρωσης καταλόγων και αρχείων μέσω διαδοχικών αιτημάτων HTTP GET/HEAD. |
| `-u http://<target-ip>` | Base Target URL | Καθορίζει το πρωτόκολλο, τη διεύθυνση και το ριζικό μονοπάτι του εξυπηρετητή ιστού. |
| `-w <wordlist>` | Wordlist Path | Ορίζει το αρχείο λεξικού που περιέχει τα υποψήφια ονόματα διαδρομών προς έλεγχο. |

#### Περιορισμοί και Παράγοντες της Μεθόδου:
- **Ποιότητα Λεξικού:** Εάν ένα κρίσιμο μονοπάτι δεν περιλαμβάνεται στο χρησιμοποιούμενο wordlist, η σάρωση θα αποτύχει να το εντοπίσει.
- **Ανάλυση HTTP Status Codes:** 
  - Κωδικοί `200 OK` και `301/302 Redirect` τεκμηριώνουν την ύπαρξη του πόρου.
  - Ο κωδικός `403 Forbidden` υποδηλώνει ότι ο πόρος **υφίσταται**, αλλά η πρόσβαση απαγορεύεται βάσει ρυθμίσεων δικαιωμάτων (απαιτείται καταγραφή και περαιτέρω διερεύνηση).
  - Ο κωδικός `404 Not Found` υποδηλώνει απουσία του πόρου.

## 5. Φάση Τρίτη: Επεξεργασία Δεδομένων και Εξαγωγή Διαπιστευτηρίων

### 5.1 Βελτιστοποίηση και Αποδιπλασιασμός Wordlist

Η αρχική εξέταση του αρχείου `fsocity.dic` αποκαλύπτει τεράστιο όγκο δεδομένων:

```bash
wc -l fsocity.dic
# 858160 fsocity.dic
```

Το αρχείο περιλαμβάνει **858.160 γραμμές**. Η απευθείας χρήση του σε δικτυακή επίθεση brute-force κατά του WordPress θα απαιτούσε εξαιρετικά μεγάλο χρονικό διάστημα και θα δημιουργούσε υπερβολικό φόρτο στον εξυπηρετητή. 

Μια προσεκτική ματιά στο περιεχόμενο αποκαλύπτει ότι το λεξικό περιέχει πολυάριθμες πανομοιότυπες, επαναλαμβανόμενες εγγραφές. Επιβάλλεται επομένως η διαδικασία αποδιπλασιασμού (deduplication).

Η ταξινόμηση και εκκαθάριση υλοποιείται με την παρακάτω εντολή:

```bash
sort -u fsocity.dic > fs-list
```

Εναλλακτικά, μέσω συνδυασμού εντολών UNIX:
```bash
sort fsocity.dic | uniq > fs-list
```

#### Τεχνική Σκοπιμότητα:
Η εντολή `uniq` απαιτεί **υποχρεωτικά** προηγούμενη ταξινόμηση μέσω της `sort`, καθώς ελέγχει αποκλειστικά γειτονικές γραμμές. Χωρίς την ταξινόμηση, διπλότυπες εγγραφές που βρίσκονται σε απόσταση θα παρέμεναν στο αρχείο.

Έλεγχος του νέου αρχείου:
```bash
wc -l fs-list
# 11451 fs-list
```

Ο αριθμός των υποψηφίων μειώθηκε από 858.160 σε **11.451 μοναδικές λέξεις** — μια εντυπωσιακή μείωση της τάξεως του **98,7%**, η οποία μετατρέπει μια επίθεση πολλών ωρών σε διαδικασία λίγων λεπτών.

### 5.2 Θεωρία User Enumeration μέσω Observable Response Discrepancy (CWE-204)

Η αδυναμία **CWE-204 (Observable Response Discrepancy)** παρουσιάζεται όταν μια εφαρμογή παρέχει διαφορετικές αποκρίσεις ανάλογα με το αν ένα όνομα χρήστη υπάρχει ή όχι στη βάση δεδομένων της. 

Στην περίπτωση παλαιότερων εκδόσεων του WordPress, ο μηχανισμός αυθεντικοποίησης εμφανίζει τις εξής διαφοροποιήσεις:
- **Ανύπαρκτο Όνομα Χρήστη:** Εμφανίζεται το μήνυμα σφάλματος:  
  `ERROR: Invalid username.`
- **Υπαρκτό Όνομα Χρήστη με Λανθασμένο Κωδικό:** Εμφανίζεται το μήνυμα σφάλματος:  
  `The password you entered for the username <user> is incorrect.`

Αυτή η λεπτή διαφορά επιτρέπει σε έναν επιτιθέμενο να επιβεβαιώσει ποια ονόματα χρηστών είναι έγκυρα, απομονώνοντας πλήρως τη διαδικασία ανακάλυψης χρηστών από τη διαδικασία εύρεσης κωδικών.

### 5.4 Επιβεβαίωση Έγκυρου Ονόματος Χρήστη (Username Enumeration)

Με τη βοήθεια του εργαλείου `hydra`, εκτελείται αυτοματοποιημένη δοκιμή των λέξεων του `fs-list` ως υποψήφια ονόματα χρηστών, διατηρώντας έναν σταθερό αυθαίρετο κωδικό (`test`):

```bash
hydra -L fs-list -p test <target-ip> http-post-form "/wp-login.php:log=^USER^&pwd=^PASS^:F=Invalid username" -t 30
```

#### Τεχνική Ανάλυση Παραμέτρων της Εντολής

| Παράμετρος | Τεχνική Λειτουργία |
| :--- | :--- |
| `-L fs-list` | Χρήση της λίστας `fs-list` για τη θέση του ονόματος χρήστη (`^USER^`). |
| `-p test` | Σταθερός κωδικός πρόσβασης (`^PASS^`), ώστε να ελεγχθεί αποκλειστικά η ύπαρξη του χρήστη. |
| `http-post-form` | Μονάδα ελέγχου φορμών HTTP POST. Αποτελείται από 3 τμήματα χωρισμένα με `:` <br>1. Διαδρομή: `/wp-login.php`<br>2. Παράμετροι: `log=^USER^&pwd=^PASS^`<br>3. Συνθήκη Αποτυχίας: `F=Invalid username` |
| `-t 30` | Εκτέλεση 30 ταυτόχρονων νημάτων (parallel connection threads). |

![Αποτέλεσμα user enumeration](images/img-09.png)

*Εικόνα 9. Έξοδος του Hydra: Ταυτοποίηση του έγκυρου χρήστη `elliot`.*

![Σενάριο reverse shell](images/img-14.png)

*Εικόνα 14. Ο πηγαίος κώδικας του PHP Reverse Shell script.*

#### Εσωτερική Λειτουργία του Reverse Shell:
1. Το script αρχικοποιεί μια εξερχόμενη σύνδεση TCP μέσω socket προς την IP και τη θύρα του επιτιθέμενου (`fsockopen`).
2. Δημιουργεί μια νέα διεργασία κελύφους συστήματος (`/bin/sh`) μέσω της συνάρτησης `proc_open`.
3. Ανακατευθύνει τις τυπικές ροές δεδομένων:
   - **`stdin` (Standard Input):** Διαβάζει εντολές απευθείας από το δικτυακό socket.
   - **`stdout` (Standard Output):** Στέλνει τα αποτελέσματα των εντολών πίσω στο socket.
   - **`stderr` (Standard Error):** Στέλνει τα μηνύματα σφάλματος πίσω στο socket.

> **Γιατί Reverse Shell και όχι Bind Shell;**  
> Σε ένα *Bind Shell*, ο στόχος ανοίγει μια θύρα και περιμένει τον επιτιθέμενο να συνδεθεί. Εάν ο στόχος προστατεύεται από τείχος προστασίας (firewall) ή βρίσκεται πίσω από NAT, οι εισερχόμενες συνδέσεις συνήθως μπλοκάρονται. Αντιθέτως, στο *Reverse Shell*, ο στόχος είναι αυτός που εκκινεί την εξερχόμενη σύνδεση προς τον επιτιθέμενο. Τα firewalls κατά κανόνα επιτρέπουν την εξερχόμενη κίνηση, καθιστώντας το reverse shell εξαιρετικά αξιόπιστο.

### 7.2 Αδυναμίες του Αλγορίθμου MD5 και Κρυπταναλυτική Ανάκτηση Password

Το εξαχθέν hash αντιστοιχεί στον αλγόριθμο **MD5 (Message Digest 5)**:
`c3fcd3d76192e4007dfb496cca67e13b`

#### Γιατί ο MD5 είναι Ακατάλληλος για Αποθήκευση Κωδικών:
1. **Απουσία Υπολογιστικού Κόστους (Work Factor):** Ο MD5 σχεδιάστηκε για γρήγορο έλεγχο ακεραιότητας δεδομένων, όχι για αποθήκευση κωδικών. Ένας σύγχρονος υπολογιστής μπορεί να υπολογίσει δισεκατομμύρια hashes MD5 ανά δευτερόλεπτο.
2. **Απουσία Salt (Αλάτισμα):** Το hash αποθηκεύτηκε χωρίς salt (τυχαία συμβολοσειρά που προσαρτάται πριν τον κατακερματισμό). Αυτό σημαίνει ότι ο ίδιος κωδικός παράγει πάντα το ίδιο ακριβώς MD5 hash παγκοσμίως, καθιστώντας το άμεσα ευάλωτο σε προϋπολογισμένους πίνακες αναζήτησης (**Rainbow Tables**).

#### Συγκριτικός Πίνακας Αλγορίθμων Κατακερματισμού Κωδικών

| Αλγόριθμος | Υπολογιστική Ταχύτητα | Εγγενές Salt | Αντίσταση σε GPU/ASIC | Καταλληλότητα για Password Hashing |
| :--- | :--- | :--- | :--- | :--- |
| **MD5** | Εξαιρετικά Υψηλή (ns) | Όχι | Μηδενική | **Επικίνδυνος / Απαρχαιωμένος** |
| **SHA-1 / SHA-256** | Πολύ Υψηλή | Όχι | Πολύ Χαμηλή | **Ακατάλληλος** (χωρίς KDF) |
| **bcrypt** | Ρυθμιζόμενη (Cost Factor) | Ναι (128-bit) | Υψηλή | **Αποδεκτός / Ασφαλής** |
| **Argon2id** | Ρυθμιζόμενη (Memory/CPU)| Ναι | Μέγιστη (Memory-Hard) | **Συνιστώμενος (State-of-the-Art)** |

## 8. Φάση Έκτη: Privilege Escalation και Πλήρης Κατάληψη

### 8.1 Αναζήτηση Εκτελέσιμων Αρχείων με Ενεργό SUID Bit

Μετά την επιτυχή οριζόντια μετακίνηση στον χρήστη `robot`, το επόμενο κρίσιμο βήμα είναι η κάθετη κλιμάκωση προνομίων (**Privilege Escalation**) με στόχο την απόκτηση δικαιωμάτων υπερχρήστη (`root`).

Μια από τις συνηθέστερες μεθόδους κλιμάκωσης σε περιβάλλοντα Linux είναι ο εντοπισμός δυαδικών εκτελέσιμων αρχείων στα οποία έχει αποδοθεί εσφαλμένα το **SUID (Set User ID) bit**.

#### Κατανόηση των Ειδικών Δικαιωμάτων SUID:
- Σε ένα κανονικό εκτελέσιμο, η διεργασία κληρονομεί τα δικαιώματα του χρήστη που την εκτελεί (Real User ID - RUID).
- Όταν ένα αρχείο φέρει το **SUID bit** (`chmod u+s`), η διεργασία εκτελείται με τα προνόμια του **ιδιοκτήτη του αρχείου** (Effective User ID - EUID). Εάν ο ιδιοκτήτης είναι ο `root`, το εκτελέσιμο τρέχει με πλήρη δικαιώματα διαχειριστή, ανεξάρτητα από το ποιος το κάλεσε.

Εκτέλεση καθολικής αναζήτησης στο σύστημα αρχείων:

```bash
find / -perm -u=s -type f 2>/dev/null
```

#### Τεχνική Ανάλυση Παραμέτρων της Εντολής:
- `/`: Ξεκινά την αναζήτηση αναδρομικά από τον ριζικό κατάλογο (root directory).
- `-perm -u=s` (ή `-perm -4000`): Φιλτράρει αυστηρά τα αρχεία που έχουν ενεργοποιημένο το SUID bit για τον ιδιοκτήτη.
- `-type f`: Περιορίζει την αναζήτηση αποκλειστικά σε κανονικά αρχεία (αποκλείει καταλόγους και ειδικές συσκευές).
- `2>/dev/null`: Ανακατευθύνει τα μηνύματα σφάλματος πρόσβασης (Standard Error) στη συσκευή απόρριψης δεδομένων, διατηρώντας την έξοδο καθαρή.

![Αποτελέσματα αναζήτησης](images/img-21.png)

*Εικόνα 21. Λίστα εκτελέσιμων αρχείων με ενεργό SUID bit: Εντοπισμός του `/usr/local/bin/nmap`.*

#### Αξιολόγηση Ευρημάτων SUID:
Στην έξοδο της εντολής εμφανίζονται τυπικά βοηθητικά προγράμματα του συστήματος που απαιτούν εκ φύσεως SUID (π.χ. `/bin/ping`, `/usr/bin/passwd`, `/usr/bin/sudo`). Ωστόσο, ξεχωρίζει ένα ασυνήθιστο δυαδικό αρχείο:
`/usr/local/bin/nmap`

Η απόδοση δικαιωμάτων SUID root σε ένα τόσο ισχυρό εργαλείο δικτύωσης συνιστά σοβαρότατο σφάλμα παραμετροποίησης.

Στο πλαίσιο μιας ολοκληρωμένης δοκιμής διείσδυσης, ο ελεγκτής οφείλει να γνωρίζει εναλλακτικές μεθοδολογικές προσεγγίσεις για την επίτευξη του ίδιου αποτελέσματος. Παρακάτω παρατίθενται ισοδύναμες τεχνικές που επιβεβαιώνουν τα ευρήματα των προηγούμενων φάσεων.

### 9.2 Στοχευμένη Σάρωση και Brute-Force με Χρήση WPScan

Το **WPScan** είναι ένα εξειδικευμένο εργαλείο αξιολόγησης ασφαλείας για το WordPress, το οποίο γνωρίζει εγγενώς την αρχιτεκτονική της πλατφόρμας.

```bash
wpscan --url http://<target-ip> -t 50 -U elliot -P fs-list
```

#### Πλεονεκτήματα Έναντι του Hydra:
- Αναγνωρίζει αυτόματα τα endpoints αυθεντικοποίησης χωρίς χειροκίνητη παραμετροποίηση.
- Υποστηρίζει την εκμετάλλευση της διεπαφής **XML-RPC** (`xmlrpc.php`), επιτρέποντας την τεχνική **system.multicall**, η οποία δοκιμάζει εκατοντάδες συνδυασμούς κωδικών σε ένα **μοναδικό** HTTP αίτημα, παρακάμπτοντας απλούς μηχανισμούς rate limiting.

### 9.3 Τοπική Κρυπτανάλυση Hash με John the Ripper

Η ανάκτηση του κωδικού πρόσβασης από το αρχείο `password.raw-md5` μπορεί να πραγματοποιηθεί τοπικά με το εργαλείο **John the Ripper**, χρησιμοποιώντας το καθιερωμένο λεξικό `rockyou.txt`:

```bash
john --format=Raw-MD5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

![Ανάκτηση password μέσω εργαλείου λεξικού](images/img-30.png)

*Εικόνα 30. Επιτυχής κρυπτανάλυση του MD5 hash μέσω John the Ripper.*

### 9.4 Επιταχυνόμενη Ανάκτηση μέσω Καρτών Γραφικών (Hashcat GPGPU)

Για hashes υψηλής πολυπλοκότητας, η χρήση επιτάχυνσης μέσω GPU (GPGPU computation) αποτελεί τη βέλτιστη βιομηχανική πρακτική. Το εργαλείο **Hashcat** αξιοποιεί τον μαζικό παραλληλισμό των καρτών γραφικών:

```bash
hashcat -m 0 -a 0 hash.txt /usr/share/wordlists/rockyou.txt
```

- `-m 0`: Δηλώνει τον τύπο κατακερματισμού (0 = MD5).
- `-a 0`: Δηλώνει Straight Dictionary Attack.

![Επιτάχυνση μέσω GPU](images/img-31.png)

*Εικόνα 31. Εξαιρετικά ταχεία ολοκλήρωση της διαδικασίας κρυπτανάλυσης με χρήση Hashcat.*

#### Σύγκριση Υπολογιστικής Απόδοσης (Ενδεικτικές Μετρήσεις):
- **CPU (Intel i7):** $\approx 10 - 50 \times 10^6$ hashes/sec για MD5.
- **GPU (NVIDIA RTX 3080/4090):** $\approx 50 - 150 \times 10^9$ hashes/sec για MD5.  
Η τεράστια αυτή διαφορά υπογραμμίζει γιατί οι αλγόριθμοι χωρίς ενσωματωμένο υπολογιστικό κόστος θεωρούνται πλέον πλήρως παρωχημένοι.

## 10. Αξιολόγηση Ευρημάτων και Μέτρα Αποκατάστασης

### 10.1 Πίνακας Ταξινόμησης Αδυναμιών κατά CVSS / Βαρύτητα

Κατά τη διάρκεια της δοκιμής διείσδυσης εντοπίστηκαν πολλαπλές αδυναμίες, οι οποίες αξιολογούνται συνοπτικά στον παρακάτω πίνακα:

### 10.2 Προτεινόμενα Μέτρα Τεχνικής Αποκατάστασης (Hardening Roadmap)

Για την αποτελεσματική θωράκιση του συστήματος και την εφαρμογή της αρχής της **Άμυνας σε Βάθος (Defense in Depth)**, συνιστώνται τα ακόλουθα μέτρα:

1. **Εξυγίανση του `robots.txt`:** Άμεση αφαίρεση ευαίσθητων διαδρομών από το αρχείο. Η ασφάλεια των πόρων πρέπει να επιβάλλεται μέσω μηχανισμών αυθεντικοποίησης και εξουσιοδότησης (Access Control Lists) στον web server και όχι μέσω απόκρυψης.
2. **Ενοποίηση Μηνυμάτων Αυθεντικοποίησης:** Διαμόρφωση της εφαρμογής ώστε να επιστρέφει ένα ενιαίο, γενικό μήνυμα σφάλματος σε κάθε αποτυχημένη προσπάθεια σύνδεσης (π.χ. *«Εσφαλμένο όνομα χρήστη ή κωδικός πρόσβασης»*), αποτρέποντας την απαρίθμηση χρηστών.
3. **Εφαρμογή Rate Limiting & Account Lockout:** Ενεργοποίηση μηχανισμών περιορισμού αποτυχημένων προσπαθειών σύνδεσης (π.χ. κλείδωμα μετά από 5 αποτυχημένες απόπειρες) και χρήση Web Application Firewall (WAF) για την αποτροπή αυτοματοποιημένων επιθέσεων brute-force.
4. **Επιβολή Ελέγχου Ταυτότητας Πολλαπλών Παραγόντων (MFA):** Υποχρεωτική ενεργοποίηση MFA/2FA για όλους τους λογαριασμούς με δικαιώματα διαχειριστή (`Administrator`).
5. **Απενεργοποίηση του Ενσωματωμένου File Editor:** Προσθήκη της παρακάτω παραμέτρου στο αρχείο `wp-config.php` για την πλήρη κατάργηση της δυνατότητας τροποποίησης κώδικα από το web dashboard:
   ```php
   define('DISALLOW_FILE_EDIT', true);
   ```
6. **Απενεργοποίηση XML-RPC:** Εφόσον δεν χρησιμοποιούνται εξωτερικές εφαρμογές διαχείρισης, συνιστάται η απενεργοποίηση του `xmlrpc.php` μέσω του αρχείου `.htaccess` ή κατάλληλου plugin:
   ```apache
   <Files xmlrpc.php>
   Order Allow,Deny
   Deny from all
   </Files>
   ```
7. **Αναβάθμιση Κρυπτογραφικών Αλγορίθμων:** Καθολική κατάργηση του MD5 και υιοθέτηση σύγχρονων, ασφαλών συναρτήσεων παραγωγής κλειδιών (**Argon2id** ή **bcrypt**) με μοναδικό κρυπτογραφικό salt ανά λογαριασμό.
8. **Αυστηροποίηση Δικαιωμάτων Αρχείων (File Permissions Hardening):** Περιορισμός των δικαιωμάτων ανάγνωσης σε ευαίσθητα αρχεία εντός των προσωπικών καταλόγων των χρηστών (`chmod 700 /home/<user>`).
9. **Εξάλειψη Επισφαλών SUID Binaries:** Αφαίρεση του SUID bit από εργαλεία γενικής χρήσης που επιτρέπουν διαφυγή κελύφους:
   ```bash
   chmod u-s /usr/local/bin/nmap
   ```
10. **Εφαρμογή Αρχής Ελαχίστων Προνομίων (Least Privilege):** Διασφάλιση ότι οι λογαριασμοί των υπηρεσιών δικτύου (όπως ο `daemon` ή ο `www-data`) δεν διαθέτουν δικαιώματα πρόσβασης σε εργαλεία μεταγλώττισης ή εκτέλεσης εντολών συστήματος.

## Παραρτήματα

### Παράρτημα Α: Ολοκληρωμένο Τεχνικό Γλωσσάρι

- **Reconnaissance (Αναγνώριση):** Η αρχική φάση συλλογής πληροφοριών σχετικά με το σύστημα-στόχο (διευθύνσεις IP, ανοικτές θύρες, λειτουργικά συστήματα).
- **Enumeration (Απαρίθμηση):** Η διαδικασία ενεργητικής διερεύνησης μιας υπηρεσίας για την εξαγωγή λεπτομερών στοιχείων, όπως ονόματα χρηστών, κοινόχρηστοι πόροι και εκδόσεις λογισμικού.
- **Wordlist (Λεξικό Λέξεων):** Αρχείο κειμένου που περιέχει λίστα πιθανών κωδικών πρόσβασης, ονομάτων χρηστών ή διαδρομών αρχείων για χρήση σε αυτοματοποιημένες δοκιμές.
- **Brute-Force Attack:** Μέθοδος επίθεσης που βασίζεται στη συστηματική, εξαντλητική δοκιμή όλων των πιθανών συνδυασμών μέχρι τον εντοπισμό του σωστού.
- **Hash Function (Συνάρτηση Κατακερματισμού):** Μαθηματικός αλγόριθμος μονόδρομης κατεύθυνσης που μετατρέπει δεδομένα αυθαίρετου μεγέθους σε μια συμβολοσειρά σταθερού μήκους.
- **Cryptographic Salt:** Τυχαία συμβολοσειρά δεδομένων που προστίθεται στον κωδικό πρόσβασης πριν τον κατακερματισμό του, καθιστώντας κάθε hash μοναδικό και προστατεύοντας από επιθέσεις Rainbow Tables.
- **Rainbow Tables:** Προϋπολογισμένες βάσεις δεδομένων που περιέχουν ζεύγη γνωστών κειμένων και των αντίστοιχων hashes τους, επιτρέποντας την άμεση αναζήτηση και ανάκτηση κωδικών.
- **Reverse Shell:** Τεχνική απομακρυσμένης πρόσβασης κατά την οποία ο στόχος εκκινεί μια σύνδεση προς τον σταθμό του επιτιθέμενου και του παραχωρεί πρόσβαση γραμμής εντολών.
- **Bind Shell:** Τεχνική πρόσβασης κατά την οποία ο στόχος ανοίγει μια τοπική θύρα ακρόασης και περιμένει τον επιτιθέμενο να συνδεθεί σε αυτήν.
- **Payload:** Το εκτελέσιμο τμήμα κακόβουλου κώδικα που παραδίδεται στον στόχο για να εκτελέσει μια συγκεκριμένη ενέργεια (π.χ. δημιουργία reverse shell).
- **PTY (Pseudo-Terminal):** Εικονική διεπαφή τερματικού στο Linux που εξομοιώνει ένα φυσικό τερματικό, επιτρέποντας τη διαδραστική εκτέλεση εντολών.
- **SUID (Set User ID) Bit:** Ειδικό δικαίωμα αρχείου σε περιβάλλοντα UNIX/Linux, το οποίο επιτρέπει στους χρήστες να εκτελούν το αρχείο με τα δικαιώματα του ιδιοκτήτη του (συνήθως του `root`).
- **RUID (Real User ID):** Το αναγνωριστικό του πραγματικού χρήστη που εκκίνησε μια διεργασία.
- **EUID (Effective User ID):** Το αναγνωριστικό που καθορίζει τα δικαιώματα πρόσβασης μιας διεργασίας κατά την εκτέλεσή της από τον πυρήνα (kernel).
- **Defense in Depth (Άμυνα σε Βάθος):** Στρατηγική ασφάλειας που βασίζεται στην εφαρμογή πολλαπλών, διαδοχικών επιπέδων προστασίας σε όλη την έκταση της πληροφοριακής υποδομής.
- **Attack Surface (Επιφάνεια Επίθεσης):** Το σύνολο όλων των πιθανών σημείων εισόδου μέσω των οποίων ένας μη εξουσιοδοτημένος χρήστης μπορεί να επιχειρήσει να εισέλθει ή να αντλήσει δεδομένα από ένα σύστημα.

### Παράρτημα Β: Ερωτήσεις Αυτοαξιολόγησης και Εμπέδωσης

1. **Ερώτηση:** Γιατί η καταχώριση ευαίσθητων διαδρομών στο αρχείο `robots.txt` αποτελεί εσφαλμένη πρακτική ασφάλειας;  
   *Απάντηση:* Επειδή το αρχείο είναι δημόσια προσβάσιμο σε οποιονδήποτε. Η καταχώριση διαδρομών σε αυτό αποκαλύπτει ακριβώς ποια σημεία επιθυμεί ο διαχειριστής να προστατεύσει, παρέχοντας άμεσο στόχο στους επιτιθέμενους (Security through Obscurity).
2. **Ερώτηση:** Πώς αξιοποιείται η αδυναμία CWE-204 για την απαρίθμηση χρηστών σε μια εφαρμογή ιστού;  
   *Απάντηση:* Μέσω της διαφοροποίησης των μηνυμάτων σφάλματος (π.χ. «Άκυρος χρήστης» έναντι «Λανθασμένος κωδικός»). Ο επιτιθέμενος απομονώνει τη μεταβλητή του χρήστη και επιβεβαιώνει τα έγκυρα ονόματα πριν δοκιμάσει κωδικούς.
3. **Ερώτηση:** Γιατί είναι απολύτως αναγκαία η ταξινόμηση (`sort`) πριν την αφαίρεση διπλοτύπων με την εντολή `uniq`;  
   *Απάντηση:* Διότι η εντολή `uniq` συγκρίνει αποκλειστικά γειτονικές γραμμές. Εάν πανομοιότυπες εγγραφές βρίσκονται διάσπαρτες στο αρχείο, δεν θα εντοπιστούν χωρίς προηγούμενη ταξινόμηση.
4. **Ερώτηση:** Γιατί η εντολή `su` αποτυγχάνει σε ένα βασικό Web Reverse Shell και πώς αποκαθίσταται η λειτουργία της;  
   *Απάντηση:* Αποτυγχάνει διότι το shell στερείται PTY (ψευδο-τερματικού), το οποίο απαιτείται για την ασφαλή ανάγνωση του κωδικού πρόσβασης. Αποκαθίσταται μέσω της εκτέλεσης `python -c 'import pty; pty.spawn("/bin/bash")'`.
5. **Ερώτηση:** Ποιος είναι ο ακριβής μηχανισμός μέσω του οποίου ένα SUID binary οδηγεί σε απόκτηση root shell;  
   *Απάντηση:* Το εκτελέσιμο τρέχει με EUID `0` (`root`). Εάν το πρόγραμμα επιτρέπει τη διαφυγή σε κέλυφος συστήματος (π.χ. μέσω `system()`) χωρίς να αποποιείται τα προνόμια, το παραγόμενο shell κληρονομεί πλήρη δικαιώματα διαχειριστή.
6. **Ερώτηση:** Ποια είναι η θεμελιώδης διαφορά μεταξύ του αλγορίθμου MD5 και του Argon2id ως προς την αποθήκευση passwords;  
   *Απάντηση:* Ο MD5 είναι εξαιρετικά γρήγορος και ευάλωτος σε μαζικό παραλληλισμό (GPU/ASIC), ενώ ο Argon2id ενσωματώνει ρυθμιζόμενο υπολογιστικό κόστος και απαιτήσεις μνήμης (memory-hard), καθιστώντας τις επιθέσεις brute-force ασύμφορες.
7. **Ερώτηση:** Ποιο ήταν το κρίσιμο μέτρο που, εάν εφαρμοζόταν στο WordPress, θα απέτρεπε το Initial Access;  
   *Απάντηση:* Η απενεργοποίηση της επεξεργασίας αρχείων μέσω της εντολής `define('DISALLOW_FILE_EDIT', true);` στο αρχείο `wp-config.php`.
8. **Ερώτηση:** Γιατί προτιμάται η μέθοδος HTTP POST έναντι της GET για την υποβολή διαπιστευτηρίων σύνδεσης;  
   *Απάντηση:* Επειδή η μέθοδος POST μεταφέρει τα διαπιστευτήρια στο σώμα του αιτήματος και όχι στο URL (Query String), αποτρέποντας την καταγραφή τους στα web server access logs, στο ιστορικό του browser και στους proxies.
9. **Ερώτηση:** Ποιο είναι το πλεονέκτημα του Reverse Shell έναντι του Bind Shell σε περιβάλλοντα που προστατεύονται από firewall;  
   *Απάντηση:* Το Reverse Shell εκκινεί εξερχόμενη σύνδεση από τον στόχο προς τον επιτιθέμενο. Τα firewalls συνήθως επιτρέπουν την εξερχόμενη κίνηση, ενώ μπλοκάρουν τις εισερχόμενες συνδέσεις που απαιτούνται από τα Bind Shells.
10. **Ερώτηση:** Πώς η αρχή των ελαχίστων προνομίων θα περιόριζε τις επιπτώσεις της παραβίασης του web server;  
    *Απάντηση:* Εάν ο service user (`daemon`) είχε πρόσβαση αποκλειστικά στα απολύτως απαραίτητα αρχεία της εφαρμογής και δεν μπορούσε να διαβάσει αρχεία σε φακέλους χρηστών (`/home/robot`) ή να εκτελέσει SUID binaries, η κλιμάκωση θα είχε αποτραπεί.
