## 1. Εισαγωγή στην Εικονικοποίηση (Virtualization) και το Oracle VM VirtualBox

Η εικονικοποίηση τοποθετεί έναν **hypervisor** ανάμεσα στο υλικό και στο λογισμικό που εκτελείται. Ο hypervisor προσομοιώνει μια ολόκληρη πλατφόρμα υλικού — CPU, μνήμη, δίσκο και δίκτυο — και κάθε τέτοια πλατφόρμα είναι μια **Εικονική Μηχανή (Virtual Machine - VM)**.

Οι hypervisors διακρίνονται σε δύο κατηγορίες:

* **Τύπου 1 (Bare-Metal):** Εκτελούνται απευθείας πάνω στο φυσικό υλικό, χωρίς λειτουργικό σύστημα από κάτω (VMware ESXi, KVM, Xen, Proxmox VE). Είναι γρήγοροι και χαμηλής καθυστέρησης, γι' αυτό αποτελούν τον κανόνα στις υποδομές κέντρων δεδομένων.
* **Τύπου 2 (Hosted):** Εγκαθίστανται ως ένα συνηθισμένο πρόγραμμα μέσα σε ένα λειτουργικό σύστημα (Oracle VM VirtualBox, VMware Workstation). Το host διαχειρίζεται τις φυσικές συσκευές· ο hypervisor μεσολαβεί για τη μηχανή.

Οι σύγχρονοι επεξεργαστές x86 προσθέτουν μια τρίτη διάσταση σε αυτή την εικόνα: την **εικονικοποίηση με υποστήριξη υλικού**. Τα Intel **VT-x** (με **EPT** για nested paging) και AMD **AMD-V** (με **NPT**) επιτρέπουν στη μηχανή να εκτελεί τις περισσότερες εντολές απευθείας σε μειωμένο επίπεδο προνομίων, ενώ οι ευαίσθητες εντολές παγιδεύονται στον hypervisor — έτσι μια VM τρέχει με σχεδόν φυσική ταχύτητα.

```
+--------------------------------------------------------------+
|             Φυσικό Υλικό Host (CPU, RAM, Κάρτα Δικτύου)      |
+--------------------------------------------------------------+
|            Λειτουργικό Σύστημα Host (Linux / Windows / macOS)|
+--------------------------------------------------------------+
|       Hypervisor Τύπου 2 (VirtualBox Engine & Kernel Drivers)|
+------------------------------+-------------------------------+
| Εικονική Μηχανή A (Guest VM) | Εικονική Μηχανή B (Guest VM)  |
|   +----------------------+   |   +----------------------+    |
|   | Guest OS             |   |   | Guest OS             |    |
|   | Εικονικές Συσκευές   |   |   | Εικονικές Συσκευές   |    |
+---+----------------------+---+---+----------------------+----+
```

<details>
<summary><strong>Περισσότερα</strong> — πώς κάθεται ένας hypervisor Τύπου 2 στο μηχάνημά σας</summary>

**Τι είναι το Oracle VM VirtualBox;** Ένας hypervisor Τύπου 2, ανοικτού κώδικα και πολυπλατφορμικός, για Windows, Linux και macOS. Δίνει σε κάθε μηχανή εικονικούς πυρήνες CPU, ρυθμιζόμενη μνήμη, προσομοιωμένους ελεγκτές αποθήκευσης (SATA, NVMe, SCSI, IDE) και εικονικές κάρτες δικτύου. Αυτή η απομόνωση το κάνει βασικό εργαλείο για δοκιμές ασφαλείας, αυτοματοποιημένες ροές ανάπτυξης, ανάλυση πρωτοκόλλων και δοκιμές λογισμικού.

</details>

## 2. Κατανόηση και Λήψη Αρχείων OVA

Μια εικονική μηχανή δεν είναι ένα μόνο αρχείο: είναι ένα σύνολο αρχείων ρυθμίσεων και εικόνων δίσκου. Για να μεταφέρονται μεταξύ hypervisors, ο οργανισμός DMTF καθιέρωσε το πρότυπο **Open Virtualization Format (OVF)**.

### Διαφορά μεταξύ OVF και OVA

Το **OVF** είναι ένας φάκελος με ξεχωριστά αρχεία· το **OVA** είναι το ίδιο πακέτο σε ένα μόνο αρχείο `tar`.

<details>
<summary><strong>Περισσότερα</strong> — τι περιέχει ένα πακέτο OVF</summary>

* **OVF (Open Virtualization Format):** ένα σύνολο μη συμπιεσμένων αρχείων — ένα αρχείο περιγραφής XML (`.ovf`) με τις προδιαγραφές υλικού (vCPU, RAM, ελεγκτές δίσκου, κάρτες δικτύου), μία ή περισσότερες εικόνες δίσκου (`.vmdk` ή `.vhd`), και ένα προαιρετικό αρχείο καταγραφής ελέγχου ακεραιότητας (`.mf`) με τιμές κατακερματισμού SHA. Η μορφή ορίζεται από τον οργανισμό DMTF στην προδιαγραφή **DSP0243**, και το manifest είναι αυτό που κάνει το πακέτο επαληθεύσιμο από άκρη σε άκρη.
* **OVA (Open Virtual Appliance):** ολόκληρο το πακέτο OVF συσκευασμένο σε ένα αρχείο POSIX `tar`. Όντας ένα αρχείο, αποφεύγει την απώλεια και τα προβλήματα ασυμβατότητας κατά τη λήψη ή τη μεταφορά.

</details>

## 3. Εισαγωγή και Ρύθμιση του OVA στο VirtualBox

Η εισαγωγή αποσυμπιέζει το αρχείο tar, μεταφράζει τις προδιαγραφές υλικού στο τοπικό σχήμα XML του VirtualBox (`.vbox`) και αντιγράφει τους εικονικούς δίσκους στον τοπικό χώρο αποθήκευσης.

1. Ανοίξτε το **Oracle VM VirtualBox Manager**.
2. Μεταβείτε στο **File (Αρχείο)** $\rightarrow$ **Import Appliance... (Εισαγωγή Συσκευής...)** (ή `Ctrl + I` / `Cmd + I`).
3. Στο πεδίο **Source (Πηγή)**, επιλέξτε **Local File System**, πατήστε το εικονίδιο φακέλου και διαλέξτε το αρχείο `.ova`. Πατήστε **Next (Επόμενο)**.
4. Στην καρτέλα **Appliance Settings (Ρυθμίσεις Συσκευής)** ελέγξτε τις προδιαγραφές:
   * **Name & Base Folder:** προσαρμόστε τον φάκελο προορισμού αν κρατάτε δίσκους VM σε ξεχωριστό NVMe ή δεύτερο αποθηκευτικό χώρο.
   * **CPU & RAM:** ορίστε τους πόρους ανάλογα με το host και αποφύγετε να υπερβείτε τον αριθμό φυσικών πυρήνων ή το 50–60% της συνολικής μνήμης, για να μην προκληθεί swapping και υποβάθμιση.
   * **MAC Address Policy:** επιλέξτε **Generate new MAC addresses for all network adapters** αν θα κλωνοποιήσετε τη μηχανή ή θα τρέξετε πολλά αντίγραφα· ίδιες MAC στο ίδιο επίπεδο 2 προκαλούν συγκρούσεις ARP και απώλεια πακέτων.
5. Πατήστε **Finish (Ολοκλήρωση)**. Το VirtualBox αποσυμπιέζει και μετατρέπει τους δίσκους, και η νέα μηχανή εμφανίζεται στη λίστα, έτοιμη για ρύθμιση δικτύου.

<details>
<summary><strong>Περισσότερα</strong> — πού κάνει τη δουλειά του ο οδηγός εισαγωγής</summary>

Η εισαγωγή είναι κάτι παραπάνω από αντιγραφή. Αποσυμπιέζει το αρχείο OVA, μεταφράζει το σχήμα υλικού του DMTF στη γηγενή διάταξη XML του VirtualBox (`.vbox`) και μετατρέπει ή αντιγράφει κάθε εικονικό δίσκο στον τοπικό χώρο αποθήκευσης.

Επειδή οι δίσκοι μετατρέπονται εδώ, είναι η στιγμή να αποφασίσετε **πού** θα φιλοξενηθούν. Ένας γρήγορος SSD/NVMe κάνει τεράστια διαφορά στους χρόνους εκκίνησης και στην απόκριση των μηχανών.

</details>

### Snapshots, μορφές δίσκου και επαναφορά

Το VirtualBox αποθηκεύει κάθε δίσκο είτε σε δική του μορφή (`.vdi`) είτε σε διαλειτουργική `.vmdk`/`.vhd`. Ένα **snapshot** δεν αντιγράφει ολόκληρο τον δίσκο: παγώνει την τρέχουσα κατάσταση και ανοίγει ένα **differencing image** που καταγράφει κάθε επόμενη εγγραφή με copy-on-write — γι' αυτό είναι γρήγορο και φθηνό.

Για ένα εργαστήριο ασφάλειας αυτή είναι η πιο χρήσιμη συνήθεια ασφαλείας: πάρτε snapshot *πριν* από κάθε καταστροφική άσκηση (**Machine → Take Snapshots**, ή `VBoxManage snapshot "<vm>" take "clean-before-lab"`) και επιστρέψτε σε αυτό μετά. Δύο επιπτώσεις προκύπτουν από τον σχεδιασμό copy-on-write: το differencing image μεγαλώνει με κάθε εγγραφή (τα snapshots **δεν** είναι αντίγραφο ασφαλείας — αντιγράψτε το `.vdi`), και μια μακριά αλυσίδα snapshots επιβραδύνει τη μηχανή, οπότε συνενώστε τα όταν τελειώσει η άσκηση.

## 4. Λειτουργίες Δικτύωσης στο VirtualBox: Αρχιτεκτονική Ανάλυση

Το VirtualBox προσφέρει πολλές λειτουργίες δικτύωσης και η σωστή επιλογή εξαρτάται από τον βαθμό απομόνωσης και πρόσβασης που χρειάζεστε μεταξύ host, VM και εξωτερικού δικτύου. Το διάγραμμα αντιπαραβάλλει τις δύο που θα χρησιμοποιήσετε περισσότερο:

```
       +-------------------------------------------------------+
       |                     Φυσικό LAN                        |
       +-------------------------------------------------------+
                                  ^
                                  | (NAT Masquerade / Bridged)
       +--------------------------v----------------------------+
       |                Host Machine (Φυσική NIC)              |
       +-------------------------------------------------------+
           |                                       |
    [Μηχανή NAT / Εικονικός Router]         [Host-Only Εικονικός Adapter]
           |                                       |
    +------v------+                         +------v------+
    | NAT Network |                         |  Host-Only  |
    | 10.0.2.0/24 |                         | 192.168.56.x|
    +------+------+                         +------+------+
           |                                       |
     +-----+-----+                           +-----+-----+
     |           |                           |           |
  +--v---+    +--v---+                    +--v---+    +--v---+
  | VM 1 |    | VM 2 |                    | VM 1 |    | VM 2 |
  +------+    +------+                    +------+    +------+
  (Επικοινωνία VM-με-VM: ΝΑΙ,             (Επικοινωνία Host <-> VM: ΝΑΙ,
   Πρόσβαση στο Internet: ΝΑΙ)             Πρόσβαση στο Internet: ΟΧΙ)
```

Ο πίνακας παρακάτω είναι ο γρηγορότερος τρόπος να διαλέξετε:

| Λειτουργία Δικτύου | VM $\rightarrow$ Internet | Host $\rightarrow$ VM Άμεσα | VM $\rightarrow$ Host Άμεσα | Επικοινωνία VM-με-VM |
| :--- | :---: | :---: | :---: | :---: |
| **Default NAT** | Ναι | Όχι (απαιτεί Port Forwarding) | Περιορισμένα (μέσω Gateway) | Όχι |
| **Host-Only** | Όχι | Ναι (απευθείας IP) | Ναι (απευθείας IP) | Ναι |
| **NAT Network** | Ναι | Όχι (απαιτεί Port Forwarding) | Περιορισμένα (μέσω Gateway) | Ναι |
| **Bridged (Γέφυρα)**| Ναι | Ναι (ως ισότιμη συσκευή στο LAN)| Ναι | Ναι |

### Host-Only Adapter vs. NAT Network — Οι βασικές διαφορές

Οι δύο αυτές λειτουργίες συγχέονται πιο συχνά, οπότε η σύντομη απάντηση:

| | **Host-Only Adapter** | **NAT Network** |
| :--- | :--- | :--- |
| **Σκοπός** | Επικοινωνία Host ↔ VM και VM ↔ VM σε ιδιωτικό, offline δίκτυο | Επικοινωνία VM ↔ VM **και** κοινή πρόσβαση στο internet |
| **Πρόσβαση στο internet** | ❌ Καμία — πλήρως απομονωμένο | ✅ Ναι — εξερχόμενη μέσω της σύνδεσης του host |
| **Host → VM** | ✅ Άμεσα (ping / browse / SSH στην IP του VM) | ❌ Μόνο με port forwarding |
| **VM → VM** | ✅ Ναι | ✅ Ναι |
| **Τυπική χρήση** | Ανάλυση malware, καταγραφή κίνησης, ασκήσεις σε κλειστό δίκτυο | Εργαστήρια πολλών κόμβων που χρειάζονται updates και λήψεις |

**Πρακτικός κανόνας:** αν τα VMs χρειάζονται internet, χρησιμοποιήστε **NAT Network**· αν δεν πρέπει να βγουν στο internet, χρησιμοποιήστε **Host-Only Adapter**. Για να τα έχετε και τα δύο, δώστε στο VM δύο adapters (dual-homed).

> ⚠️ **Το NAT Network δεν είναι το ίδιο με το NAT.** Η επιλογή **NAT** είναι η *προεπιλεγμένη ανά VM*: κρύβει κάθε μηχανή στο δικό της ιδιωτικό υποδίκτυο, οπότε δύο VMs σε απλό NAT δεν βλέπονται μεταξύ τους. Το **NAT Network** είναι ένα *κοινόχρηστο, επώνυμο* δίκτυο που το δημιουργείτε μία φορά και συνδέετε πολλά VMs. Κατά τη ρύθμιση της μηχανής πρέπει να επιλέξετε **NAT Network** από το πεδίο **Attached to:** — **όχι** **NAT** — και μετά το όνομα του δικτύου που φτιάξατε.

### Πώς ενεργοποιούμε ένα NAT Network (όχι NAT)

Για να επικοινωνούν πολλές εικονικές μηχανές μεταξύ τους κρατώντας παράλληλα πρόσβαση στο internet, δημιουργήστε και αναθέστε ένα ειδικό NAT Network.

### Βήμα 1: Δημιουργία του Κεντρικού NAT Network

1. Στο κεντρικό παράθυρο του VirtualBox, ανοίξτε το **Tools (Εργαλεία)** (το εικονίδιο με τις τρεις γραμμές πάνω αριστερά) και επιλέξτε **Network (Δίκτυο)**.
2. Επιλέξτε την καρτέλα **NAT Networks**.
3. Πατήστε **Create (Δημιουργία)**. Θα δημιουργηθεί μια εγγραφή με όνομα `NatNetwork`.
4. Επιλέξτε το `NatNetwork` και ορίστε τις ιδιότητες:
   * **IPv4 Prefix (Πρόθεμα IPv4):** ένα μη συγκρουόμενο εύρος RFC 1918, όπως `10.0.2.0/24` ή `192.168.15.0/24`, που δεν πέφτει πάνω στο φυσικό δίκτυο του host.
   * **Enable DHCP (Ενεργοποίηση DHCP):** ενεργοποιήστε το ώστε ο ενσωματωμένος διακομιστής DHCP να αποδίδει αυτόματα διευθύνσεις στις μηχανές κατά την εκκίνηση.
   * **Enable IPv6:** αφήστε το απενεργοποιημένο εκτός αν το σενάριό σας δοκιμάζει dual-stack ή δρομολόγηση IPv6.
5. Πατήστε **Apply (Εφαρμογή)**.

### Βήμα 2: Σύνδεση των Εικονικών Μηχανών στο NAT Network

Για κάθε μηχανή που θέλετε να μπει σε αυτό το κοινό περιβάλλον:

1. Βεβαιωθείτε ότι η μηχανή είναι απενεργοποιημένη.
2. Επιλέξτε τη μηχανή και πατήστε **Settings (Ρυθμίσεις)** (ή `Ctrl + S`).
3. Μεταβείτε στην κατηγορία **Network (Δίκτυο)**.
4. Στην καρτέλα **Adapter 1 (Προσαρμογέας 1)**:
   * Ενεργοποιήστε το **Enable Network Adapter**.
   * Στο **Attached to (Συνδεδεμένο σε):** επιλέξτε **NAT Network** — *όχι* την απλή επιλογή **NAT**, που δίνει στη μηχανή ξεχωριστό ιδιωτικό δίκτυο.
   * Στο **Name (Όνομα):** επιλέξτε το δίκτυο του Βήματος 1 (π.χ. `NatNetwork`).
5. Αναπτύξτε το **Advanced (Για προχωρημένους)**:
   * **Adapter Type:** κρατήστε το `Intel PRO/1000 MT Desktop (82540EM)` για ευρεία συμβατότητα ή `Paravirtualized Network (virtio-net)` για Linux guest με παραεικονικό I/O.
   * **Promiscuous Mode:** `Deny` για κανονική χρήση· `Allow VMs` ή `Allow All` μόνο όταν τρέχετε αναλυτή πακέτων (Wireshark, Suricata) μέσα σε guest.
6. Πατήστε **OK** και επαναλάβετε τη διαδικασία για κάθε μηχανή.

### Τι είναι το NAT Network και πώς διαφέρει από το απλό NAT;

| Τύπος Δικτύου | Πρόσβαση στο Internet | Επικοινωνία μεταξύ VMs | Πρόσβαση από το Host |
| :--- | :---: | :---: | :---: |
| **NAT (Απλό)** | Ναι | Όχι (κάθε VM είναι απομονωμένη) | Μόνο με Port Forwarding |
| **NAT Network** | Ναι | **Ναι (όλες οι VMs στο ίδιο δίκτυο)** | Μόνο με Port Forwarding |
| **Internal Network** | Όχι | Ναι | Όχι |
| **Bridged Adapter** | Ναι | Ναι (μέσω του φυσικού LAN) | Ναι (σαν ξεχωριστή φυσική συσκευή) |

Το **NAT Network** λειτουργεί σαν ένας εικονικός router με ενσωματωμένο switch: όλες οι μηχανές που συνδέονται σε αυτό ανήκουν στο ίδιο υποδίκτυο και μπορούν να επικοινωνήσουν μεταξύ τους (π.χ. μέσω `ping`, `ssh`, web services), ενώ ταυτόχρονα μοιράζονται τη σύνδεση του υπολογιστή σας (host) προς το διαδίκτυο.

### Τεχνική Επεξήγηση Παραμέτρων:
* **Promiscuous Mode (Καρτέλα Advanced):** 
  - Εξ ορισμού είναι ρυθμισμένο σε `Deny`. 
  - Αν δοκιμάζετε εργαλεία ανάλυσης δικτύου (όπως το Wireshark) ή θέλετε να παρακολουθείτε όλη την κυκλοφορία του υποδικτύου, μπορείτε να το αλλάξετε σε `Allow VMs` ή `Allow All`.
* **MAC Address:** Κάθε εικονική κάρτα δικτύου λαμβάνει μια μοναδική διεύθυνση MAC, ώστε ο DHCP server να αποδίδει αξιόπιστα IP διευθύνσεις χωρίς διενέξεις.

## Έλεγχος Λειτουργίας (Verification)

Μόλις εκκινήσουν οι μηχανές σας, μπορείτε να επαληθεύσετε τη σωστή λειτουργία του δικτύου:

1. **Έλεγχος IP διεύθυνσης:**
   - Σε Linux: `ip a` ή `ifconfig`
   - Σε Windows: `ipconfig`
   *(Θα πρέπει να δείτε IP εντός του υποδικτύου, π.χ. `10.0.2.4`, `10.0.2.15` κ.λπ.)*

2. **Έλεγχος εξωτερικής πρόσβασης (Internet):**
   ```bash
   ping -c 4 8.8.8.8
   ```

3. **Έλεγχος επικοινωνίας μεταξύ των VMs:**
   Εκτελέστε ping από την πρώτη εικονική μηχανή προς την IP της δεύτερης:
   ```bash
   ping <IP_VM_Θύματος>
   ```
