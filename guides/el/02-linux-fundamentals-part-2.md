## Εισαγωγή

Το 1ο Μέρος κάλυψε το θεμελιώδες επίπεδο του Linux πάνω στο οποίο οικοδομούνται όλα τα υπόλοιπα: το κέλυφος, το σύστημα αρχείων, το κείμενο, τα πακέτα και τα δικαιώματα. Το παρόν μέρος προχωρά ένα επίπεδο βαθύτερα, εξετάζοντας τους παράγοντες που καθορίζουν την πραγματική συμπεριφορά ενός συστήματος. Αναλύουμε το **δίκτυο** — τις διεπαφές που παρουσιάζει το σύστημα, τις διευθύνσεις και τα αναγνωριστικά υλικού που φέρει, τον διακομιστή που αποδίδει τις διευθύνσεις του, καθώς και την υπηρεσία ονοματοδοσίας την οποία συμβουλεύεται πριν συνδεθεί οπουδήποτε. Εξετάζουμε τις **διεργασίες** — πώς να παρακολουθείτε καθετί που εκτελείται, να ελέγχετε τους πόρους που καταναλώνονται, να αποφασίζετε ποιες εργασίες απαιτούν την προσοχή του επεξεργαστή, να τερματίζετε ό,τι δυσλειτουργεί και να προγραμματίζετε εργασίες για μεταγενέστερη εκτέλεση. Τέλος, αναλύουμε τις **μεταβλητές περιβάλλοντος**, το αθόρυβο επίπεδο παραμετροποίησης που ορίζει ποιο πρόγραμμα θα εκτελεστεί όταν πληκτρολογείτε ένα απλό όνομα, ποιος επιλυτής θα ανταποκριθεί και ποιες πληροφορίες γνωρίζει εξαρχής ένα νέο κέλυφος.

Κάθε ενότητα διατηρεί την ίδια δομή με το 1ο Μέρος: μια καταγραφή των εντολών που πληκτρολογήθηκαν και των αποτελεσμάτων που παρήχθησαν, ακολουθούμενη από διεξοδική επεξήγηση σε παραγράφους σχετικά με το τι συνέβη και γιατί έχει σημασία. Όπου ένα παραδοσιακό εργαλείο διαθέτει σύγχρονο αντικαταστάτη — όπως η `ifconfig` έναντι της `ip`, η `netstat` έναντι της `ss`, ή η `top` έναντι της `htop` — παρουσιάζονται και τα δύο, καθώς η παλαιότερη τεκμηρίωση, οι τεχνικές συνεντεύξεις και τα πραγματικά συστήματα παραγωγής τα χρησιμοποιούν συχνά παράλληλα.

Μια προειδοποίηση πριν ξεκινήσετε: Δύο από τα τρία θέματα που καλύπτονται εδώ ενέχουν τον κίνδυνο να σας αποκόψουν από το μηχάνημα στο οποίο εργάζεστε. Η αλλαγή μιας διεύθυνσης μέσω σύνδεσης SSH τερματίζει άμεσα τη συνεδρία σας, ενώ ο τερματισμός μιας λανθασμένης διεργασίας μπορεί να διακόψει μια κρίσιμη υπηρεσία. Συνιστάται να εργάζεστε μέσα σε μια εικονική μηχανή, να λαμβάνετε προκαταρκτικό στιγμιότυπο (snapshot) και να διατηρείτε ανοιχτή μια δεύτερη κονσόλα όσο πειραματίζεστε με τις ρυθμίσεις δικτύου.

### Πώς να διαβάζετε τις καταγραφές τερματικού

Οι συμβάσεις είναι ίδιες με εκείνες του 1ου Μέρους και αξίζει να επαναληφθούν, καθώς οι προτροπές αλλάζουν ανάλογα με τα δικαιώματα. Η προτροπή `root@kali:~#` αντιστοιχεί σε κέλυφος που εκτελείται υπό τον παντοδύναμο λογαριασμό root, και το τελικό `#` αποτελεί σαφή προειδοποίηση. Η προτροπή `student@kali:~$` αντιστοιχεί σε έναν απλό χρήστη, με το `$` να υποδηλώνει τη διαφορά προνομίων. Οτιδήποτε βρίσκεται μετά την προτροπή στη γραμμή εισόδου αποτελεί ό,τι πληκτρολογήθηκε, ενώ κάθε γραμμή από κάτω μέχρι την επόμενη προτροπή αποτελεί έξοδο του προγράμματος. Τίποτα δεν εκτελείται μέχρι να πατηθεί το πλήκτρο Enter. Κείμενο εντός γωνιωδών αγκυλών, όπως `dig <όνομα>`, συνιστά δεσμευτικό θέσης που αντικαθιστάτε με πραγματική τιμή. Τέλος, τα αποτελέσματα καταγράφηκαν σε συστήματα βασισμένα στο Debian και είναι ενδεικτικά, καθώς οι διευθύνσεις IP, οι διευθύνσεις MAC, τα αναγνωριστικά PID και οι χρονοσημάνσεις θα διαφέρουν στο δικό σας μηχάνημα.

## 1. Διαχείριση δικτύων

Η δικτύωση αποτελεί θεμελιώδη τομέα για όσους ασχολούνται με την ασφάλεια πληροφοριακών συστημάτων, καθώς το μεγαλύτερο μέρος των υποδομών που θα κληθείτε να αξιολογήσετε βρίσκεται στο δίκτυο και όχι σε ένα απομονωμένο μηχάνημα. Ακόμη και για την καθημερινή διαχείριση, είναι αδύνατο να προχωρήσετε χωρίς να γνωρίζετε πώς να επιθεωρείτε μια διεπαφή, να ερμηνεύετε τη διεύθυνση που διαθέτει, να κατανοείτε ποιος διακομιστής επιλύει τα ονόματα και να τροποποιείτε αυτές τις ρυθμίσεις κατά βούληση. Αυτή η ενότητα εξετάζει τα απαραίτητα εργαλεία με τη σειρά που θα τα χρησιμοποιούσατε: επιθεώρηση ενσύρματης διεπαφής, επιθεώρηση ασύρματης διεπαφής, αλλαγή διεύθυνσης IP, πλαστογράφηση διεύθυνσης υλικού (MAC), αίτηση απόδοσης διεύθυνσης από DHCP, ερωτήματα στο DNS, αλλαγή επιλυτή και τοπική αντιστοίχιση ονομάτων.

Αξίζει να σημειωθεί ότι τα παραδοσιακά εργαλεία όπως `ifconfig`, `iwconfig`, `route` και `netstat` προέρχονται από το πακέτο `net-tools`, το οποίο πολλές σύγχρονες διανομές δεν εγκαθιστούν πλέον από προεπιλογή, έχοντας αντικατασταθεί από την εντολή `ip` (της σουίτας `iproute2`) και την `ss`. Κάθε παραδοσιακή εντολή σε αυτή την ενότητα συνοδεύεται από το σύγχρονο αντίστοιχό της, καθώς η παλαιότερη τεκμηρίωση και οι ερωτήσεις τεχνικών συνεντεύξεων βρίθουν αναφορών στην `ifconfig`, ενώ κάθε σύγχρονη διανομή παρέχει προεγκατεστημένη την `ip`.

### 1.1 `ifconfig` — Ανάλυση των διεπαφών δικτύου

Η εντολή `ifconfig` αποτελεί το κλασικό εργαλείο αλληλεπίδρασης με τις ενεργές διεπαφές δικτύου. Όταν εκτελείται χωρίς ορίσματα, εκτυπώνει κάθε διεπαφή που αναγνωρίζει ο πυρήνας, η οποία σε ένα τυπικό εργαστηριακό μηχάνημα περιλαμβάνει έναν φυσικό ή εικονικό προσαρμογέα Ethernet καθώς και τη διεπαφή τοπικής αναδρομής (loopback).

```bash
root@kali:~# ifconfig
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.17  netmask 255.255.255.0  broadcast 192.168.1.255
        inet6 fe80::20c:29ff:fe1b:2c3d  prefixlen 64  scopeid 0x20<link>
        ether 00:0c:29:1b:2c:3d  txqueuelen 1000  (Ethernet)
        RX packets 10422  bytes 9012443 (8.5 MiB)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 5120  bytes 774211 (756.0 KiB)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0

lo: flags=73<UP,LOOPBACK,RUNNING>  mtu 65536
        inet 127.0.0.1  netmask 255.0.0.0
        inet6 ::1  prefixlen 128  scopeid 0x10<host>
        loopback  txqueuelen 1000  (Local Loopback)
        RX packets 118  bytes 9412 (9.1 KiB)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 118  bytes 9412 (9.1 KiB)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
```

Στην έξοδο καταγράφονται δύο διεπαφές. Η πρώτη γραμμή κάθε τμήματος αναφέρει το όνομα της διεπαφής και τις σημαίες κατάστασής της: η ένδειξη `UP` σημαίνει ότι η διεπαφή είναι διοικητικά ενεργοποιημένη, η `RUNNING` υποδηλώνει ότι ο οδηγός ανιχνεύει φυσική σύνδεση (συνδεδεμένο καλώδιο ή εικονικό μεταγωγέα), οι `BROADCAST` και `MULTICAST` περιγράφουν τους τύπους κίνησης που γίνονται δεκτοί, και το `mtu 1500` αντιπροσωπεύει τη μέγιστη μονάδα μετάδοσης (το μεγαλύτερο ωφέλιμο φορτίο που μεταφέρει η ζεύξη σε ένα πλαίσιο). Η διεπαφή τοπικής αναδρομής διαθέτει `mtu` 65536, επειδή δεν αντιστοιχεί σε φυσικό καλώδιο και τα πακέτα δεν εγκαταλείπουν ποτέ το ίδιο το μηχάνημα.

Η δεύτερη γραμμή περιλαμβάνει τη διευθυνσιοδότηση. Η καταγραφή `inet 192.168.1.17 netmask 255.255.255.0 broadcast 192.168.1.255` αφορά το IPv4: τη διεύθυνση IP, τη μάσκα υποδικτύου που διαχωρίζει το τμήμα δικτύου από το τμήμα κόμβου, και τη διεύθυνση εκπομπής που προσεγγίζει κάθε κόμβο στο τοπικό τμήμα. Μια μάσκα `/24` (255.255.255.0) με διεύθυνση 192.168.1.17 ορίζει ως δίκτυο το 192.168.1.0, εύρος διαθέσιμων κόμβων από .1 έως .254 και διεύθυνση εκπομπής τη .255. Η γραμμή `inet6` αντιστοιχεί στην αυτόματα παραγόμενη διεύθυνση IPv6 τοπικής ζεύξης (link-local), αναγνωρίσιμη από το πρόθεμα `fe80::`, η οποία υφίσταται ακόμη και σε δίκτυα χωρίς ρητή ρύθμιση IPv6.

Η τρίτη γραμμή περιγράφει το επίπεδο ζεύξης δεδομένων. Το πεδίο `ether` αναγράφει τη διεύθυνση MAC, το μοναδικό αναγνωριστικό υλικού της κάρτας δικτύου, όπου το πρόθεμα `00:0c:29` ταυτοποιεί έναν εικονικό προσαρμογέα VMware. Το πεδίο `txqueuelen` καθορίζει το μήκος της ουράς μετάδοσης.

Το υπόλοιπο τμήμα περιλαμβάνει στατιστικά στοιχεία. Οι μετρητές `RX` και `TX` καταγράφουν πακέτα και bytes που λήφθηκαν και στάλθηκαν, ενώ οι μετρητές `errors`, `dropped`, `overruns`, `carrier` και `collisions` καταγράφουν σφάλματα επικοινωνίας. Μια διαρκώς αυξανόμενη τιμή στα πεδία `errors` ή `dropped` συνήθως υποδηλώνει ελαττωματικό καλώδιο, προβληματική θύρα ή αναντιστοιχία ρυθμίσεων διπλής κατεύθυνσης (duplex). Όλοι αυτοί οι μετρητές μηδενίζονται όταν η διεπαφή απενεργοποιηθεί και ενεργοποιηθεί εκ νέου.

Το σύγχρονο αντίστοιχο αυτής της εντολής είναι η `ip addr` (συχνά συντομευμένη ως `ip a`), η οποία παρουσιάζει τις ίδιες πληροφορίες με διαφορετική διάταξη:

```bash
root@kali:~# ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128 
eth0             UP             192.168.1.17/24 fe80::20c:29ff:fe1b:2c3d/64
root@kali:~# ip route
default via 192.168.1.1 dev eth0 proto dhcp metric 100 
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.17 metric 100 
```

Η παράμετρος `-br` παράγει συνοπτική έξοδο (brief) μίας γραμμής ανά διεπαφή, ιδανική όταν αναζητάτε άμεσα τη διεύθυνση. Η δεύτερη εντολή, `ip route`, εκτυπώνει τον πίνακα δρομολόγησης, όπου η γραμμή `default via 192.168.1.1 dev eth0` προσδιορίζει την προεπιλεγμένη πύλη (gateway), δηλαδή τον δρομολογητή στον οποίο αποστέλλονται τα πακέτα όταν ο προορισμός τους δεν ανήκει στο τοπικό υποδίκτυο. Η γνώση της πύλης είναι κρίσιμη, καθώς η προεπιλεγμένη διαδρομή διαφοροποιεί ένα μηχάνημα που μπορεί να επικοινωνήσει με το διαδίκτυο από ένα μηχάνημα που μπορεί να μιλήσει μόνο με τους τοπικούς γείτονές του.

### 1.2 `iwconfig` — Έλεγχος ασύρματων συσκευών δικτύου

Εάν το σύστημα διαθέτει ασύρματο προσαρμογέα, η `iwconfig` αποτελεί το παραδοσιακό εργαλείο ανάγνωσης των ραδιοφωνικών ρυθμίσεών του: του δικτύου στο οποίο είναι συνδεδεμένο, του σημείου πρόσβασης (AP), της συχνότητας, του ρυθμού μετάδοσης και της ποιότητας σήματος.

```bash
root@kali:~# iwconfig
lo        no wireless extensions.

eth0      no wireless extensions.

wlan0     IEEE 802.11  ESSID:"LAB-AP"  
          Mode:Managed  Frequency:2.437 GHz  Access Point: 3C:37:86:1A:2B:40   
          Bit Rate=72.2 Mb/s   Tx-Power=20 dBm   
          Retry short limit:7   RTS thr:off   Fragment thr:off
          Encryption key:off
          Power Management:off
          Link Quality=58/70  Signal level=-52 dBm  
          Rx invalid nwid:0  Rx invalid crypt:0  Rx invalid frag:0
          Tx excessive retries:0  Invalid misc:0   Missed beacon:0
```

Σε ένα μηχάνημα χωρίς ασύρματο υλικό — συνηθισμένη περίπτωση στις εικονικές μηχανές — κάθε διεπαφή αναφέρει `no wireless extensions`, αποτέλεσμα απολύτως αναμενόμενο. Όταν υπάρχει ασύρματη κάρτα, η έξοδος παρουσιάζει πεδία κρίσιμης σημασίας: το `ESSID:"LAB-AP"` είναι το όνομα του δικτύου στο οποίο συνδέθηκε η κάρτα, και το `Mode:Managed` υποδηλώνει λειτουργία απλού πελάτη. Το πεδίο `Access Point` εμφανίζει τη διεύθυνση MAC του δρομολογητή με τον οποίο έγινε η σύνδεση, στοιχείο χρήσιμο για εντοπισμό φυσικής τοποθεσίας ή ανίχνευση κακόβουλων σημείων πρόσβασης (rogue APs). Η ένδειξη `Link Quality=58/70 Signal level=-52 dBm` εκφράζει την ισχύ του σήματος, όπου τιμές πλησιέστερες στο μηδέν υποδηλώνουν ισχυρότερο σήμα, καθιστώντας τα −52 dBm ένδειξη εξαιρετικής σύνδεσης.

Σε επίπεδο ασφάλειας, το πεδίο `Encryption key:off` αποκαλύπτει εάν η ζεύξη χρησιμοποιεί κρυπτογράφηση, ενώ ο μετρητής `Rx invalid crypt` καταγράφει πλαίσια που απέτυχαν στον έλεγχο ακεραιότητας, γεγονός που σε κρυπτογραφημένο δίκτυο μπορεί να υποδηλώνει παρεμβολές ή επίθεση. Η σύγχρονη εντολή αντικατάστασης είναι η `iw` (π.χ. `iw dev wlan0 link`), ενώ η `nmcli device wifi list` αποτελεί το εργαλείο υψηλότερου επιπέδου όταν η διαχείριση γίνεται μέσω του NetworkManager.

### 1.3 Αλλαγή διεύθυνσης IP

Η διεύθυνση IP μιας διεπαφής μπορεί να οριστεί χειροκίνητα με μία εντολή: αναγράφοντας `ifconfig`, τη διεπαφή και την επιθυμητή διεύθυνση. Στο παρακάτω παράδειγμα, η διεπαφή Ethernet λαμβάνει τη διεύθυνση 192.168.1.13.

```bash
root@kali:~# ifconfig eth0 192.168.1.13
root@kali:~# ifconfig eth0
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.13  netmask 255.255.255.0  broadcast 192.168.1.255
        ether 00:0c:29:1b:2c:3d  txqueuelen 1000  (Ethernet)
        RX packets 10430  bytes 9012611 (8.5 MiB)
        TX packets 5121  bytes 774311 (756.1 KiB)
root@kali:~# ip -br addr show eth0
eth0             UP             192.168.1.13/24 fe80::20c:29ff:fe1b:2c3d/64
```

Η διεύθυνση άλλαξε άμεσα, όπως επιβεβαιώνει η δεύτερη εντολή: `inet 192.168.1.13` αντί για 192.168.1.17. Αυτό συμβαίνει επειδή ο πυρήνας διαχειρίζεται τη διεύθυνση ως τοπική κατάσταση χωρίς να απαιτείται διαπραγμάτευση με εξωτερικές υπηρεσίες, εκμίσθωση DHCP ή ειδοποίηση του δρομολογητή.

Ωστόσο, αυτή η αλλαγή είναι αυστηρά **προσωρινή**. Τίποτα δεν εγγράφηκε σε αρχείο ρυθμίσεων, επομένως μια επανεκκίνηση του συστήματος ή της υπηρεσίας δικτύου επαναφέρει τη διεπαφή στις προηγούμενες τιμές της. Εάν το σύστημα διαχειρίζεται από το NetworkManager ή το systemd-networkd, οι υπηρεσίες αυτές ενδέχεται να αναιρέσουν την αλλαγή άμεσα. Επιπλέον, η χειροκίνητη ανάθεση δεν ενημερώνει αυτόματα τον πίνακα δρομολόγησης, με αποτέλεσμα η προεπιλεγμένη διαδρομή να διατηρείται με διεύθυνση προέλευσης που δεν ισχύει πλέον, διακόπτοντας τη συνδεσιμότητα. Η ενδεδειγμένη μέθοδος για μόνιμη ρύθμιση περιλαμβάνει την επεξεργασία των επίσημων αρχείων παραμετροποίησης (αρχεία YAML του Netplan στο Ubuntu, προφίλ στο `/etc/NetworkManager/system-connections/`, ή `/etc/network/interfaces` στο Debian) και την επαναφόρτωση της υπηρεσίας.

Εάν εργάζεστε μέσω SSH, η αλλαγή της διεύθυνσης διακόπτει άμεσα την ενεργή συνεδρία σας. Για ασφάλεια, συνιστάται η εργασία από τοπική κονσόλα, η προσθήκη της νέας διεύθυνσης παράλληλα με την παλιά μέσω της σύγχρονης εντολής `ip addr add 192.168.1.13/24 dev eth0`, ή ο προγραμματισμός επαναφοράς μέσω της εντολής `at`.

### 1.4 Πλαστογράφηση διεύθυνσης MAC

Η διεύθυνση MAC δεν αποτελεί απλώς ένα αναγνωριστικό, αλλά σε πολλά δίκτυα λειτουργεί ως μηχανισμός ελέγχου πρόσβασης. Ασύρματα δίκτυα με φιλτράρισμα MAC, πύλες ταυτοποίησης (captive portals), διακομιστές DHCP με στατικές αποδόσεις και συστήματα ελέγχου πρόσβασης δικτύου (NAC) λαμβάνουν αποφάσεις βάσει της διεύθυνσης υλικού. Επειδή η τιμή αυτή διαβάζεται από τις κεφαλίδες των πλαισίων και δεν προέρχεται απευθείας από κάποιον μη τροποποιήσιμο καταχωρητή υλικού κατά τη λήψη, μια σύγχρονη κάρτα δικτύου επιτρέπει στο λειτουργικό σύστημα να παρουσιάσει οποιαδήποτε τιμή επιθυμεί ο διαχειριστής, καθιστώντας την πλαστογράφηση (spoofing) απλή υπόθεση.

Η διαδικασία απαιτεί τρία βήματα, καθώς οι περισσότεροι οδηγοί δεν δέχονται νέα διεύθυνση υλικού όσο η διεπαφή μεταφέρει δεδομένα: απενεργοποίηση της διεπαφής (`down`), ορισμός της νέας διεύθυνσης και εκ νέου ενεργοποίηση (`up`).

```bash
root@kali:~# ifconfig eth0 down
root@kali:~# ifconfig eth0 hw ether 00:11:22:33:44:55
root@kali:~# ifconfig eth0 up
root@kali:~# ifconfig eth0
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.17  netmask 255.255.255.0  broadcast 192.168.1.255
        ether 00:11:22:33:44:55  txqueuelen 1000  (Ethernet)
        RX packets 2  bytes 168 (168.0 B)
        TX packets 3  bytes 252 (252.0 B)
```

Η παράμετρος `hw ether` καθορίζει διεύθυνση υλικού τύπου Ethernet, ακολουθούμενη από τη νέα τιμή. Η επαλήθευση εμφανίζει πλέον την τιμή `ether 00:11:22:33:44:55`. Παρατηρήστε ότι οι μετρητές `RX` και `TX` μηδενίστηκαν, καθώς η απενεργοποίηση της διεπαφής εκκαθαρίζει τα στατιστικά της.

Το σύγχρονο αντίστοιχο είναι η εντολή `ip link set dev eth0 address 00:11:22:33:44:55`, πλαισιωμένη από τις `ip link set eth0 down` και `up`. Πρέπει να επισημανθεί ότι δεν γίνονται δεκτές όλες οι διευθύνσεις: διευθύνσεις πολυδιανομής (multicast) ή τιμές με ακατάλληλα δυαδικά ψηφία απορρίπτονται με σφάλμα εκχώρησης διεύθυνσης. Επιλέγετε πάντα μονοδιανεμητικές διευθύνσεις (unicast) και, ιδανικά, τιμές που φέρουν έγκυρο πρόθεμα κατασκευαστή (OUI).

Η αλλαγή της MAC δεν προσφέρει απόλυτη ανωνυμία. Σε μεταγωγικά δίκτυα (switched networks), ο μεταγωγέας καταγράφει σε ποια θύρα εμφανίζεται κάθε διεύθυνση, επομένως η χρήση διεύθυνσης που ανήκει σε άλλη ενεργή συσκευή προκαλεί αστάθεια θύρας (port flapping), η οποία καταγράφεται και μπλοκάρεται από μηχανισμούς ασφαλείας όπως το Port Security και το DHCP Snooping. Σε έναν έλεγχο ασφάλειας, το ουσιαστικό εύρημα δεν είναι ότι πλαστογραφήθηκε μια MAC, αλλά ότι το δίκτυο χρησιμοποιεί ένα εύκολα τροποποιήσιμο αναγνωριστικό ως παράγοντα ταυτοποίησης.

### 1.5 Λήψη νέας διεύθυνσης από DHCP με την `dhclient`

Η χειροκίνητη διευθυνσιοδότηση εξυπηρετεί σε απομονωμένα εργαστήρια, αλλά τα περισσότερα συστήματα ζητούν αυτόματα διεύθυνση από τον τοπικό διακομιστή DHCP κάθε φορά που συνδέονται. Το πρωτόκολλο DHCP παρέχει διευθύνσεις, μάσκες υποδικτύου, πύλες και διακομιστές DNS από μια ελεγχόμενη δεξαμενή. Στο Linux, η διαδικασία εκτελείται συνήθως από τον δαίμονα `dhclient`.

```bash
root@kali:~# dhclient eth0
root@kali:~# ifconfig eth0
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.17  netmask 255.255.255.0  broadcast 192.168.1.255
        ether 00:11:22:33:44:55  txqueuelen 1000  (Ethernet)
        RX packets 421  bytes 38112 (37.2 KiB)
        TX packets 388  bytes 74520 (72.8 KiB)
```

Η εκτέλεση της `dhclient` με το όνομα της διεπαφής εκκινεί τη διαδικασία αίτησης, και η διεύθυνση επιστρέφει στην τιμή `192.168.1.17`, την οποία είχε εκχωρήσει ο διακομιστής πριν από τη χειροκίνητη παρέμβαση, επαναφέροντας το σύστημα σε διαχειριζόμενη κατάσταση.

Οι πλήρεις λεπτομέρειες της επικοινωνίας καταγράφονται στο αρχείο εκμίσθωσης (lease file), το οποίο αποτυπώνει όσα προσέφερε ο διακομιστής και τον χρόνο λήξης τους:

```bash
root@kali:~# grep -A3 "lease" /var/lib/dhcp/dhclient.eth0.leases | head -20
lease {
  interface "eth0";
  fixed-address 192.168.1.17;
  option subnet-mask 255.255.255.0;
  option routers 192.168.1.1;
  option domain-name-servers 192.168.1.1;
  option dhcp-lease-time 3600;
  option dhcp-message-type 5;
  renew 4 2026/10/09 13:20:11;
  rebind 4 2026/10/09 13:50:11;
  expire 4 2026/10/09 14:05:11;
}
```

Αυτή η καταγραφή περιλαμβάνει τη διεύθυνση, τη μάσκα, την πύλη (`option routers`), τους διακομιστές DNS, τη διάρκεια εκμίσθωσης σε δευτερόλεπτα, καθώς και τις ακριβείς χρονικές στιγμές ανανέωσης (renew), επανασύνδεσης (rebind) και λήξης (expire). Επειδή η εκμίσθωση δεν είναι μόνιμη, ένας υπολογιστής που παρέμεινε εκτός λειτουργίας για καιρό μπορεί να λάβει διαφορετική διεύθυνση, ενώ η διαδικασία ανανέωσης στο μέσο του χρόνου εκμίσθωσης εξηγεί γιατί ορισμένες διευθύνσεις αλλάζουν απρόσμενα όταν ο διακομιστής τις έχει ήδη αποδώσει αλλού.

Δύο σχετικές εντολές ολοκληρώνουν τη διαχείριση: η `dhclient -r eth0` απελευθερώνει ρητά την εκμίσθωση ενημερώνοντας τον διακομιστή ότι η διεύθυνση είναι πλέον διαθέσιμη, ενώ η `dhclient -v eth0` εκτελείται με αναλυτική καταγραφή εμφανίζοντας τα τέσσερα βήματα της χειραψίας (DISCOVER, OFFER, REQUEST, ACK). Σε σύγχρονα περιβάλλοντα γραφείου αυτά ελέγχονται από το NetworkManager ή το systemd-networkd, όπου η άμεση επίκληση της `dhclient` μπορεί να προκαλέσει συγκρούσεις μεταξύ των υπηρεσιών.

### 1.6 Εξέταση DNS με την `dig`

Το DNS μεταφράζει ονόματα τομέα (όπως το `example.com`) σε διευθύνσεις IP, ενώ παράλληλα δημοσιεύει τους διακομιστές αλληλογραφίας ενός οργανισμού, τους έγκυρους διακομιστές ονομάτων και τα σημεία απόληξης κρίσιμων υπηρεσιών. Για τη συλλογή πληροφοριών ασφάλειας, το DNS συνιστά ανεξάντλητη πηγή δεδομένων, και η εντολή `dig` (Domain Information Groper) αποτελεί το κατεξοχήν εργαλείο εξέτασής του.

Εκτελούμενη με ένα απλό όρισμα, η `dig` αναζητά εγγραφές τύπου A (διεύθυνση IPv4) και εμφανίζει την πλήρη απάντηση, συμπεριλαμβανομένων των τεχνικών μεταδεδομένων:

```bash
root@kali:~# dig example.com

; <<>> DiG 9.18.24-1-Debian <<>> example.com
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41233
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 1232
;; QUESTION SECTION:
;example.com.			IN	A

;; ANSWER SECTION:
example.com.		3600	IN	A	93.184.216.34

;; Query time: 24 msec
;; SERVER: 192.168.1.1#53(192.168.1.1) (UDP)
;; WHEN: Fri Oct 09 12:34:56 UTC 2026
;; MSG SIZE  rcvd: 56
```

Αναλύοντας την έξοδο: η γραμμή `HEADER` καταγράφει τον τύπο λειτουργίας (`opcode: QUERY`), τον κωδικό αποτελέσματος (`status: NOERROR`, όπου NXDOMAIN σημαίνει ανύπαρκτο όνομα και SERVFAIL αποτυχία του επιλυτή) και τις σημαίες πρωτοκόλλου. Η ενότητα `QUESTION SECTION` επαναλαμβάνει το ερώτημα, ενώ η ενότητα `ANSWER SECTION` παρέχει την απάντηση: το όνομα, τον χρόνο ζωής TTL σε δευτερόλεπτα (3600), την κλάση διαδικτύου (`IN`), τον τύπο εγγραφής (`A`) και τη διεύθυνση (`93.184.216.34`).

Οι τελευταίες τέσσερις γραμμές είναι εξαιρετικά διαφωτιστικές. Το πεδίο `Query time: 24 msec` δείχνει τη διάρκεια της αναδρομικής επίλυσης. Το πεδίο `SERVER: 192.168.1.1#53` προσδιορίζει ποιος επιλυτής απάντησε στο σύστημά σας — εδώ η τοπική πύλη — επιβεβαιώνοντας ποιος διακομιστής διαχειρίζεται τα ερωτήματά σας. Τέλος, καταγράφονται η χρονοσήμανση και το μέγεθος του ληφθέντος μηνύματος σε bytes.

Διαφορετικοί τύποι εγγραφών απαντούν σε διαφορετικά ερωτήματα. Ο τύπος `mx` καταγράφει τους διακομιστές ανταλλαγής αλληλογραφίας (mail exchangers), προσδιορίζοντας την υποδομή ηλεκτρονικού ταχυδρομείου ενός οργανισμού:

```bash
root@kali:~# dig example.com mx +noall +answer
example.com.		3600	IN	MX	0 .
```

Αυτή η απάντηση αποτελεί εγγραφή **null MX**: η τιμή `0 .` (προτεραιότητα μηδέν με προορισμό τη ρίζα) αποτελεί επίσημο τρόπο δήλωσης ότι ο συγκεκριμένος τομέας δεν δέχεται καθόλου αλληλογραφία. Ένας τομέας που υποστηρίζει ενεργά ηλεκτρονικό ταχυδρομείο επιστρέφει ονόματα συστημάτων συνοδευόμενα από αριθμούς προτίμησης, όπως φαίνεται στο παρακάτω παράδειγμα από δοκιμαστική ζώνη `.example`:

```bash
root@kali:~# dig intranet.example mx +noall +answer
intranet.example.	300	IN	MX	10 mail1.intranet.example.
intranet.example.	300	IN	MX	20 mail2.intranet.example.
```

Εδώ εμφανίζονται δύο διακομιστές, με τον `mail1` να προτιμάται έναντι του `mail2` καθώς ο χαμηλότερος αριθμός έχει προτεραιότητα, παρέχοντας εξισορρόπηση φορτίου και εφεδρεία. Και τα δύο συστήματα αποτελούν σημεία εισόδου δεδομένων από το διαδίκτυο και χρήζουν περαιτέρω διερεύνησης σε έναν έλεγχο ασφάλειας.

Ο τύπος `ns` εμφανίζει τους έγκυρους διακομιστές ονομάτων (authoritative name servers) που κατέχουν τα αυθεντικά αντίγραφα της ζώνης:

```bash
root@kali:~# dig example.com ns +noall +answer
example.com.		172800	IN	NS	a.iana-servers.net.
example.com.		172800	IN	NS	b.iana-servers.net.
```

Σε έναν έλεγχο παρείσδυσης, αυτοί είναι οι διακομιστές στους οποίους θα επιχειρούσατε αίτημα μεταφοράς ζώνης (`dig @a.iana-servers.net example.com AXFR`), ώστε να εξακριβωθεί αν επιτρέπουν την άντληση ολόκληρου του περιεχομένου του τομέα (υποτομείς, εσωτερικές διευθύνσεις και διακομιστές). Τα σύγχρονα συστήματα το απαγορεύουν, αλλά οι περιπτώσεις κακής παραμετροποίησης προσφέρουν πλήρη χαρτογράφηση της υποδομής.

Χρήσιμες παράμετροι περιλαμβάνουν την `+short` που εκτυπώνει μόνο το τελικό αποτέλεσμα (ιδανική για σενάρια Bash), την `+noall +answer` που παραλείπει τις κεφαλίδες, την `@1.1.1.1` που κατευθύνει το ερώτημα σε συγκεκριμένο επιλυτή για σύγκριση αποτελεσμάτων, την `-x` για αντίστροφη επίλυση διεύθυνσης σε όνομα (`dig -x 93.184.216.34`), και την `+trace` που παρακολουθεί τη διαδικασία επίλυσης βήμα προς βήμα από τους ριζικούς διακομιστές.

### 1.7 Αλλαγή του διακομιστή DNS

Ο προεπιλεγμένος επιλυτής που χρησιμοποιεί το σύστημά σας καθορίζεται στο αρχείο απλού κειμένου `/etc/resolv.conf`:

```bash
root@kali:~# cat /etc/resolv.conf
# Generated by NetworkManager
search lab.local
nameserver 192.168.1.1
```

Σε ένα τυπικό αρχείο εμφανίζονται δύο οδηγίες. Η γραμμή `nameserver` ορίζει τη διεύθυνση του επιλυτή στον οποίο αποστέλλονται τα ερωτήματα, ενώ η γραμμή `search` απαριθμεί τομείς που προσαρτώνται αυτόματα σε απλά ονόματα, επιτρέποντας την εκτέλεση εντολών όπως `ping fileserver` σε εταιρικά δίκτυα χωρίς πλήρες όνομα τομέα. Ένα αρχείο μπορεί να περιλαμβάνει έως τρεις γραμμές `nameserver`, οι οποίες εξετάζονται διαδοχικά: εάν ο πρώτος διακομιστής δεν ανταποκριθεί έγκαιρα, το σύστημα στρέφεται στον επόμενο.

Η αλλαγή του επιλυτή πραγματοποιείται με εγγραφή νέας γραμμής στο αρχείο, με τον ταχύτερο τρόπο να είναι η χρήση της `echo` και του τελεστή ανακατεύθυνσης `>`, ο οποίος αντικαθιστά πλήρως τα περιεχόμενα:

```bash
root@kali:~# echo "nameserver 1.1.1.1" > /etc/resolv.conf
root@kali:~# cat /etc/resolv.conf
nameserver 1.1.1.1
root@kali:~# dig example.com +short @1.1.1.1
93.184.216.34
root@kali:~# dig example.com | grep "SERVER:"
;; SERVER: 1.1.1.1#53(1.1.1.1) (UDP)
```

Ο τελεστής `>` είναι καταστροφικός καθώς διαγράφει τα προηγούμενα δεδομένα χωρίς δυνατότητα αναίρεσης, γι' αυτό και προηγήθηκε η ανάγνωση του αρχείου. Μετά την εγγραφή, το αρχείο περιέχει τον δημόσιο επιλυτή της Cloudflare (1.1.1.1). Η δεύτερη κλήση της `dig` επιβεβαιώνει την αλλαγή στην πράξη: η ένδειξη `SERVER:` αναφέρει πλέον `1.1.1.1#53`, αποδεικνύοντας ότι τα ερωτήματα εξέρχονται όντως μέσω του νέου επιλυτή.

Υπάρχει μια ουσιώδης ιδιαιτερότητα: στα περισσότερα σύγχρονα συστήματα το `/etc/resolv.conf` παράγεται αυτόματα από υπηρεσίες όπως το NetworkManager, η `dhclient` ή το `systemd-resolved`, και συχνά αποτελεί συμβολικό σύνδεσμο. Συνεπώς, οποιαδήποτε χειροκίνητη αλλαγή θα αντικατασταθεί στην επόμενη ανανέωση εκμίσθωσης DHCP ή επανεκκίνηση. Η μόνιμη ρύθμιση επιτυγχάνεται μέσω του διαχειριστή δικτύου (π.χ. `nmcli con mod <όνομα> ipv4.dns 1.1.1.1` ή ρύθμιση στο `/etc/systemd/resolved.conf`). Σε απομονωμένα εργαστήρια, ορισμένοι διαχειριστές καθιστούν το αρχείο μη τροποποιήσιμο με την εντολή `chattr +i /etc/resolv.conf`, πρακτική που ωστόσο μπορεί να προκαλέσει σφάλματα σε μελλοντικές αυτόματες ρυθμίσεις δικτύου.

Στις δοκιμές ασφάλειας, ο επιλυτής έχει σημασία διότι καταγράφει κάθε όνομα που αναζητάτε, επιτρέποντας σε έναν κακόβουλο διακομιστή σε μη αξιόπιστο δίκτυο να παρακολουθεί τη δραστηριότητά σας ή να απαντά με παραποιημένες διευθύνσεις. Επιπλέον, η χρήση επιλυτών που υποστηρίζουν DNSSEC ή εφαρμόζουν φιλτράρισμα επηρεάζει τις προσβάσιμες διευθύνσεις, καθιστώντας απαραίτητο τον έλεγχο των μηχανισμών επίλυσης και της τυχόν χρήσης κρυπτογραφημένου DNS (DoH ή DoT).

### 1.8 Αντιστοίχιση ονομάτων συστημάτων στο `/etc/hosts`

Πριν αποσταλεί οποιοδήποτε ερώτημα DNS, το λειτουργικό σύστημα συμβουλεύεται ένα τοπικό αρχείο. Το `/etc/hosts` αποτελεί έναν στατικό πίνακα αντιστοίχισης ονομάτων σε διευθύνσεις IP. Εξετάζεται πάντα πρώτο βάσει της σειράς που ορίζεται στο αρχείο `/etc/nsswitch.conf`, όπου η καταχώριση `hosts: files dns` υποδεικνύει ρητά έλεγχο των τοπικών αρχείων πριν από την αποστολή ερωτήματος στο DNS.

```bash
root@kali:~# cat /etc/hosts
127.0.0.1	localhost
127.0.1.1	kali
::1		localhost ip6-localhost ip6-loopback

# The following lines are desirable for IPv6 capable hosts
ff02::1		ip6-allnodes
ff02::2		ip6-allrouters
root@kali:~# nano /etc/hosts
root@kali:~# cat /etc/hosts
127.0.0.1	localhost
127.0.1.1	kali
::1		localhost ip6-localhost ip6-loopback

# The following lines are desirable for IPv6 capable hosts
ff02::1		ip6-allnodes
ff02::2		ip6-allrouters
192.168.1.9	portal.example.com
```

Η μορφή του αρχείου είναι απλή: η διεύθυνση IP τοποθετείται στην πρώτη στήλη, ακολουθούμενη από ένα ή περισσότερα ονόματα διαχωρισμένα με κενό, ενώ ο χαρακτήρας `#` εισάγει σχόλια. Οι προεπιλεγμένες εγγραφές αντιστοιχίζουν το `localhost` στην τοπική αναδρομή και αποδίδουν το όνομα του συστήματος (`kali`) στη διεύθυνση `127.0.1.1`, σύμβαση των διανομών Debian που διασφαλίζει ότι το όνομα του συστήματος επιλύεται ακόμη και χωρίς ενεργό δίκτυο.

Προσθέτοντας μια νέα γραμμή, αντιστοιχίζετε οποιοδήποτε όνομα σε οποιαδήποτε διεύθυνση, και επειδή το αρχείο υπερισχύει του DNS, η επίδραση είναι άμεση και καθολική για το σύστημα:

```bash
root@kali:~# getent hosts portal.example.com
192.168.1.9     portal.example.com
root@kali:~# curl -s -o /dev/null -w "%{http_code} %{remote_ip}\n" http://portal.example.com/
200 192.168.1.9
root@kali:~# dig +short portal.example.com
93.184.216.34
```

Αυτές οι τρεις εντολές αποδεικνύουν τη λειτουργία της παράκαμψης. Η `getent hosts` συμβουλεύεται τον μηχανισμό επίλυσης του λειτουργικού συστήματος (όπως ακριβώς κάνουν οι εφαρμογές) και επιστρέφει την εγγραφή από το αρχείο hosts. Η `curl` συνδέεται στη διεύθυνση `192.168.1.9` χρησιμοποιώντας το όνομα `portal.example.com`. Αντίθετα, η `dig` παρακάμπτει πλήρως το `/etc/hosts`, επειδή επικοινωνεί απευθείας με τους διακομιστές DNS, επιστρέφοντας την πραγματική δημόσια διεύθυνση (93.184.216.34). Αυτή η διαφοροποίηση εξηγεί γιατί ένα όνομα μπορεί να λειτουργεί κανονικά σε έναν περιηγητή ιστού αλλά να αποτυγχάνει σε ένα σενάριο που χρησιμοποιεί τη `dig`.

Οι θεμιτές χρήσεις περιλαμβάνουν την απόδοση φιλικών ονομάτων σε εργαστηριακά μηχανήματα πριν στηθεί υπηρεσία DNS, τον έλεγχο νέων ιστοσελίδων πριν ενημερωθούν οι δημόσιες εγγραφές, ή τον αποκλεισμό ανεπιθύμητων τομέων κατευθύνοντάς τους στο `127.0.0.1`. Η κακόβουλη χρήση συνίσταται στην εκμετάλλευση αυτού του μηχανισμού: εάν ένας επιτιθέμενος αποκτήσει δικαίωμα εγγραφής στο αρχείο (ή εκτελέσει πλαστογράφηση ARP/DNS), μπορεί να κατευθύνει τον χρήστη σε παραποιημένο διακομιστή υποκλοπής διαπιστευτηρίων. Η αμυντική αντιμετώπιση επιβάλλει παρακολούθηση της ακεραιότητας των `/etc/hosts` και `/etc/resolv.conf`, χρήση DNSSEC και DoH, καθώς και άμεση διερεύνηση οποιασδήποτε ανακατεύθυνσης σε μη αναμενόμενες διευθύνσεις.

## 2. Διαχείριση διεργασιών

Μια διεργασία (process) είναι ένα πρόγραμμα σε κατάσταση εκτέλεσης: ο πυρήνας το έχει φορτώσει στη μνήμη, του έχει εκχωρήσει ένα μοναδικό αναγνωριστικό, το έχει εντάξει στον χρονοπρογραμματιστή του επεξεργαστή και καταγράφει τους πόρους που καταναλώνει. Σε έναν προσωπικό υπολογιστή εκτελούνται εκατοντάδες διεργασίες ανά πάσα στιγμή, οι περισσότερες εκ των οποίων είναι δαίμονες (υπηρεσίες παρασκηνίου χωρίς συνδεδεμένο τερματικό), ενώ σε έναν διακομιστή ο αριθμός είναι ακόμη μεγαλύτερος. Η ικανότητα καταγραφής τους, αξιολόγησης των πόρων τους, ρύθμισης προτεραιότητας και τερματισμού προβληματικών εκτελέσεων διαφοροποιεί τον έμπειρο διαχειριστή από τον απλό χρήστη. Στις δοκιμές ασφάλειας, οι ίδιες εντολές αποκαλύπτουν ποια διεργασία ακούει σε μια ανοιχτή θύρα, εντοπίζουν ύποπτους δαίμονες και επιτρέπουν την αναστολή λογισμικού προστασίας κατά τη διάρκεια εξουσιοδοτημένων ελέγχων.

### 2.1 `ps` — Προβολή των δικών σας διεργασιών

Το βασικό εργαλείο επισκόπησης διεργασιών είναι η εντολή `ps` (process status). Χωρίς ορίσματα, καταγράφει μόνο τις διεργασίες που ανήκουν στον τρέχοντα χρήστη και είναι συνδεδεμένες με το συγκεκριμένο τερματικό.

```bash
root@kali:~# ps
    PID TTY          TIME CMD
   4122 pts/0    00:00:00 bash
   4188 pts/0    00:00:00 ps
```

Εμφανίζονται μόλις δύο διεργασίες: το κέλυφος της τρέχουσας συνεδρίας και η ίδια η εντολή `ps`. Το `PID` είναι το αριθμητικό αναγνωριστικό διεργασίας που εκχωρεί ο πυρήνας και αποτελεί τη λαβή μέσω της οποίας επιθεωρείτε ή τερματίζετε μια διεργασία. Το `TTY` υποδεικνύει το τερματικό στο οποίο είναι προσαρτημένη η διεργασία (`pts/0` είναι το πρώτο ψευδο-τερματικό), ενώ ένα ερωτηματικό `?` υποδηλώνει διεργασία χωρίς τερματικό (χαρακτηριστικό των δαιμόνων). Το πεδίο `TIME` εκφράζει τον συνολικό χρόνο επεξεργαστή που έχει καταναλώσει η διεργασία από την εκκίνησή της και όχι τον πραγματικό χρόνο που υπάρχει στο σύστημα.

Δύο χρήσιμες παραλλαγές είναι η `ps -f`, η οποία προσθέτει το αναγνωριστικό της γονικής διεργασίας (PPID) και ολόκληρη τη γραμμή εντολών εκκίνησης, και η `ps -ef` (σε μορφή System V), η οποία εμφανίζει κάθε διεργασία στο σύστημα με πλήρη στοιχεία.

### 2.2 `ps aux` — Κάθε διεργασία, κάθε χρήστης

Η εκτέλεση της `ps` με τις επιλογές τύπου BSD `aux` προβάλλει όλες τις διεργασίες όλων των χρηστών στο σύστημα μαζί με αναλυτικά στοιχεία κατανάλωσης πόρων.

```bash
root@kali:~# ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.6 168412 12984 ?        Ss   09:41   0:04 /sbin/init splash
root           2  0.0  0.0      0     0 ?        S    09:41   0:00 [kthreadd]
root         812  0.0  0.1  15420  9216 ?        Ss   09:41   0:00 sshd: /usr/sbin/sshd -D [listener] 0 of 10-100 startups
root        1044  0.0  0.4 240128 34220 ?        Ssl  09:41   0:01 /usr/lib/snapd/snapd
www-data    1204  0.1  1.1 3310420 88144 ?       Ssl  09:44   0:06 python3 /opt/portal/app.py
student     3901  0.0  0.1  10344  5120 pts/0    Ss   10:12   0:00 -bash
student     4122  0.0  0.0  12440  4096 pts/0    R+   10:31   0:00 ps aux
```

Κάθε στήλη απαντά σε συγκεκριμένο ερώτημα. Το `USER` δηλώνει τον λογαριασμό υπό τον οποίο εκτελείται η διεργασία, στοιχείο που καθορίζει τα δικαιώματά σας επ' αυτής: μπορείτε να στείλετε σήματα μόνο στις δικές σας διεργασίες, ενώ για οποιουδήποτε άλλου απαιτούνται προνόμια root. Τα `%CPU` και `%MEM` καταγράφουν τα ποσοστά χρήσης επεξεργαστή και μνήμης. Τα πεδία `VSZ` και `RSS` εκφράζουν τη μνήμη σε kilobytes: το `VSZ` είναι το εικονικό μέγεθος του χώρου διευθύνσεων που έχει δεσμεύσει η διεργασία, ενώ το `RSS` (Resident Set Size) είναι η πραγματική φυσική μνήμη RAM που καταλαμβάνει αυτή τη στιγμή, αποτελώντας την πιο αξιόπιστη ένδειξη κατανάλωσης. Η στήλη `STAT` περιέχει κωδικούς που περιγράφουν την κατάσταση της διεργασίας.

Οι κωδικοί κατάστασης `STAT` αποκαλύπτουν την υγεία μιας διεργασίας: το `R` σημαίνει ότι εκτελείται ή είναι έτοιμη προς εκτέλεση στον επεξεργαστή, το `S` σημαίνει διακοπτόμενη αναστολή (interruptible sleep — κατάσταση αναμονής για είσοδο ή πακέτο, στην οποία βρίσκεται η πλειονότητα των διεργασιών), και το `D` δηλώνει αδιάκοπτη αναστολή (συνήθως αναμονή εγγραφής/ανάγνωσης στον δίσκο, κατά την οποία η διεργασία δεν μπορεί να τερματιστεί ούτε με `SIGKILL`). Το `T` υποδηλώνει διεργασία σε παύση (όπως μετά από πάτημα `Ctrl+Z`), ενώ το `Z` αντιστοιχεί σε διεργασία-ζόμπι (zombie): η διεργασία ολοκληρώθηκε αλλά η γονική της δεν έχει αναγνώσει ακόμη την κατάσταση εξόδου της, παραμένοντας ως ανενεργή εγγραφή στον πίνακα χωρίς κατανάλωση πόρων.

Το πεδίο `START` δηλώνει την ώρα εκκίνησης, το `TIME` τον χρόνο επεξεργαστή και το `COMMAND` τη γραμμή εντολής, όπου ονόματα μέσα σε αγκύλες (όπως `[kthreadd]`) υποδηλώνουν νήματα του ίδιου του πυρήνα. Χρήσιμες παραλλαγές περιλαμβάνουν την `ps aux --sort=-%mem | head` για ταξινόμηση κατά χρήση μνήμης, την `ps -eo pid,ppid,user,%cpu,cmd --sort=-%cpu | head` για προσαρμοσμένες στήλες και ταξινόμηση κατά χρήση επεξεργαστή, καθώς και την `ps -ef --forest` που σχεδιάζει ιεραρχικά το δέντρο διεργασιών, αποκαλύπτοντας ποιες θυγατρικές διεργασίες δημιούργησε κάθε κύριος δαίμονας.

### 2.3 Φιλτράρισμα διεργασιών κατά όνομα

Σε συστήματα με εκατοντάδες διεργασίες, η έξοδος της `ps aux` φιλτράρεται μέσω διοχέτευσης στην `grep`, απομονώνοντας τις γραμμές που αναφέρονται στο επιθυμητό πρόγραμμα, όπως για παράδειγμα στην κονσόλα `msfconsole`:

```bash
root@kali:~# ps aux | grep msfconsole
root        5210  1.3  2.4 612344 198772 pts/1   Sl+  10:33   0:02 ruby /usr/bin/msfconsole -q
root        5233  0.0  0.0  12440  4096 pts/1    S+   10:33   0:00 grep msfconsole
```

Επιστρέφονται δύο γραμμές. Η πρώτη είναι η πραγματική διεργασία που εκτελεί το σενάριο μέσω του διερμηνέα Ruby. Η δεύτερη γραμμή είναι η ίδια η εντολή `grep`, η οποία αντιστοιχίστηκε επειδή περιείχε τη λέξη αναζήτησης στη γραμμή εντολών της. Για να εξαιρεθεί η ίδια η `grep`, μπορείτε να προσθέσετε `| grep -v grep` ή να περικλείσετε έναν χαρακτήρα σε αγκύλες (`ps aux | grep "[m]sfconsole"`), καθώς η έκφραση με αγκύλες ταιριάζει με το όνομα αλλά δεν εμφανίζεται αυτούσια στη γραμμή της `grep`.

Το ενδεδειγμένο εργαλείο για αυτή τη λειτουργία είναι η `pgrep`, η οποία σχεδιάστηκε ειδικά για αναζήτηση διεργασιών, δεν εμφανίζει τον εαυτό της και επιστρέφει απευθείας τα αναγνωριστικά PID:

```bash
root@kali:~# pgrep -a msfconsole
5210 ruby /usr/bin/msfconsole -q
root@kali:~# pgrep -u student -l bash
3901 bash
root@kali:~# pgrep -f "app.py"
1204
```

Η παράμετρος `-a` εκτυπώνει ολόκληρη τη γραμμή εντολών δίπλα στο PID, η `-u` φιλτράρει βάσει χρήστη, η `-l` εκτυπώνει μόνο το όνομα, και η `-f` συγκρίνει το μοτίβο με ολόκληρη τη γραμμή εντολών και όχι μόνο με το όνομα του εκτελέσιμου (απαραίτητο για διεργασίες που εκκινούνται ως `python3 /opt/portal/app.py`). Η συνδεδεμένη εντολή `pkill` αποστέλλει σήματα σε όλες τις διεργασίες που ταιριάζουν με το κριτήριο αναζήτησης.

### 2.4 `top` — Εντοπισμός των πιο απαιτητικών διεργασιών

Εκεί όπου η `ps` προσφέρει ένα στιγμιότυπο, η εντολή `top` παρέχει δυναμική παρακολούθηση. Προβάλλει τις διεργασίες ταξινομημένες κατά κατανάλωση πόρων και ανανεώνει την οθόνη ανά τακτά δευτερόλεπτα, επιτρέποντας την άμεση παρατήρηση του φόρτου του συστήματος, της χρήσης του επεξεργαστή και της διαθέσιμης μνήμης.

```bash
root@kali:~# top
top - 10:36:22 up 55 min,  1 user,  load average: 0.42, 0.31, 0.24
Tasks: 214 total,   1 running, 213 sleeping,   0 stopped,   0 zombie
%Cpu(s):  3.9 us,  1.0 sy,  0.0 ni, 94.8 id,  0.3 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :   3914.8 total,   2412.6 free,    681.0 used,    821.2 buff/cache
MiB Swap:   2048.0 total,   2047.7 free,      0.3 used.   2893.0 avail Mem 

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
   1204 www-data  20   0 3310420  88144  21412 S   4.3   2.2   0:06.42 python3
   1044 root      20   0  240128  34220  19840 S   0.7   0.9   0:01.19 snapd
   5210 root      20   0  612344 198772  42188 S   0.3   5.0   0:02.11 ruby
      1 root      20   0  168412  12984   9216 S   0.0   0.6   0:04.33 systemd
```

Οι πέντε γραμμές της κεφαλίδας συνοψίζουν τη συνολική κατάσταση του μηχανήματος. Η πρώτη γραμμή αναφέρει την ώρα, τον χρόνο συνεχούς λειτουργίας (uptime), τους συνδεδεμένους χρήστες και τον **μέσο φόρτο** (load average) για το τελευταίο ένα, πέντε και δεκαπέντε λεπτά. Τιμή φόρτου υψηλότερη από τον αριθμό των πυρήνων σημαίνει αναμονή εργασιών στην ουρά. Η δεύτερη γραμμή καταγράφει τις διεργασίες ανά κατάσταση. Η τρίτη γραμμή αναλύει τον χρόνο CPU: `us` για εφαρμογές χρήστη, `sy` για λειτουργίες πυρήνα, `id` για αδράνεια, `wa` για αναμονή εισόδου/εξόδου (υψηλό `wa` υποδηλώνει αργό δίσκο), και `st` (steal) για χρόνο που δεσμεύτηκε από το υποκείμενο σύστημα εικονικοποίησης (hypervisor). Οι γραμμές μνήμης καταγράφουν τη συνολική, ελεύθερη και χρησιμοποιούμενη μνήμη, καθώς και την ενδιάμεση μνήμη `buff/cache`. Το Linux χρησιμοποιεί σκόπιμα την αδρανή μνήμη RAM ως λανθάνουσα μνήμη δίσκου την οποία αποδεσμεύει άμεσα όταν ζητηθεί, επομένως ένα σύστημα με χαμηλή ένδειξη `free` αλλά υψηλή `buff/cache` λειτουργεί απολύτως φυσιολογικά.

Κάτω από την κεφαλίδα ακολουθεί ο πίνακας διεργασιών, όπου διακρίνονται οι στήλες `PR` (προτεραιότητα πυρήνα) και `NI` (τιμή ευγένειας - nice), οι οποίες ρυθμίζουν την προτεραιότητα κατανομής επεξεργαστικής ισχύος.

Η `top` είναι διαδραστική: πατώντας `P` ταξινομείτε κατά χρήση CPU, με το `M` ταξινομείτε κατά χρήση μνήμης, με το `k` τερματίζετε μια διεργασία εισάγοντας το PID της, με το `r` αλλάζετε την τιμή προτεραιότητας nice, με το `1` εμφανίζετε αναλυτικά κάθε πυρήνα, με το `h` ανοίγετε τη βοήθεια και με το `q` εξέρχεστε. Για καταγραφή σε αρχεία, η εντολή `top -b -n 1 | head -20` εκτελεί μία μόνο σάρωση σε λειτουργία δέσμης (batch mode). Για πιο σύγχρονη εμπειρία με υποστήριξη ποντικιού και χρωμάτων, προτιμάται το εργαλείο `htop`.

### 2.5 `nice` — Ορισμός προτεραιότητας νέας διεργασίας

Όταν οι απαιτήσεις σε επεξεργαστική ισχύ υπερβαίνουν τη διαθεσιμότητα, ο χρονοπρογραμματιστής κατανέμει τον χρόνο CPU λαμβάνοντας υπόψη την **τιμή ευγένειας (nice value)** κάθε διεργασίας — έναν αριθμό από −20 έως 19 που δηλώνει πόσο πρόθυμη είναι μια διεργασία να παραχωρήσει τη σειρά της. Η κλίμακα λειτουργεί αντίστροφα από το αναμενόμενο: το −20 αντιστοιχεί στην ύψιστη προτεραιότητα (λιγότερο ευγενική διεργασία, μέγιστη απαίτηση), το 19 στη χαμηλότερη προτεραιότητα (απόλυτα ευγενική, υποχωρεί πάντα), ενώ η προεπιλογή είναι το 0. Μια διεργασία διατηρεί την τιμή nice με την οποία ξεκίνησε καθ' όλη τη διάρκειά της.

Η παράμετρος `-n` ορίζει την τιμή προτεραιότητας. Στο παρακάτω παράδειγμα, ο δαίμονας ssh-agent εκκινείται με τιμή −10, αποκτώντας προτεραιότητα έναντι των υπολοίπων.

```bash
root@kali:~# nice -n -10 /usr/bin/ssh-agent
SSH_AUTH_SOCK=/tmp/ssh-XXXXXXuP3n9g/agent.4412; export SSH_AUTH_SOCK;
SSH_AGENT_PID=4412; export SSH_AGENT_PID;
echo Agent pid 4412;
root@kali:~# ps -o pid,ni,cmd -C ssh-agent
    PID  NI CMD
   4412 -10 /usr/bin/ssh-agent
```

Το πρόγραμμα εκκινήθηκε κανονικά και εκχώρησε αναγνωριστικό διεργασίας. Η εντολή επαλήθευσης `ps -o pid,ni,cmd -C ssh-agent` απομονώνει τις συγκεκριμένες στήλες και επιβεβαιώνει στη στήλη `NI` την τιμή `-10`. Η επιλογή `-C` αναζητά απευθείας βάσει ονόματος εντολής, αποφεύγοντας τις παρενέργειες της `grep`.

Εδώ ισχύει ένας αυστηρός κανόνας δικαιωμάτων: οποιοσδήποτε χρήστης μπορεί να καταστήσει μια διεργασία πιο ευγενική (αυξάνοντας τον αριθμό nice ώστε να παραχωρεί προτεραιότητα), αλλά μόνο ο root επιτρέπεται να μειώσει τον αριθμό (αυξάνοντας την προτεραιότητα). Εάν ένας απλός χρήστης επιχειρήσει να θέσει αρνητική τιμή, το κέλυφος απορρίπτει την εντολή με μήνυμα άρνησης πρόσβασης (`Permission denied`), διασφαλίζοντας ότι οι διαδραστικές εργασίες δεν θα στερηθούν πόρους από μη εξουσιοδοτημένες εργασίες παρασκηνίου.

Η πιο κοινή χρήση από απλούς χρήστες είναι η ανάθεση της ελάχιστης δυνατής προτεραιότητας σε βαριές εργασίες συντήρησης, ώστε να μην επιβαρύνουν το σύστημα:

```bash
root@kali:~# nice -n 19 ./backup-script.sh &
[1] 5487
root@kali:~# nice -n 19 /usr/bin/updatedb &
[2] 5490
```

Και οι δύο εργασίες εκτελούνται με τη χαμηλότερη προτεραιότητα (19) στο παρασκήνιο, με τα σύμβολα `[1]` και `[2]` να υποδηλώνουν τους αριθμούς εργασίας του κελύφους. Αυτή η προσέγγιση αποτελεί την ενδεδειγμένη πρακτική για μακροχρόνιες διαδικασίες συντήρησης σε κοινόχρηστα μηχανήματα.

### 2.6 `renice` — Αλλαγή προτεραιότητας ενεργής διεργασίας

Η προτεραιότητα μιας διεργασίας που εκτελείται ήδη μπορεί να μεταβληθεί δυναμικά χωρίς να απαιτείται επανεκκίνησή της, μέσω της εντολής `renice`. Δέχεται μια νέα τιμή nice και ένα ή περισσότερα PIDs, λειτουργώντας σε οποιαδήποτε διεργασία εφόσον διαθέτετε τα κατάλληλα δικαιώματα.

```bash
root@kali:~# renice 20 6242
6242 (process ID) old priority 0, new priority 20
root@kali:~# ps -o pid,ni,cmd -p 6242
    PID  NI CMD
   6242  20 /usr/bin/updatedb
root@kali:~# renice -n -5 -p 6242
renice: failed to set priority for 6242 (process ID): Permission denied
```

Το ενημερωτικό μήνυμα καταγράφει τόσο την παλιά όσο και τη νέα προτεραιότητα (από 0 σε 20), υποδηλώνοντας ότι η διεργασία υποχωρεί πλέον έναντι όλων των άλλων. Η τρίτη εντολή καταδεικνύει τον περιορισμό δικαιωμάτων: ως απλός χρήστης, η απόπειρα μείωσης της τιμής nice στο −5 απορρίπτεται με σφάλμα `Permission denied`.

Χρήσιμες μορφές περιλαμβάνουν την `renice -n 10 -p 6242` για ρητό ορισμό τιμής σε σενάρια εντολών, την `renice -u student` που μεταβάλλει την προτεραιότητα όλων των διεργασιών ενός συγκεκριμένου χρήστη, και την `renice 5 -g developers` για ομάδες διεργασιών. Σε σύγχρονα περιβάλλοντα με systemd, ο έλεγχος πόρων επιτυγχάνεται πληρέστερα μέσω ομάδων ελέγχου (cgroups) με εντολές όπως `systemctl set-property`, οι οποίες θέτουν απόλυτα όρια χρήσης CPU και μνήμης σε επίπεδο υπηρεσίας.

### 2.7 `kill` — Τερματισμός διεργασιών μέσω σημάτων

Η εντολή `kill` τερματίζει διεργασίες, αν και ο ρόλος της είναι ευρύτερος: στην πραγματικότητα αποστέλλει ένα **σήμα (signal)**, μια ασύγχρονη ειδοποίηση που παραδίδει ο πυρήνας στη διεργασία, την οποία η διεργασία μπορεί να διαχειριστεί όπως επιθυμεί — να εκτελέσει εκκαθάριση, να αποθηκεύσει δεδομένα, να αγνοήσει το σήμα ή να τερματίσει. Υπάρχουν συνολικά 64 σήματα, με τα δύο σημαντικότερα να είναι το ευγενικό αίτημα τερματισμού και ο αναγκαστικός τερματισμός. Παρακάτω αποστέλλεται το σήμα 1 στη διεργασία 6242:

```bash
root@kali:~# kill -1 6242
root@kali:~# ps -p 6242
    PID TTY          TIME CMD
root@kali:~# kill -l
 1) SIGHUP	 2) SIGINT	 3) SIGQUIT	 4) SIGILL	 5) SIGTRAP
 6) SIGABRT	 7) SIGBUS	 8) SIGFPE	 9) SIGKILL	10) SIGUSR1
11) SIGSEGV	12) SIGUSR2	13) SIGPIPE	14) SIGALRM	15) SIGTERM
...
root@kali:~# kill -9 4378
```

Το σήμα 1 (`SIGHUP` - Hangup) σήμαινε αρχικά αποσύνδεση του τερματικού. Σύγχρονοι δαίμονες όπως οι `sshd`, `nginx` και `rsyslog` το ερμηνεύουν ως εντολή επαναφόρτωσης των αρχείων ρυθμίσεων και των αρχείων καταγραφής χωρίς διακοπή των ενεργών συνδέσεων. Ωστόσο, σε απλά προγράμματα που δεν διαθέτουν ειδικό χειριστή για το σήμα αυτό, η αποστολή του προκαλεί τερματισμό, όπως συνέβη με την `updatedb`.

Η εντολή `kill -l` εμφανίζει τη λίστα όλων των σημάτων. Το σήμα 15, `SIGTERM`, είναι η **προεπιλογή** όταν καλείτε την `kill` χωρίς αριθμό: ζητά ευγενικά από το πρόγραμμα να τερματίσει, επιτρέποντάς του να αποθηκεύσει δεδομένα, να διαγράψει προσωρινά αρχεία και να κλείσει ανοιχτές συνδέσεις. Αντίθετα, το σήμα 9, `SIGKILL`, δεν μπορεί να παγιδευτεί, να αγνοηθεί ή να μπλοκαριστεί από την εφαρμογή: ο πυρήνας απομακρύνει τη διεργασία άμεσα από τη μνήμη. Το `SIGKILL` αποτελεί έσχατη λύση αποκλειστικά για διεργασίες που δεν ανταποκρίνονται στο `SIGTERM`, καθώς δεν παρέχει περιθώριο εκκαθάρισης, οδηγώντας συχνά σε αλλοίωση βάσεων δεδομένων και εγκατάλειψη κλειδωμένων αρχείων. Το σήμα 2 (`SIGINT`) αποστέλλεται μέσω `Ctrl+C`, το σήμα 3 (`SIGQUIT`) μέσω `Ctrl+\`, ενώ τα σήματα 19 (`SIGSTOP`) και 18 (`SIGCONT`) παγώνουν και επανεκκινούν διεργασίες.

Η ορθή πρακτική επιβάλλει πάντα τη δοκιμή του `SIGTERM` πρώτα και κλιμάκωση σε `SIGKILL` μόνο εάν η διεργασία δεν ανταποκριθεί. Εάν μια διεργασία δεν τερματίζει με `SIGTERM`, ενδέχεται να είναι μπλοκαρισμένη σε είσοδο/έξοδο δίσκου (κατάσταση D) ή να είναι ζόμπι (κατάσταση Z). Στην περίπτωση των ζόμπι, κανένα σήμα δεν έχει αποτέλεσμα, καθώς η διεργασία έχει ήδη ολοκληρωθεί και περιμένει απλώς την ανάγνωση της κατάστασής της από τον γονέα.

Για στοχευμένο τερματισμό βάσει ονόματος χρησιμοποιούνται η `pkill` (π.χ. `pkill -f app.py` για τερματισμό βάσει γραμμής εντολών ή `pkill -u student -TERM -f backup`) και η `killall` που τερματίζει βάσει ακριβούς ονόματος προγράμματος. Επειδή ένα ευρύ μοτίβο μπορεί να επηρεάσει ακούσια άλλες εφαρμογές, συνιστάται να εκτελείτε πρώτα την `pgrep` για έλεγχο των επηρεαζόμενων PIDs πριν αποστείλετε το σήμα.

### 2.8 Εργασίες παρασκηνίου, `jobs`, `fg` και `nohup`

Μια εντολή που εκτελείται στην προτροπή δεσμεύει το τερματικό μέχρι να ολοκληρωθεί. Το κέλυφος παρέχει μηχανισμούς **ελέγχου εργασιών (job control)**: προσθέτοντας ένα εμπορικό και (`&`) στο τέλος μιας εντολής, αυτή εκτελείται στο παρασκήνιο (background), επιστρέφοντας άμεσα την προτροπή στον χρήστη.

```bash
root@kali:~# nano lab-notes.txt &
[1] 4312
root@kali:~# jobs
[1]+  Stopped                 nano lab-notes.txt
root@kali:~# fg %1
```

Το κέλυφος επιστρέφει τον αριθμό εργασίας `[1]` και το PID `4312`. Στην περίπτωση του `nano`, όντας διαδραστικό πρόγραμμα πλήρους οθόνης, τίθεται αυτόματα σε κατάσταση παύσης (`Stopped`), επειδή επιχειρεί να διαβάσει είσοδο από ένα πληκτρολόγιο που δεν ελέγχει πλέον. Η εκτέλεση στο παρασκήνιο προορίζεται για μη διαδραστικά προγράμματα (όπως μεταγλωττίσεις, σαρώσεις, λήψεις αρχείων ή αντίγραφα ασφαλείας) και όχι για επεξεργαστές κειμένου.

```bash
root@kali:~# ./backup-script.sh &
[2] 4701
root@kali:~# jobs -l
[1]+  4312 Stopped                 nano lab-notes.txt
[2]-  4701 Running                 ./backup-script.sh &
root@kali:~# bg %1
```

Σε ένα μη διαδραστικό σενάριο, η εργασία παραμένει ενεργή (`Running`). Η εντολή `jobs -l` καταγράφει όλες τις εργασίες με τα PIDs τους. Το σύμβολο `+` επισημαίνει την τρέχουσα εργασία στην οποία επιδρούν οι `fg` και `bg` εάν δεν δηλωθεί αριθμός, ενώ το σύμβολο `-` επισημαίνει την αμέσως προηγούμενη.

Το βασικό λεξιλόγιο ελέγχου εργασιών περιλαμβάνει: πάτημα `Ctrl+Z` για προσωρινή παύση της τρέχουσας εργασίας προσκηνίου, `bg %1` για συνέχιση της εργασίας 1 στο παρασκήνιο, `fg %1` για επαναφορά της στο προσκήνιο, `jobs` για εμφάνιση της λίστας, `kill %1` για αποστολή σήματος βάσει αριθμού εργασίας, και `disown %1` για αποσύνδεση της εργασίας από τον πίνακα του κελύφους ώστε να μην επηρεαστεί όταν αυτό κλείσει.

Όταν κλείνει ένα παράθυρο τερματικού, το κέλυφος αποστέλλει αυτόματα το σήμα `SIGHUP` σε όλες τις εργασίες του, διακόπτοντας όσες δεν το διαχειρίζονται. Το κλασικό εργαλείο προστασίας είναι η `nohup`, η οποία απομονώνει τη διεργασία από το σήμα αποσύνδεσης και ανακατευθύνει αυτόματα την έξοδό της:

```bash
root@kali:~# nohup ./scan.sh > scan.log 2>&1 &
[3] 4820
root@kali:~# ps -o pid,stat,cmd -p 4820
    PID STAT CMD
   4820 S    /bin/bash ./scan.sh
root@kali:~# nohup ./scan.sh &
[4] 4833
nohup: ignoring input and appending output to 'nohup.out'
```

Η ανακατεύθυνση `> scan.log 2>&1` προωθεί τόσο την τυπική έξοδο όσο και τα σφάλματα σε αρχείο. Εάν παραλειφθεί, η `nohup` αποθηκεύει αυτόματα τα δεδομένα στο αρχείο `nohup.out` στον τρέχοντα κατάλογο. Για σύνθετες εργασίες μακράς διαρκείας, προτιμάται η χρήση πολυπλεκτών τερματικού όπως το `tmux` ή το `screen`, τα οποία διατηρούν ολόκληρες συνεδρίες ενεργές στον διακομιστή επιτρέποντας επανασύνδεση από οπουδήποτε.

### 2.9 Προγραμματισμός εκτέλεσης διεργασίας με την `at`

Ορισμένες εργασίες απαιτείται να εκτελεστούν σε συγκεκριμένη μελλοντική χρονική στιγμή. Η εντολή `at` προγραμματίζει την **εφάπαξ** εκτέλεση μιας εντολής σε καθορισμένο χρόνο. Διαβάζει τις εντολές προς εκτέλεση από την τυπική είσοδο:

```bash
root@kali:~# at 9:00pm
warning: commands will be executed using /bin/sh
at> /root/simple_bash.sh
at> <EOT>
job 3 at Sat Oct 10 21:00:00 2026
```

Η προειδοποίηση στην αρχή είναι κρίσιμη: η `at` εκτελεί τις εντολές μέσω του `/bin/sh` και όχι μέσω του διαδραστικού σας κελύφους, επομένως ιδιαιτερότητες του bash, ψευδώνυμα και τοπικές μεταβλητές δεν θα ισχύουν, απαιτώντας τη χρήση πλήρων διαδρομών αρχείων. Η προτροπή `at>` δέχεται εντολές ανά γραμμή, και ο συνδυασμός `Ctrl+D` (που εμφανίζεται ως `<EOT>`) σηματοδοτεί το τέλος της εισαγωγής. Η εντολή επιβεβαιώνει τον αριθμό της εργασίας και τον ακριβή χρόνο εκτέλεσης, δεχόμενη ποικίλες μορφές ώρας όπως `at 9:00pm`, `at 14:30`, `at now + 10 minutes` ή `at midnight`.

Η ουρά εκκρεμών εργασιών ελέγχεται με τρεις εντολές: η `atq` παραθέτει τις προγραμματισμένες εργασίες, η `at -c <αριθμός>` εκτυπώνει το πλήρες περιβάλλον και τις εντολές που θα εκτελεστούν (απαραίτητο για αποσφαλμάτωση), και η `atrm <αριθμός>` ακυρώνει την εργασία. Η υποκείμενη υπηρεσία είναι ο δαίμονας `atd`, ενώ η πρόσβαση ελέγχεται από τα αρχεία `/etc/at.allow` και `/etc/at.deny`.

Για εργασίες που απαιτείται να εκτελούνται **επαναλαμβανόμενα** (καθημερινά, κάθε ώρα ή σε εβδομαδιαία βάση), το κατάλληλο εργαλείο είναι το `cron`. Οι προγραμματισμένες εργασίες ενός χρήστη καταγράφονται στο αρχείο crontab, το οποίο επεξεργάζεται με την εντολή `crontab -e`:

```bash
root@kali:~# crontab -l
# m h  dom mon dow   command
  0 3  *   *   *     /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
 30 1  *   *   0     /usr/local/bin/weekly-report.sh
```

Τα πέντε πεδία χρόνου αντιστοιχούν κατά σειρά σε: λεπτό (0-59), ώρα (0-23), ημέρα του μήνα (1-31), μήνα (1-12) και ημέρα της εβδομάδας (0-7, όπου 0 και 7 είναι η Κυριακή), με τον αστερίσκο `*` να σημαίνει «κάθε». Έτσι, η πρώτη γραμμή εκτελεί το αντίγραφο ασφαλείας στις 03:00 κάθε μέρα, ενώ η δεύτερη εκτελεί την εβδομαδιαία αναφορά στις 01:30 κάθε Κυριακή. Καθολικές ρυθμίσεις συστήματος φιλοξενούνται στα `/etc/crontab` και `/etc/cron.d/`, ενώ απλά σενάρια μπορούν να τοποθετηθούν απευθείας στους καταλόγους `/etc/cron.daily`, `/etc/cron.hourly` κ.λπ. Οι σύγχρονες διανομές χρησιμοποιούν επίσης χρονόμετρα systemd (systemd timers), τα οποία ελέγχονται με την `systemctl list-timers`.

Στις δοκιμές ασφάλειας, οι προγραμματισμένες εργασίες έχουν διττή σημασία. Αμυντικά, το `cron` αποτελεί κλασικό μηχανισμό διατήρησης πρόσβασης (persistence) για κακόβουλο λογισμικό, επομένως οποιαδήποτε άγνωστη εργασία απαιτεί άμεσο έλεγχο. Επιθετικά, η εντολή `at` αποτελεί την ασφαλέστερη μέθοδο αυτόματης επαναφοράς ρυθμίσεων (rollback) όταν πρόκειται να τροποποιήσετε το τείχος προστασίας ή το δίκτυο: προγραμματίζοντας εκ των προτέρων την επαναφορά των παλιών ρυθμίσεων σε πέντε λεπτά, διασφαλίζετε ότι δεν θα αποκλειστείτε μόνιμα από το σύστημα εάν η νέα ρύθμιση διακόψει τη σύνδεσή σας.

## 3. Μεταβλητές περιβάλλοντος χρήστη

Οι μεταβλητές είναι ονοματισμένες τιμές — ζεύγη κλειδιού-τιμής που διατηρεί ένα ενεργό κέλυφος — και η κατανόησή τους είναι απαραίτητη για τη διαχείριση του Linux, καθώς μεγάλο μέρος αυτού που ορίζεται ως περιβάλλον λειτουργίας βασίζεται σε αυτές. Διακρίνονται σε δύο κατηγορίες με ουσιαστική διαφορά: Μια **μεταβλητή κελύφους (shell variable)** υφίσταται αποκλειστικά μέσα στο κέλυφος που τη δημιούργησε και είναι αόρατη στα προγράμματα που εκκινούνται από αυτό. Μια **μεταβλητή περιβάλλοντος (environment variable)** έχει εξαχθεί (exported), πράγμα που σημαίνει ότι αντιγράφεται αυτόματα στο περιβάλλον κάθε θυγατρικής διεργασίας και σε κάθε πρόγραμμα που καλείται στη συνέχεια. Οι μεταβλητές κληρονομούνται ιεραρχικά προς τα κάτω στο δέντρο διεργασιών και δεν επιστρέφουν ποτέ προς τα πάνω: μια θυγατρική διεργασία διαβάζει ό,τι της μεταβιβάστηκε, αλλά δεν μπορεί να μεταβάλει το περιβάλλον του γονέα της.

Κατά σύμβαση, τα ονόματα των μεταβλητών γράφονται με κεφαλαία γράμματα (`HOME`, `PATH`, `USER`). Αυτή η διάκριση είναι αυστηρή, καθώς τα ονόματα `HISTSIZE` και `histsize` αντιστοιχούν σε εντελώς διαφορετικές μεταβλητές για το σύστημα.

### 3.1 Προβολή όλων των μεταβλητών

Δύο εντολές καταγράφουν τις μεταβλητές, αντικατοπτρίζοντας τον διαχωρισμό μεταξύ των δύο κατηγοριών. Η εντολή `set`, χωρίς ορίσματα, εκτυπώνει όλες τις μεταβλητές και συναρτήσεις του τρέχοντος κελύφους, συμπεριλαμβανομένων των μεταβλητών περιβάλλοντος. Η εντολή `env` εκτυπώνει αποκλειστικά το εξαγόμενο περιβάλλον, δηλαδή τη λίστα των μεταβλητών που παραδίδονται στις θυγατρικές διεργασίες.

```bash
root@kali:~# set | more
BASH=/usr/bin/bash
BASHOPTS=checkwinsize:cmdhist:complete_fullquote:expand_aliases:extquote:force_fignore:globasciiranges
BASH_ALIASES=()
BASH_ARGC=()
BASH_ARGV=()
BASH_CMDS=()
BASH_COMPLETION_VERSINFO=([0]="2" [1]="11")
BASH_LINENO=()
BASH_SOURCE=()
...
COLUMNS=80
DIRSTACK=()
EUID=0
GROUPS=([0]="0")
HISTFILE=/root/.bash_history
HISTFILESIZE=2000
HISTSIZE=1000
HOME=/root
HOSTNAME=kali
--More--
```

Η διοχέτευση στην εντολή `more` είναι απαραίτητη στην πράξη, καθώς η `set` παράγει εκατοντάδες γραμμές εσωτερικών δεδομένων του κελύφους. Ανάμεσά τους διακρίνονται γνώριμες μεταβλητές: η `HOME` δηλώνει τον προσωπικό κατάλογο, η `HOSTNAME` το όνομα του μηχανήματος, η `HISTFILE` το αρχείο αποθήκευσης ιστορικού και η `HISTSIZE` τον αριθμό εντολών που διατηρεί το κέλυφος στη μνήμη για άμεση ανάκληση με το επάνω βέλος. Επειδή η έξοδος αποτελεί απλό κείμενο, μπορεί να φιλτραριστεί άμεσα.

### 3.2 Φιλτράρισμα για συγκεκριμένη μεταβλητή

Η διοχέτευση της `set` στην `grep` επιτρέπει τον άμεσο εντοπισμό μιας μεταβλητής ανάμεσα σε εκατοντάδες εγγραφές. Εδώ αναζητούμε τη μεταβλητή `HISTSIZE`:

```bash
root@kali:~# set | grep HISTSIZE
HISTFILESIZE=2000
HISTSIZE=1000
root@kali:~# echo "my history holds $HISTSIZE commands"
my history holds 1000 commands
root@kali:~# printenv HISTSIZE

root@kali:~# printenv HOME
/root
```

Η χρήση της `grep` εμφανίζει τις μεταβλητές ιστορικού στη μορφή `όνομα=τιμή`. Η εντολή `echo` εισάγει την τιμή μέσα σε πρόταση, χρησιμοποιώντας το σύμβολο **`$` μπροστά από το όνομα, το οποίο σημαίνει «αντικατάσταση με την τιμή της μεταβλητής»**. Εάν παραλείψετε το σύμβολο του δολαρίου, το κέλυφος θα εκτυπώσει απλώς το λεκτικό όνομα της μεταβλητής.

Η εντολή `printenv` εκτυπώνει *αποκλειστικά την τιμή* μιας μεταβλητής, ιδανική για χρήση σε σενάρια. Στο παράδειγμα παραπάνω, η εντολή `printenv HISTSIZE` δεν επέστρεψε τίποτα απολύτως. Αυτό δεν αποτελεί σφάλμα: η `HISTSIZE` είναι ορισμένη στο τρέχον κέλυφος, αλλά δεν έχει **εξαχθεί** ποτέ στο περιβάλλον, επομένως υφίσταται μόνο τοπικά και η διεργασία `printenv` (όντας θυγατρική διεργασία) δεν μπορεί να τη δει. Αντίθετα, η `printenv HOME` εκτυπώνει κανονικά `/root`, επειδή η `HOME` είναι εξαγμένη μεταβλητή περιβάλλοντος. Αυτό αποτελεί την απόλυτη απόδειξη της διαφοράς μεταξύ μεταβλητής κελύφους και μεταβλητής περιβάλλοντος.

Η διαπίστωση ότι το κέλυφος διατηρεί χίλιες εντολές στο ιστορικό έχει σημασία και στην ασφάλεια: το ιστορικό καταγράφει ό,τι πληκτρολογήθηκε, συμπεριλαμβανομένων κωδικών πρόσβασης που δόθηκαν ως ορίσματα και διευθύνσεων συνδεδεμένων συστημάτων. Γι' αυτό το αρχείο `~/.bash_history` αποτελεί πρωταρχικό στόχο ελέγχου σε παραβιασμένα συστήματα, και η εκκαθάρισή του ή η αποτροπή καταγραφής (προσθέτοντας ένα κενό διάστημα πριν από ευαίσθητες εντολές) αποτελεί βασική συνήθεια διαχειριστών.

### 3.3 Προσωρινή αλλαγή τιμής

Η αλλαγή μιας μεταβλητής πραγματοποιείται με ανάθεση νέας τιμής, χωρίς κενά διαστήματα γύρω από το σύμβολο της ισότητας:

```bash
root@kali:~# HISTSIZE=0
root@kali:~# echo $HISTSIZE
0
root@kali:~# echo $HISTSIZE > ~/valueofHISTSIZE.txt
root@kali:~# cat ~/valueofHISTSIZE.txt
0
```

Η πρώτη γραμμή ορίζει τη μεταβλητή σε μηδέν και η δεύτερη το επιβεβαιώνει. Η συνέπεια είναι άμεση: το κέλυφος παύει να διατηρεί εντολές στη μνήμη για την τρέχουσα συνεδρία, το πάτημα του επάνω βέλους δεν επιστρέφει τίποτα και η ανάκληση ιστορικού απενεργοποιείται μέχρι να επαναφέρετε την τιμή. Αυτό αποδεικνύει πώς μια αλλαγή ενός μόνο χαρακτήρα μπορεί να μεταβάλει αθόρυβα τη λειτουργία του συστήματος χωρίς κανένα μήνυμα σφάλματος.

Δύο σημεία απαιτούν προσοχή. Πρώτον, ο κανόνας των κενών: η σύνταξη `HISTSIZE=0` εκτελεί ανάθεση, ενώ η `HISTSIZE = 0` ερμηνεύεται από το κέλυφος ως απόπειρα εκτέλεσης εντολής με όνομα `HISTSIZE` και δύο ορίσματα, αποτυγχάνοντας με μήνυμα `command not found`. Το σύμβολο της ισότητας πρέπει να εφάπτεται αυστηρά στο όνομα και στην τιμή. Δεύτερον, η ανακατεύθυνση στην τρίτη εντολή αποσκοπεί στην αποθήκευση της τιμής σε αρχείο πριν από οποιαδήποτε αλλαγή, ώστε να είναι δυνατή η επαναφορά. Ο τελεστής `>` δημιουργεί το αρχείο και καταγράφει την τιμή, αν και στο παράδειγμα αποθηκεύτηκε η ήδη τροποποιημένη τιμή (0), υπενθυμίζοντας ότι η λήψη αντιγράφου πρέπει να προηγείται της επεξεργασίας.

### 3.4 Μόνιμη εφαρμογή αλλαγών με την `export`

Η απλή ανάθεση ισχύει μόνο για τη διάρκεια της τρέχουσας συνεδρίας. Εάν ανοίξετε νέο τερματικό, η `HISTSIZE` θα επανέλθει στην τιμή 1000. Για να καταστεί μια αλλαγή καθολική και μόνιμη, πρέπει πρώτα να ενταχθεί στο περιβάλλον μέσω της `export` και στη συνέχεια να καταγραφεί σε αρχείο αρχικοποίησης όπως το `~/.bashrc`.

```bash
root@kali:~# HISTSIZE=0
root@kali:~# export HISTSIZE
root@kali:~# bash -c 'echo "child shell sees HISTSIZE=$HISTSIZE"'
child shell sees HISTSIZE=0
root@kali:~# bash -c 'echo "child shell sees HISTFILE=$HISTFILE"'
child shell sees HISTFILE=
root@kali:~# echo 'export HISTSIZE=0' >> ~/.bashrc
```

Οι δύο πρώτες εντολές αποτελούν την τυπική διαδικασία: ανάθεση τιμής και στη συνέχεια εξαγωγή της μεταβλητής (ή συνεπτυγμένα `export HISTSIZE=0`). Η τρίτη εντολή επιβεβαιώνει την κληρονομικότητα: η `bash -c` εκκινεί ένα νέο θυγατρικό κέλυφος, το οποίο διαβάζει κανονικά την εξαχθείσα τιμή 0. Η τέταρτη εντολή λειτουργεί ως αντιπαραβολή: η μεταβλητή `HISTFILE`, μη έχοντας εξαχθεί, εμφανίζεται κενή στο θυγατρικό κέλυφος, επιβεβαιώνοντας τον κανόνα της κληρονομικότητας.

Η τελευταία γραμμή καθιστά τη ρύθμιση μόνιμη προσαρτώντας την στο αρχείο `~/.bashrc`, το οποίο εκτελείται κάθε φορά που ξεκινά ένα διαδραστικό κέλυφος bash. Ο τελεστής `>>` προσθέτει τη γραμμή στο τέλος του αρχείου διατηρώντας τα υπάρχοντα δεδομένα. Η χρήση του απλού `>` σε αυτό το σημείο θα διέγραφε όλες τις προηγούμενες ρυθμίσεις του χρήστη. Η επιλογή του αρχείου εξαρτάται από τον τύπο του κελύφους: `~/.bashrc` για διαδραστικά κελύφη, `~/.profile` για συνεδρίες σύνδεσης, και αρχεία στο `/etc/profile.d/` για καθολικές ρυθμίσεις σε όλο το σύστημα. Μια αλλαγή στο `~/.bashrc` τίθεται σε ισχύ στο επόμενο τερματικό ή άμεσα στο τρέχον μέσω της εντολής `source ~/.bashrc`.

### 3.5 Δημιουργία και διαγραφή προσαρμοσμένων μεταβλητών

Οι μεταβλητές δεν περιορίζονται σε όσες ορίζει το σύστημα. Μπορείτε να δημιουργήσετε δικές σας μεταβλητές με οποιοδήποτε όνομα για να αποθηκεύσετε τιμές που πληκτρολογείτε συχνά:

```bash
root@kali:~# url_variable="example.com"
root@kali:~# echo $url_variable
example.com
root@kali:~# echo "the target is $url_variable"
the target is example.com
root@kali:~# url_variable=example.org
root@kali:~# echo $url_variable
example.org
root@kali:~# unset url_variable
root@kali:~# echo $url_variable

root@kali:~#
```

Η ανάθεση δημιουργεί τη μεταβλητή και η `echo $url_variable` διαβάζει την τιμή της, ενώ υποστηρίζεται άμεσα η ενσωμάτωσή της μέσα σε μεγαλύτερες συμβολοσειρές. Η επαναληπτική ανάθεση μεταβάλλει την τιμή της οποιαδήποτε στιγμή. Αντίστροφα, η εντολή `unset` διαγράφει πλήρως τη μεταβλητή από το κέλυφος, με αποτέλεσμα η επόμενη κλήση της `echo` να εκτυπώνει κενή γραμμή, καθώς μια μη ορισμένη μεταβλητή αναπτύσσεται σε κενό χωρίς να παράγει σφάλμα.

Αυτή η σιωπηρή ανάπτυξη κενών τιμών αποτελεί συχνή αιτία σφαλμάτων σε σενάρια: εάν ένα όνομα μεταβλητής πληκτρολογηθεί λάθος, η εντολή εκτελείται με ελλιπή ορίσματα αντί να διακοπεί. Οι δύο βασικές άμυνες περιλαμβάνουν τη χρήση εισαγωγικών (π.χ. `"$url_variable"`), η οποία αποτρέπει τον κατακερματισμό κενών ορισμάτων, καθώς και τη συντακτική μορφή ελέγχου `${var:?μήνυμα}`, η οποία διακόπτει το σενάριο με προειδοποίηση εάν η μεταβλητή δεν έχει οριστεί (π.χ. `: "${url_variable:?παρακαλώ ορίστε τη μεταβλητή url_variable}"`).

Επιπλέον, η χρήση εισαγωγικών κατά την ανάθεση αποτελεί καλή πρακτική: η εντολή `url_variable="the example domain"` λειτουργεί σωστά, ενώ χωρίς εισαγωγικά θα προκαλούσε συντακτικό σφάλμα καθώς το κέλυφος θα προσπαθούσε να εκτελέσει το δεύτερο τμήμα ως εντολή.

### 3.6 Σημαντικές μεταβλητές συστήματος

Η κατανόηση συγκεκριμένων βασικών μεταβλητών διευκολύνει άμεσα τη διάγνωση προβλημάτων στο σύστημα.

Η μεταβλητή `PATH` είναι η κρισιμότερη όλων: περιέχει μια λίστα καταλόγων διαχωρισμένων με άνω και κάτω τελεία, τους οποίους το κέλυφος ερευνά διαδοχικά για να εντοπίσει την εντολή που πληκτρολογήσατε. Η εντολή `export PATH="$PATH:/opt/tools/bin"` προσθέτει νέους καταλόγους στη διαδρομή αναζήτησης, με τη σειρά να καθορίζει ποιο εκτελέσιμο υπερισχύει εάν υπάρχει συνωνυμία. Σε επίπεδο ασφάλειας, ένα `PATH` που περιλαμβάνει την τρέχουσα διαδρομή `.` επιτρέπει την εκτέλεση κακόβουλων αρχείων από κοινόχρηστους φακέλους, ενώ ένας εγγράψιμος κατάλογος στην αρχή του `PATH` του root συνιστά σοβαρό κενό κλιμάκωσης προνομίων.

Η μεταβλητή `HOME` ορίζει τον προσωπικό κατάλογο και αποτελεί την τιμή στην οποία αναπτύσσεται η περισπωμένη `~`. Κάθε πρόγραμμα που αποθηκεύει ρυθμίσεις βασίζεται σε αυτήν. Οι μεταβλητές `USER` και `LOGNAME` περιέχουν το όνομα του συνδεδεμένου λογαριασμού, ενώ η `SHELL` καταγράφει το προεπιλεγμένο κέλυφος. Η `PS1` διαμορφώνει την εμφάνιση της προτροπής εντολών (prompt), επιτρέποντας την προσθήκη χρωμάτων και πληροφοριών. Οι `HISTFILE`, `HISTSIZE` και `HISTFILESIZE` ρυθμίζουν το αρχείο και το μέγεθος του ιστορικού εντολών. Οι `LANG` και `LC_ALL` καθορίζουν τη γλώσσα, την κωδικοποίηση χαρακτήρων και τη σειρά ταξινόμησης, εξηγώντας γιατί η εντολή `sort` μπορεί να συμπεριφέρεται διαφορετικά σε διαφορετικά συστήματα. Οι `EDITOR` και `VISUAL` ορίζουν τον επεξεργαστή που ανοίγουν αυτόματα εργαλεία όπως το `crontab -e` και το `git commit`, καθιστώντας την εντολή `export EDITOR=nano` εξαιρετικά χρήσιμη για αρχάριους. Τέλος, η μεταβλητή `LD_PRELOAD` δίνει εντολή στον δυναμικό συνδέτη να φορτώσει μια κοινόχρηστη βιβλιοθήκη πριν από όλες τις άλλες σε κάθε διεργασία: αποτελεί νόμιμο εργαλείο αποσφαλμάτωσης, αλλά ταυτόχρονα κλασικό μηχανισμό κλιμάκωσης προνομίων όταν επηρεάζει δυαδικά αρχεία με SUID, καθιστώντας την παρουσία της σε περιβάλλον παραγωγής άξια άμεσης διερεύνησης.

Συνολικά, τα τρία αντικείμενα αυτού του μέρους — δίκτυα, διεργασίες και μεταβλητές περιβάλλοντος — συνιστούν το ενδιάμεσο επίπεδο γνώσης ανάμεσα στην απλή χρήση της γραμμής εντολών και την ουσιαστική διαχείριση ή αξιολόγηση ενός συστήματος Linux.

## 5. Ασκήσεις πρακτικής εξάσκησης

Οι έννοιες και οι εντολές αυτού του οδηγού εμπεδώνονται πλήρως μόνο μέσω πρακτικής εφαρμογής. Παρατίθεται μια σειρά συνδυαστικών ασκήσεων που βασίζονται στην ύλη των δύο πρώτων μερών. Συνιστάται να εργαστείτε σε εικονική μηχανή ή περιέκτη (container), λαμβάνοντας προηγουμένως ένα στιγμιότυπο.

Στην πρώτη ενότητα ασκήσεων δικτύου, καταγράψτε τη διεύθυνση IP της διεπαφής σας, τη μάσκα υποδικτύου, τη διεύθυνση MAC, την προεπιλεγμένη πύλη και τον διαμορφωμένο επιλυτή DNS. Αλλάξτε χειροκίνητα τη διεύθυνση IP και αποδείξτε ότι η μεταβολή είναι προσωρινή κάνοντας επανεκκίνηση της υπηρεσίας δικτύου. Πλαστογραφήστε τη διεύθυνση MAC, εκτελέστε την `dhclient` και εξηγήστε ποια διεύθυνση IP αποδόθηκε πίσω και για ποιον λόγο. Τέλος, χρησιμοποιήστε την `dig` για να ανακτήσετε τις εγγραφές A, MX και NS ενός τομέα της επιλογής σας, διατυπώνοντας σε μία πρόταση τι πληροφορία παρέχει ο κάθε τύπος εγγραφής.

Στη δεύτερη ενότητα ασκήσεων διεργασιών, εντοπίστε τη διεργασία που καταναλώνει τη μεγαλύτερη μνήμη RAM καθώς και εκείνη με τη μεγαλύτερη χρήση επεξεργαστή. Εκτελέστε μια μακροχρόνια εντολή με την ελάχιστη δυνατή προτεραιότητα (nice 19) στο παρασκήνιο, εμφανίστε την με την `jobs -l`, θέστε την προσωρινά σε παύση, στείλτε την ξανά στο παρασκήνιο και επαναφέρετέ την στο προσκήνιο. Προγραμματίστε μια ακίνδυνη εντολή μέσω της `at` για εκτέλεση δύο λεπτά αργότερα και επιβεβαιώστε την ολοκλήρωσή της. Στείλτε το σήμα `SIGTERM` σε μια δική σας δοκιμαστική διεργασία και, μόνο εάν αυτή δεν ανταποκριθεί, κλιμακώστε σε `SIGKILL`, τεκμηριώνοντας γραπτώς γιατί η τήρηση αυτής της σειράς είναι κρίσιμη.

Στην τρίτη ενότητα ασκήσεων μεταβλητών περιβάλλοντος, εκτυπώστε την τιμή της `HISTSIZE`, αποθηκεύστε την σε ένα αρχείο στον προσωπικό σας κατάλογο, τροποποιήστε την τοπικά για το τρέχον κέλυφος και αποδείξτε ότι ένα νέο θυγατρικό κέλυφος δεν βλέπει την αλλαγή. Στη συνέχεια, εξάγετέ την με την εντολή `export`, αποδείξτε ότι το θυγατρικό κέλυφος λαμβάνει πλέον τη νέα τιμή, και τέλος καταστήστε τη μόνιμη προσθέτοντάς την στο `~/.bashrc`. Δημιουργήστε μια δική σας προσαρμοσμένη μεταβλητή, χρησιμοποιήστε την μέσα σε μια εντολή και διαγράψτε την με την `unset`, παρατηρώντας σε τι αναπτύσσεται μια διαγραμμένη μεταβλητή.

Εάν μπορείτε να ολοκληρώσετε αυτές τις ασκήσεις χωρίς να ανατρέξετε σε εξωτερικές πηγές, έχετε κατακτήσει το επίπεδο που γεφυρώνει την απλή χρήση της γραμμής εντολών με τη διαχείριση συστημάτων, και είστε πλήρως έτοιμοι για το Μέρος 3.

## Τελικές παρατηρήσεις

Τα τρία θέματα αυτού του μέρους μοιράζονται ένα κοινό χαρακτηριστικό: αφορούν όλα **καταστάσεις του συστήματος από τις οποίες εξαρτώνται άλλες λειτουργίες**. Από τη διεύθυνση IP εξαρτάται κάθε δικτυακή σύνδεση που πραγματοποιεί το μηχάνημα. Από μια διεργασία εξαρτάται οποιοσδήποτε χρήστης ή εφαρμογή αξιοποιεί την υπηρεσία που αυτή παρέχει. Από μια μεταβλητή περιβάλλοντος εξαρτώνται όλες οι θυγατρικές διεργασίες που την κληρονομούν αθόρυβα. Γι' αυτό οι εντολές αυτού του οδηγού έχουν μεγαλύτερο αντίκτυπο από εκείνες του 1ου Μέρους: ένα λάθος δεν παράγει απλώς ένα μήνυμα σφάλματος, αλλά οδηγεί σε ένα σύστημα που συμπεριφέρεται διαφορετικά από το αναμενόμενο, επηρεάζοντας συχνά τρίτους χρήστες.

Δύο θεμελιώδεις συνήθειες προστατεύουν από τους περισσότερους κινδύνους. Η πρώτη είναι να *επιθεωρείτε την κατάσταση πριν αλλάξετε οτιδήποτε*: διαβάζετε ένα αρχείο ρυθμίσεων πριν το αντικαταστήσετε, εκτελείτε την `pgrep` πριν καλέσετε την `pkill`, ελέγχετε τον πίνακα διευθύνσεων πριν τροποποιήσετε μια διεπαφή, και αποθηκεύετε την τιμή μιας μεταβλητής πριν την αφαιρέσετε. Η δεύτερη συνήθεια είναι να *διατηρείτε πάντα οδό επιστροφής*: ένα στιγμιότυπο εικονικής μηχανής, μια δεύτερη ενεργή κονσόλα διαχείρισης, ή μια προγραμματισμένη αυτόματη επαναφορά μέσω της `at` πριν προβείτε σε αλλαγές δικτύου.

Το **Μέρος 3** αποτελεί τη συνέχεια όπου όλα αυτά τα στοιχεία συνδυάζονται. Καλύπτει τη συγγραφή **σεναρίων κελύφους και την αυτοματοποίηση** — συνθήκες, βρόχους, συναρτήσεις και μεταβλητές, οργανωμένα σε ολοκληρωμένα προγράμματα που εκτελούν εργασίες ωρών σε δευτερόλεπτα — μαζί με τον **προγραμματισμό εργασιών** μέσω `cron` και τη **διαχείριση υπηρεσιών** μέσω `systemctl` (συμπεριλαμβανομένων των διακομιστών Apache, OpenSSH και FTP). Πέρα από τη σειρά των τριών μερών, τα επόμενα φυσικά βήματα περιλαμβάνουν τη δημιουργία προσαρμοσμένων μονάδων systemd, τη διαχείριση ρυθμίσεων σε πολλαπλούς διακομιστές και τη βαθύτερη μελέτη των προχωρημένων μηχανισμών ασφάλειας και δικαιωμάτων του Linux.
