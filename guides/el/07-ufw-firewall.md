# UFW: Εκπαιδευτικός Οδηγός Ρύθμισης Firewall

> **Χρήση μόνο σε συστήματα που σας ανήκουν ή διαχειρίζεστε με εξουσιοδότηση.** Μια αλλαγή firewall μπορεί να διακόψει SSH, web υπηρεσίες, monitoring και άλλες λειτουργίες. Πριν αλλάξετε απομακρυσμένο server, διατηρήστε ενεργή συνεδρία SSH και διαθέστε console ή out-of-band πρόσβαση για ανάκτηση.

## Πώς να διαβάζετε αυτόν τον οδηγό

Κάθε βήμα εμφανίζεται με τον ίδιο τρόπο: η **εντολή** που πληκτρολογείτε, η **έξοδος** που παράγει και, στη συνέχεια, μια σύντομη επεξήγηση για το τι συνέβη και πώς να διαβάσετε το αποτέλεσμα. Για παράδειγμα:

```bash
id
```

**Έξοδος:**

```text
uid=1000(student) gid=1000(student) groups=1000(student),27(sudo)
```

Το πλαίσιο εντολής δείχνει τι ακριβώς εκτελείτε· το πλαίσιο εξόδου δείχνει τι απάντησε το μηχάνημα. Η έξοδος είναι ενδεικτική — διευθύνσεις, εκδόσεις και process IDs διαφέρουν στο δικό σας lab.

Οι παράγραφοι μετά από κάθε έξοδο εξηγούν *τι κάνει το εργαλείο* και *γιατί έχει σημασία το βήμα*, ώστε να μάθετε τη μέθοδο, όχι μόνο τη σύνταξη.

<details>
<summary><strong>Περισσότερα</strong> — ο ρυθμός που ακολουθεί κάθε ενότητα</summary>

Κάθε ενότητα ακολουθεί τον ίδιο ρυθμό. Πρώτα διαβάζετε σε τι χρησιμεύει το βήμα. Μετά βλέπετε την ακριβή εντολή, στο δικό της πλαίσιο. Έπειτα την έξοδο που παρήγαγε, σε ξεχωριστό πλαίσιο. Τέλος, μια σύντομη εξήγηση δένει τα δύο και σας λέει τι να προσέξετε μετά.

Οτιδήποτε μεγαλύτερο — επιπλέον παράμετροι, παγίδες, θεωρία, εναλλακτικές και προειδοποιήσεις — βρίσκεται σε συμπτυσσόμενο πλαίσιο σαν αυτό, ώστε να διαβάζετε πρώτα την κύρια ροή και να ανοίγετε τη λεπτομέρεια μόνο όταν τη θέλετε.

</details>

## 1. Τι είναι το UFW

Το UFW, δηλαδή Uncomplicated Firewall, είναι εργαλείο γραμμής εντολών για τη διαχείριση κανόνων firewall σε Linux.

Προσφέρει πιο κατανοητές εντολές από την απευθείας επεξεργασία κανόνων χαμηλού επιπέδου. Μπορεί να ελέγχει πρόσβαση με βάση source IP, subnet, service profile, θύρα και πρωτόκολλο. Είναι συνήθως διαθέσιμο σε διανομές βάσει Debian, όπως Ubuntu και Debian.

<details>
<summary><strong>Περισσότερα</strong> — πού βρίσκεται ένα firewall και τι δεν αντικαθιστά</summary>

Το UFW λειτουργεί μαζί με τις υπηρεσίες του host, τα cloud security groups, το routing και τυχόν upstream firewall. Ένας κανόνας που επιτρέπει SSH στο UFW δεν αρκεί αν το cloud firewall μπλοκάρει τη σύνδεση.

Το firewall δεν αντικαθιστά authentication, ενημερώσεις λογισμικού ή ασφαλή ρύθμιση εφαρμογών. Αποφασίζει ποιες συνδέσεις φτάνουν σε μια υπηρεσία· δεν αποφασίζει ποιους εμπιστεύεται η υπηρεσία μόλις ανοίξει η σύνδεση.

Επίσης δεν περιγράφει κίνηση που ανήκει σε σύνδεση η οποία είχε ήδη εδραιωθεί πριν προστεθεί ο κανόνας, γι' αυτό εξετάζετε χωριστά τις εκτεθειμένες υπηρεσίες.

</details>

## 2. Προετοιμασία και ασφάλεια

Χρειάζεστε administrative privileges για κάθε εντολή UFW σε αυτόν τον οδηγό.

Συνδεθείτε μέσω εξουσιοδοτημένης συνεδρίας SSH ή τοπικής κονσόλας και εντοπίστε τη θύρα SSH πριν ενεργοποιήσετε το firewall. Αν ο server χρησιμοποιεί μη τυπική θύρα, αντικαταστήστε τη στα παραδείγματα.

Ένας χρήσιμος αρχικός έλεγχος είναι να επιβεβαιώσετε ποιοι είστε και τι ακούει στο δίκτυο:

```bash
id
```

**Έξοδος:**

```text
uid=1000(admin) gid=1000(admin) groups=1000(admin)
```

Η `id` επιβεβαιώνει τον τρέχοντα χρήστη και τις ομάδες του, δηλαδή αν κατέχετε πραγματικά τα administrative δικαιώματα που προϋποθέτει ο οδηγός.

```bash
sudo ss -tulpn
```

**Έξοδος:**

```text
Netid State  Local Address:Port  Process
LISTEN 0      128    0.0.0.0:22   users:(('sshd',pid=742,fd=3))
LISTEN 0      128    0.0.0.0:80   users:(('apache2',pid=911,fd=4))
```

Η `ss -tulpn` εμφανίζει τις listening TCP και UDP υποδοχές μαζί με τη διεργασία που κατέχει καθεμία. Εδώ το SSH ακούει στη θύρα 22 και το HTTP στη θύρα 80· το inventory αυτό πρέπει να καθοδηγεί τους κανόνες, γι' αυτό μην επιτρέπετε μηχανικά κάθε υπηρεσία που εντοπίζετε.

<details>
<summary><strong>Περισσότερα</strong> — ανάγνωση της εξόδου <code>ss</code> και αποφυγή αποκλεισμού</summary>

Κάθε γραμμή του `ss -tulpn` είναι μία listening υποδοχή. Το `Netid` δηλώνει την οικογένεια πρωτοκόλλου (`tcp`, `udp`, `tcp6`). Το `Local Address:Port` είναι το σημείο όπου η υπηρεσία δέχεται συνδέσεις· το `0.0.0.0:22` σημαίνει κάθε διεπαφή IPv4 στη θύρα 22, ενώ το `127.0.0.1:5432` θα σήμαινε ότι η υπηρεσία είναι προσβάσιμη μόνο από το ίδιο το μηχάνημα. Η στήλη `Process` ονομάζει το πρόγραμμα και το PID του — έτσι μαθαίνετε ποια υπηρεσία κατέχει μια θύρα.

Πριν ενεργοποιήσετε firewall απομακρυσμένα, κρατήστε ανοιχτή μια υπάρχουσα συνεδρία SSH, επιβεβαιώστε τη θύρα SSH και με δεύτερο τρόπο (τη ρύθμιση του daemon ή την κονσόλα του παρόχου) και βεβαιωθείτε ότι υπάρχει δρόμος ανάκτησης. Ένας ανεκτικός κανόνας που προστέθηκε βιαστικά ανακτάται· ένας αποκλεισμός σε απομακρυσμένο server χωρίς console access, όχι.

</details>

## 3. Εγκατάσταση UFW

Σε Debian-based διανομή, ανανεώστε τα metadata των πακέτων και εγκαταστήστε το UFW:

```bash
sudo apt update
```

**Έξοδος:**

```text
Reading package lists... Done
Building dependency tree... Done
All packages are up to date.
```

Η `apt update` ανανεώνει το τοπικό ευρετήριο των διαθέσιμων πακέτων από τα ρυθμισμένα repositories· δεν εγκαθιστά ούτε αναβαθμίζει τίποτα.

```bash
sudo apt install ufw
```

**Έξοδος:**

```text
Reading package lists... Done
Building dependency tree... Done
The following NEW packages will be installed:
  ufw
Setting up ufw ...
```

Η `apt install ufw` κατεβάζει και εγκαθιστά το εργαλείο διαχείρισης firewall και τα υποστηρικτικά αρχεία. Η ακριβής έξοδος διαφέρει ανά διανομή και έκδοση πακέτου, οπότε εξετάζετε πάντα τυχόν prompts πριν επιβεβαιώσετε αλλαγές.

Ελέγξτε την αρχική κατάσταση:

```bash
sudo ufw status verbose
```

**Έξοδος:**

```text
Status: inactive
```

Το `inactive` σημαίνει ότι το UFW είναι εγκατεστημένο αλλά δεν εφαρμόζει ακόμη κανόνες.

Αυτή η αρχική ανενεργή κατάσταση είναι χρήσιμη, γιατί επιτρέπει να δημιουργήσετε πολιτική πρόσβασης πριν ενεργοποιήσετε την επιβολή της.

<details>
<summary><strong>Περισσότερα</strong> — γιατί το UFW ξεκινά ανενεργό και τι δεν κάνει η εγκατάσταση</summary>

Η εγκατάσταση του πακέτου τοποθετεί την εντολή `ufw`, τα application profiles κάτω από το `/etc/ufw/applications.d` και ένα σύνολο προεπιλεγμένων αρχείων ρύθμισης. Δεν αλλάζει από μόνη της τον ενεργό packet filter — αυτό συμβαίνει μόνο όταν ενεργοποιήσετε το UFW ή φορτώσετε κανόνες.

Αυτός ο διαχωρισμός είναι ο λόγος ύπαρξης όλης της ροής εργασίας: χτίστε πρώτα την πολιτική και μετά ανάψτε την επιβολή. Η ενεργοποίηση firewall χωρίς κανόνα SSH είναι ο συχνότερος τρόπος να αποκλειστείτε από απομακρυσμένο μηχάνημα.

</details>

## 4. Ασφαλής προεπιλεγμένη πολιτική

Πριν ενεργοποιήσετε το UFW, επιλέξτε προεπιλεγμένες πολιτικές. Μια συνηθισμένη πολιτική server απορρίπτει νέες εισερχόμενες συνδέσεις και επιτρέπει εξερχόμενες:

```bash
sudo ufw default deny incoming
```

**Έξοδος:**

```text
Default incoming policy changed to 'deny'
```

Η incoming policy ελέγχει νέες συνδέσεις προς τον server· θέτοντάς την σε `deny` απορρίπτετε εξ ορισμού την ανεπιθύμητη κίνηση.

```bash
sudo ufw default allow outgoing
```

**Έξοδος:**

```text
Default outgoing policy changed to 'allow'
```

Η outgoing policy ελέγχει συνδέσεις που ξεκινά ο server, οι οποίες συνήθως χρειάζονται για ενημερώσεις, DNS και συγχρονισμό ώρας. Οι προεπιλογές δεν αντικαθιστούν τους ειδικούς κανόνες υπηρεσιών και δεν μπλοκάρουν απαραίτητα κίνηση που ανήκει σε ήδη εδραιωμένη σύνδεση.

<details>
<summary><strong>Περισσότερα</strong> — γιατί το «deny incoming, allow outgoing» είναι το συνηθισμένο σημείο εκκίνησης</summary>

Ένας server συνήθως πρέπει να απαντά σε αιτήματα που ήδη γνωρίζει να εξυπηρετεί, και συνήθως πρέπει να βγαίνει έξω για ενημερώσεις, DNS και συγχρονισμό ώρας. Το «deny incoming» με «allow outgoing» ταιριάζει σε αυτό το σχήμα και ταυτόχρονα μπλοκάρει ανεπιθύμητες συνδέσεις που κανείς δεν ζήτησε.

Οι προεπιλογές είναι η *εφεδρεία*: περιγράφουν τι συμβαίνει σε σύνδεση που δεν ταίριαξε με κανέναν ρητό κανόνα. Η σειρά μετράει λιγότερο για τις προεπιλογές παρά για τους κανόνες, γιατί οι προεπιλογές εξετάζονται μόνο όταν δεν εφαρμόζεται κανένας κανόνας.

</details>

## 5. Επιτρέψτε το SSH πριν την ενεργοποίηση

Επιτρέψτε την πραγματική θύρα SSH πριν ενεργοποιήσετε το firewall:

```bash
sudo ufw allow 22/tcp
```

**Έξοδος:**

```text
Rule added
Rule added (v6)
```

Ο κανόνας επιτρέπει TCP συνδέσεις στη θύρα 22 για IPv4 και IPv6, εφόσον και οι δύο οικογένειες διευθύνσεων είναι ενεργές.

Αν το SSH χρησιμοποιεί διαφορετική θύρα, χρησιμοποιήστε τη σωστή:

```bash
sudo ufw allow 7822/tcp
```

Μην επιτρέπετε τη θύρα 22 απλώς επειδή είναι η συνηθισμένη. Επιβεβαιώστε τη θύρα με `ss`, τη ρύθμιση του SSH daemon ή την κονσόλα του παρόχου. Κρατήστε ανοιχτή την τρέχουσα συνεδρία SSH έως ότου δοκιμαστεί νέα σύνδεση.

<details>
<summary><strong>Περισσότερα</strong> — IPv4, IPv6 και οι δύο γραμμές επιβεβαίωσης</summary>

Η γραμμή `Rule added` είναι ο κανόνας IPv4· το `Rule added (v6)` είναι το δίδυμό του για IPv6. Το UFW προσθέτει και τους δύο όταν το σύστημα έχει και τις δύο στοίβες, γι' αυτό μία εντολή παράγει δύο μηνύματα.

Το να κρατάτε ανοιχτή την υπάρχουσα συνεδρία έχει σημασία γιατί η συνεδρία είναι ήδη *εδραιωμένη*: το κλείσιμο του firewall πάνω σε ζωντανή σύνδεση συνήθως δεν την κόβει, αλλά καμία *νέα* σύνδεση δεν γίνεται δεκτή μέχρι ένας κανόνας να το επιτρέψει. Γι' αυτό δοκιμάζετε μια δεύτερη συνεδρία πριν κλείσετε την πρώτη.

</details>

## 6. Profiles εφαρμογών

Δείτε τα διαθέσιμα application profiles:

```bash
sudo ufw app list
```

**Έξοδος:**

```text
Available applications:
  Apache
  Apache Full
  OpenSSH
```

Τα profiles προέρχονται από εγκατεστημένα αρχεία εφαρμογών. Ένα profile αντιστοιχίζει φιλικό όνομα σε μία ή περισσότερες θύρες και πρωτόκολλα.

Εξετάστε το πριν το χρησιμοποιήσετε:

```bash
sudo ufw app info "Apache Full"
```

**Έξοδος:**

```text
Profile: Apache Full
Title: Web Server (HTTP,HTTPS)
Ports: 80/tcp,443/tcp
```

Η έξοδος δείχνει ότι το profile ανοίγει HTTP και HTTPS. Το `Apache Full` επιτρέπει γενικά και τα δύο.

Αν απαιτείται μόνο κρυπτογραφημένη web πρόσβαση, προτιμήστε profile ή ρητό κανόνα που επιτρέπει μόνο την 443.

```bash
sudo ufw allow "Apache Full"
```

**Έξοδος:**

```text
Rule added
Rule added (v6)
```

Τα εισαγωγικά χρειάζονται επειδή το όνομα περιέχει κενό. Μην ανοίγετε υπηρεσία που δεν είναι εγκατεστημένη, αναγκαία, παρακολουθούμενη και σωστά ασφαλισμένη.

<details>
<summary><strong>Περισσότερα</strong> — τι είναι στην πραγματικότητα ένα application profile</summary>

Ένα profile είναι ένα μικρό αρχείο, συνήθως κάτω από το `/etc/ufw/applications.d/`, που δίνει σε μια υπηρεσία ένα όνομα και μια λίστα θυρών. Το `OpenSSH` συνοδεύει το πακέτο, γι' αυτό εμφανίζεται στη λίστα ακόμη και σε μηχάνημα που δεν είχε ποτέ web server.

Το `app info` δείχνει τις θύρες πίσω από το φιλικό όνομα. Η συνήθεια που αξίζει να χτίσετε είναι να τρέχετε `app info` πριν το `app allow`: το profile είναι διευκόλυνση, όχι υπόσχεση ότι θα ανοίξουν μόνο οι θύρες που περιμένατε.

</details>

## 7. Επιτρέψτε συγκεκριμένη IP

Για να επιτρέψετε κάθε υποστηριζόμενη κίνηση από μία trusted πηγή:

```bash
sudo ufw allow from 192.168.1.1
```

**Έξοδος:**

```text
Rule added
```

Ο κανόνας βασίζεται στην πηγή. Είναι ευρύς, γιατί μπορεί να επιτρέπει πρόσβαση σε πολλές τοπικές υπηρεσίες αν δεν συνδυαστεί με θύρα ή υπηρεσία προορισμού. Ένας στενότερος κανόνας είναι συχνά ασφαλέστερος:

```bash
sudo ufw allow from 192.168.1.1 to any port 22 proto tcp
```

Αυτό επιτρέπει SSH μόνο από τη συγκεκριμένη IP. Το `to any port 22` ορίζει την υπηρεσία προορισμού και το `proto tcp` περιορίζει τον κανόνα σε TCP.

Αφαιρέστε τον ευρύ κανόνα όταν δεν τον χρειάζεστε πια:

```bash
sudo ufw delete allow from 192.168.1.1
```

**Έξοδος:**

```text
Rule deleted
```

Η εντολή διαγραφής πρέπει να αντιστοιχεί στο νόημα του κανόνα. Αν ο αρχικός κανόνας είχε θύρα ή πρωτόκολλο, διαγράψτε τον αντίστοιχο πλήρη κανόνα ή χρησιμοποιήστε αριθμημένους κανόνες.

<details>
<summary><strong>Περισσότερα</strong> — γιατί το «από μια IP» είναι ευρύτερο απ' ό,τι φαίνεται</summary>

Το `allow from 192.168.1.1` λέει «αυτός ο host μπορεί να με προσεγγίσει σε *κάθε* θύρα». Σε μηχάνημα που τρέχει μόνο SSH είναι αβλαβές· σε μηχάνημα που τρέχει και βάση δεδομένων ή admin panel, είναι μεγαλύτερη τρύπα απ' ό,τι σκοπεύατε. Μόλις προσθέσετε `to any port 22 proto tcp`, ο κανόνας περιορίζεται σε μία υπηρεσία και ένα πρωτόκολλο.

Επειδή το νόημα ενός κανόνα εξαρτάται από κάθε μέρος του, το UFW διαγράφει τον κανόνα βρίσκοντας έναν που ταιριάζει με τους ίδιους όρους. Η διαγραφή διαφορετικής διατύπωσης μπορεί σιωπηλά να μη διαγράψει τίποτα — ή να διαγράψει κάτι άλλο. Γι' αυτό ακριβώς υπάρχει η αριθμημένη λίστα στις επόμενες ενότητες.

</details>

## 8. Επιτρέψτε subnet

```bash
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
```

**Έξοδος:**

```text
Rule added
```

Το δίκτυο `/24` περιέχει τις διευθύνσεις στο εύρος `192.168.1.0` έως `192.168.1.255`, τηρουμένων των συμβάσεων δικτύου. Το παράδειγμα επιτρέπει SSH μόνο από αυτό το δίκτυο.

Χρησιμοποιείτε τα εύρη subnet προσεκτικά: ένα υπερβολικά ευρύ trusted δίκτυο μπορεί να εκθέσει administrative υπηρεσίες σε περισσότερα συστήματα απ' ό,τι σκοπεύατε.

<details>
<summary><strong>Περισσότερα</strong> — πώς υπολογίζεται ένα επίθημα CIDR</summary>

Ο αριθμός μετά την κάθετο είναι το μήκος του προθέματος δικτύου. Το `/24` καθηλώνει τα πρώτα 24 bit και αφήνει 8 ελεύθερα, καλύπτοντας 256 διευθύνσεις· το `/16` αφήνει 16 ελεύθερα και καλύπτει 65.536· το `/32` καθηλώνει και τα 32 και ονομάζει ακριβώς έναν host.

Ο κανόνας είναι να κρατάτε το trusted δίκτυο τόσο μικρό όσο απαιτεί η ανάγκη. Ένα `/24` για subnet γραφείου είναι σχεδιαστική απόφαση· ένα `/16` «επειδή ήταν ευκολότερο» εμπιστεύεται σιωπηλά χιλιάδες διευθύνσεις.

</details>

## 9. Προβολή και διαγραφή αριθμημένων κανόνων

```bash
sudo ufw status numbered
```

**Έξοδος:**

```text
Status: active

     To                         Action      From
[ 1] 22/tcp                     ALLOW IN    192.168.1.1
[ 2] 80/tcp                     ALLOW IN    Anywhere
[ 3] 443/tcp                    ALLOW IN    Anywhere
```

Η αριθμημένη λίστα δείχνει σειρά, προορισμό, ενέργεια, κατεύθυνση και πηγή. Ελέγξτε την πριν διαγράψετε οτιδήποτε.

Για διαγραφή του δεύτερου κανόνα:

```bash
sudo ufw delete 2
```

**Έξοδος:**

```text
Deleting:
 allow 80/tcp
Proceed with operation (y|n)? y
Rule deleted
```

Οι αριθμοί αλλάζουν μετά από διαγραφές. Εκτελείτε ξανά `ufw status numbered` πριν διαγράψετε επόμενο κανόνα, αντί να βασίζεστε σε παλιά λίστα.

<details>
<summary><strong>Περισσότερα</strong> — γιατί η αρίθμηση κερδίζει την επανάληψη του κανόνα</summary>

Η διαγραφή με αριθμό είναι ακριβής και σας δείχνει το κείμενο του κανόνα πριν ενεργήσει — γι' αυτό είναι η ασφαλέστερη από τις δύο μορφές διαγραφής. Η διαγραφή με διατύπωση εξαρτάται από το να πετύχετε κάθε όρο ακριβώς, και ένα σχεδόν-σωστό μπορεί να αποτύχει σιωπηλά.

Το κόστος είναι ότι οι αριθμοί είναι θέσεων: διαγράψτε τον κανόνα 2 και ο παλιός κανόνας 3 γίνεται κανόνας 2. Γι' αυτό η οδηγία να ξανατρέχετε το `status numbered` πριν από κάθε διαγραφή δεν είναι σχολαστικότητα — είναι ο κανόνας που οι περισσότεροι μαθαίνουν με τον δύσκολο τρόπο.

</details>

## 10. Απόρριψη IP ή subnet

Για να μπλοκάρετε διεύθυνση πηγής:

```bash
sudo ufw deny from 192.168.1.1
```

**Έξοδος:**

```text
Rule added
```

Για να μπλοκάρετε subnet:

```bash
sudo ufw deny from 192.168.1.0/24
```

Ένας κανόνας `deny` απορρίπτει την ταιριαστή κίνηση. Οι ευρείες αρνήσεις μπορεί να μπλοκάρουν administrators, monitoring ή health checks. Προτιμήστε ακριβείς κανόνες και καταγράψτε τον λόγο ύπαρξης κάθε deny.

Για αφαίρεση:

```bash
sudo ufw delete deny from 192.168.1.1
```

**Έξοδος:**

```text
Rule deleted
```

Η διαγραφή αντιστοιχεί στους όρους του αρχικού κανόνα· αν ο κανόνας περιλάμβανε θύρα ή πρωτόκολλο, η αντίστοιχη εντολή πρέπει να τα περιλαμβάνει επίσης. Ελέγξτε ξανά την αριθμημένη λίστα πριν από την επόμενη αλλαγή.

<details>
<summary><strong>Περισσότερα</strong> — deny έναντι reject, και γιατί το μπλοκ είναι τελευταία λύση</summary>

Ένας κανόνας `deny` απορρίπτει την ταιριαστή κίνηση. Κάποια front-ends προσφέρουν και λειτουργία που απαντά με ρητή άρνηση αντί για σιωπή· η διαφορά αφορά κυρίως το πόσο γρήγορα μαθαίνει ένας scanner ότι η θύρα υπάρχει, και είναι επιλογή ρύθμισης, όχι κάτι που αποφασίζει το UFW για σας.

Ο λόγος να είστε προσεκτικοί είναι ότι μια άρνηση γράφεται εύκολα και δύσκολα ερμηνεύεται αργότερα. Ένα μπλοκ για έναν θορυβώδη host είναι εντάξει· ένα μπλοκ για ολόκληρο subnet μπορεί να βγάλει εκτός έναν administrator, έναν monitoring agent ή ένα health check, και το σύμπτωμα εμφανίζεται αλλού. Καταγράψτε τον λόγο δίπλα σε κάθε μπλοκ, ώστε ο επόμενος να μη χρειάζεται να μαντέψει.

</details>

## 11. Ενεργοποίηση και επαλήθευση

Αφού προστεθούν όλοι οι απαιτούμενοι κανόνες, ενεργοποιήστε το UFW:

```bash
sudo ufw enable
```

**Έξοδος:**

```text
Command may disrupt existing ssh connections. Proceed with operation (y|n)? y
Firewall is active and enabled on system startup
```

Η προειδοποίηση υπάρχει επειδή λανθασμένη πολιτική μπορεί να τερματίσει ή να εμποδίσει το SSH. Επιβεβαιώστε ότι υπάρχει κανόνας για τη σωστή θύρα SSH πριν απαντήσετε `y`.

Η δεύτερη γραμμή σημαίνει ότι το UFW είναι ενεργό τώρα και ρυθμισμένο να ξεκινά κατά το boot.

Ελέγξτε την πλήρη ρύθμιση:

```bash
sudo ufw status verbose
```

**Έξοδος:**

```text
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere
80/tcp                     ALLOW IN    Anywhere
443/tcp                    ALLOW IN    Anywhere
22/tcp (v6)                ALLOW IN    Anywhere (v6)
```

Η `status verbose` εμφανίζει αν το UFW είναι ενεργό, την κατάσταση logging, τις default policies και τους ενεργούς κανόνες. Οι IPv6 εγγραφές είναι σημαντικές όταν ο server έχει IPv6, διαφορετικά η αξιολόγηση μόνο IPv4 μπορεί να δώσει ψευδή αίσθηση κάλυψης.

```bash
sudo ufw show added
```

**Έξοδος:**

```text
Added user rules (see 'ufw status' for running firewall rules):
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
```

Το `show added` παραθέτει ακριβώς τους κανόνες που εισήχθησαν μέσω εντολών `ufw`, χρήσιμο για επισκόπηση ή αναδημιουργία της πολιτικής σας αργότερα.

<details>
<summary><strong>Περισσότερα</strong> — ανάγνωση της επικεφαλίδας verbose, γραμμή προς γραμμή</summary>

Το `Status: active` σημαίνει ότι η επιβολή είναι ενεργή. Το `Logging: on (low)` είναι το τρέχον επίπεδο logging. Το `Default: deny (incoming), allow (outgoing), disabled (routed)` επαναλαμβάνει τις προεπιλεγμένες πολιτικές της ενότητας 4, και το σκέλος `disabled (routed)` δείχνει ότι το UFW δεν προωθεί κίνηση μεταξύ διεπαφών. Το `New profiles: skip` λέει τι κάνει το UFW όταν συναντήσει application profile που δεν έχει ξαναδεί.

Η τελική απόφαση είναι πάντα ο πίνακας κανόνων: αν μια θύρα εμφανίζεται με `ALLOW IN`, νέες συνδέσεις σε αυτή γίνονται δεκτές. Αν τίποτα δεν ταιριάζει με μια νέα εισερχόμενη σύνδεση, η προεπιλογή deny-incoming καθορίζει τη μοίρα της.

</details>

## 12. Logging και αντιμετώπιση προβλημάτων

Ενεργοποιήστε μέτριο logging όταν χρειάζεστε ορατότητα στην κίνηση που απορρίπτεται:

```bash
sudo ufw logging medium
```

**Έξοδος:**

```text
Logging enabled
```

Η εντολή θέτει το επίπεδο logging του firewall· το `medium` καταγράφει αρκετή λεπτομέρεια για να ερευνήσετε απορριφθείσα κίνηση χωρίς να πλημμυρίζει το log.

```bash
sudo ufw status verbose
```

**Έξοδος:**

```text
Status: active
Logging: on (medium)
```

Η γραμμή κατάστασης επιβεβαιώνει ότι το νέο επίπεδο ισχύει. Περισσότερο logging βοηθά στη διάγνωση αλλά αυξάνει τον όγκο των logs, οπότε κρατήστε το επίπεδο όσο χαμηλό επιτρέπει η έρευνα.

Εξετάστε τα firewall και kernel logs με το σύστημα καταγραφής της διανομής σας, για παράδειγμα:

```bash
sudo journalctl -k --since "10 minutes ago" | grep -i ufw
```

**Έξοδος:**

```text
kernel: [UFW BLOCK] IN=eth0 OUT= SRC=203.0.113.50 DST=198.51.100.10 PROTO=TCP DPT=23
```

Το `UFW BLOCK` δηλώνει απορριφθέν πακέτο. Το `SRC` είναι η πηγή, το `DST` ο προορισμός, το `PROTO` το πρωτόκολλο και το `DPT` η θύρα προορισμού.

Τα logs βοηθούν να ξεχωρίσετε κακόβουλες σαρώσεις από νόμιμη κίνηση που αποκλείστηκε κατά λάθος. Τα παραδείγματα τεκμηρίωσης χρησιμοποιούν δεσμευμένες διευθύνσεις· τα πραγματικά logs θα περιέχουν τις δικές σας διευθύνσεις.

<details>
<summary><strong>Περισσότερα</strong> — από μία γραμμή log σε απόφαση</summary>

Μια γραμμή μπλοκ είναι ερώτηση, όχι ετυμηγορία. Διαβάστε την πηγή, τον προορισμό και τη θύρα και μετά αποφασίστε αν η κίνηση ήταν εχθρική (σάρωση σε θύρα που δεν τρέχετε) ή νόμιμη (monitoring host που ξεχάσατε να επιτρέψετε).

Τα επίπεδα logging ξεκινούν από το `off` και ανεβαίνουν· όσο υψηλότερο το επίπεδο, τόσο περισσότερη λεπτομέρεια ανά συμβάν και τόσο γρηγορότερα μεγαλώνει το log. Κρατήστε ήσυχο επίπεδο σε κανονική λειτουργία και ανεβάστε το μόνο όσο ερευνάτε, ώστε ένα πολυάσχολο log να μην κρύβει τα συμβάντα που σας ενδιαφέρουν.

</details>

## 13. Reload, disable και reset

Μετά από χειροκίνητες αλλαγές σε υποστηριζόμενη ρύθμιση του UFW, φορτώστε ξανά τους κανόνες:

```bash
sudo ufw reload
```

**Έξοδος:**

```text
Firewall reloaded
```

Το reload εφαρμόζει τη ρύθμιση χωρίς επανεκκίνηση συστήματος. Αν το firewall συμπεριφέρεται περίεργα, εξετάστε κανόνες και logs πριν κάνετε περαιτέρω αλλαγές.

Για προσωρινή απενεργοποίηση:

```bash
sudo ufw disable
```

**Έξοδος:**

```text
Firewall stopped and disabled on system startup
```

Το disable σταματά την ενεργή επιβολή και εμποδίζει την αυτόματη εκκίνηση στο boot. Χρησιμοποιήστε το μόνο όταν γνωρίζετε την έκθεση που δημιουργείται. Ασφαλέστερη επιλογή είναι συχνά να διορθώσετε ή να διαγράψετε έναν συγκεκριμένο κανόνα.

Για επιστροφή του UFW σε καθαρή κατάσταση:

```bash
sudo ufw reset
```

**Έξοδος:**

```text
Resetting all rules to installed defaults. Proceed with operation (y|n)? y
Backing up 'user.rules' to '/etc/ufw/user.rules.20261008_190000'
```

Το reset διαγράφει τους user-defined κανόνες και επαναφέρει τις προεπιλογές. Μπορεί να αφαιρέσει και την εξαίρεση SSH που κρατά δυνατή την απομακρυσμένη πρόσβαση, επομένως προτιμήστε console ή βεβαιωθείτε ότι μπορείτε να επαναφέρετε άμεσα τους απαιτούμενους κανόνες. Τα backups και η ακριβής έξοδος διαφέρουν ανά διανομή.

<details>
<summary><strong>Περισσότερα</strong> — reload, disable και reset δεν είναι εναλλάξιμα</summary>

Το `reload` κρατά την πολιτική και την εφαρμόζει ξανά — αυτό θέλετε μετά την επεξεργασία ενός υποστηριζόμενου αρχείου. Το `disable` σταματά την επιβολή αλλά αφήνει τους κανόνες αποθηκευμένους, οπότε το μηχάνημα είναι εκτεθειμένο μέχρι να ενεργοποιήσετε ξανά το UFW. Το `reset` πετά το σύνολο κανόνων και επιστρέφει στις προεπιλογές εγκατάστασης· επειδή η εξαίρεση SSH είναι μέρος των «user rules», είναι από τα τρία αυτό που πιθανότερα θα σας αποκλείσει.

Ο κοινός παρονομαστής είναι ότι και τα τρία αλλάζουν τι επιβάλλεται, οπότε και τα τρία ανήκουν σε στιγμή που έχετε console access ή σχέδιο ανάκτησης.

</details>

## 14. ICMP και ping

Το ping χρησιμοποιεί ICMP, όχι TCP ή UDP. Ο αποκλεισμός του ping δεν κάνει έναν server αόρατο και μπορεί να επηρεάσει monitoring, path MTU discovery, διάγνωση και λειτουργία IPv6.

Στα περισσότερα περιβάλλοντα είναι καλύτερο να επιτρέπονται τα απαραίτητα ICMP types και να βασίζεστε σε authentication, ενημερώσεις, least privilege και monitoring για την ασφάλεια.

Αν κάποια τεκμηριωμένη πολιτική απαιτεί αλλαγή της συμπεριφοράς ICMP πριν το routing ή το input, κρατήστε πρώτα backup:

```bash
sudo cp -a /etc/ufw/before.rules /etc/ufw/before.rules.backup
```

Η `cp -a` αντιγράφει το αρχείο διατηρώντας τα χαρακτηριστικά του· στο Linux μια επιτυχημένη αντιγραφή δεν εκτυπώνει τίποτα, οπότε η σιωπή εδώ είναι επιτυχία και το backup υπάρχει πλέον.

```bash
sudoedit /etc/ufw/before.rules
```

Το `sudoedit` ανοίγει το αρχείο στον editor σας με ασφαλέστερη ροή που δεν τρέχει τον editor ως root· αποθηκεύετε και βγαίνετε όπως συνήθως, και ένα συντακτικό λάθος εδώ μπορεί να εμποδίσει το UFW να φορτώσει.

```bash
sudo ufw reload
```

**Έξοδος:**

```text
Firewall reloaded
```

Το `ufw reload` ζητά από το UFW να φορτώσει την επεξεργασμένη ρύθμιση, και η γραμμή επιβεβαίωσης δείχνει ότι οι νέοι κανόνες ισχύουν.

Δοκιμάστε μετά τόσο την επιθυμητή όσο και την ανεπιθύμητη κίνηση, και εξετάστε τη ρύθμιση IPv6 ξεχωριστά, γιατί οι κανόνες ICMP του IPv4 δεν περιγράφουν αυτόματα τη συμπεριφορά του IPv6.

<details>
<summary><strong>Περισσότερα</strong> — τι είναι το <code>before.rules</code> και γιατί το επεξεργάζεστε τελευταίο</summary>

Το `/etc/ufw/before.rules` περιέχει τους ακατέργαστους κανόνες που το UFW εισάγει πριν από τους user rules — εκεί μένει η διαχείριση ICMP, το connection tracking και άλλα στοιχεία χαμηλού επιπέδου. Επειδή βρίσκεται πιο κοντά στον packet filter από οτιδήποτε πληκτρολογείτε με το `ufw`, ένα συντακτικό λάθος μπορεί να εμποδίσει το `ufw` να φορτώσει καθόλου.

Γι' αυτό το βήμα backup με `cp -a` έρχεται πρώτο, γι' αυτό η επεξεργασία περνά από το `sudoedit` αντί για απλό root editor, και γι' αυτό το reload είναι ξεχωριστό, συνειδητό βήμα που μπορείτε να παρακολουθήσετε. Αντιμετωπίστε αυτό το αρχείο ως την εξαίρεση που αγγίζετε σκόπιμα, όχι ως μέρος της καθημερινής διαχείρισης κανόνων.

</details>

## 15. Τελική λίστα επαλήθευσης

Μετά τη ρύθμιση, επικυρώστε από εξουσιοδοτημένο management host και από τον ίδιο τον server:

```bash
sudo ufw status numbered
```

**Έξοδος:**

```text
Status: active

     To                         Action      From
[ 1] 22/tcp                     ALLOW IN    192.168.1.1
[ 2] 80/tcp                     ALLOW IN    Anywhere
[ 3] 443/tcp                    ALLOW IN    Anywhere
```

Το `status numbered` δείχνει τους ενεργούς κανόνες με τη θέση τους, ώστε να επιβεβαιώσετε ότι κάθε προοριζόμενη υπηρεσία επιτρέπεται από τη σωστή πηγή.

```bash
sudo ss -tulpn
```

**Έξοδος:**

```text
Netid State  Local Address:Port  Process
LISTEN 0      128    0.0.0.0:22   users:(('sshd',pid=742,fd=3))
LISTEN 0      128    0.0.0.0:80   users:(('apache2',pid=911,fd=4))
```

Η εντολή inventory της ενότητας 2 επαναλαμβάνεται εδώ, γιατί η πολιτική και οι listening υποδοχές πρέπει να διαβάζονται δίπλα-δίπλα.

Επιβεβαιώστε ότι:

- Η θύρα SSH επιτρέπεται μόνο από τις απαιτούμενες administrative πηγές.
- Οι web θύρες είναι ανοικτές μόνο όταν η υπηρεσία πρέπει να είναι δημόσια.
- Δεν εκτίθενται μη χρησιμοποιούμενες υπηρεσίες.
- Οι IPv4 και IPv6 κανόνες συμφωνούν με τη σχεδίαση.
- Οι default policies είναι καταγεγραμμένες.
- Το logging έχει κατάλληλο επίπεδο.
- Υπάρχει rollback plan ή console access.

<details>
<summary><strong>Περισσότερα</strong> — πώς δοκιμάζετε πραγματικά την πολιτική, όχι μόνο τη διαβάζετε</summary>

Η ανάγνωση του πίνακα κανόνων επιβεβαιώνει τι *σκοπεύατε*. Μια δοκιμή επιβεβαιώνει τι *κάνει* το μηχάνημα. Συνδεθείτε από host που πρέπει να επιτρέπεται και από host που δεν πρέπει, και επιβεβαιώστε ότι οι δύο απαντήσεις διαφέρουν προς την αναμενόμενη κατεύθυνση.

Συνδυάστε τις δύο παραπάνω εντολές για έναν λόγο: η πρώτη είναι η πολιτική σας, η δεύτερη είναι τι ακούει πραγματικά. Θύρα που ακούει χωρίς αντίστοιχο κανόνα είναι είτε υπηρεσία που ξεχάσατε να δημοσιεύσετε είτε υπηρεσία που ξεχάσατε να κλείσετε — και ο μόνος τρόπος να τις ξεχωρίσετε είναι να ελέγξετε τη σχεδίαση.

</details>

## 16. Βασικά μαθήματα

Μια σωστή πολιτική firewall χτίζεται από inventory υπηρεσιών και trusted πηγών, όχι από τυφλή αντιγραφή εντολών.

Ξεκινήστε με περιοριστική προεπιλογή, επιτρέψτε μόνο την απαραίτητη κίνηση, ελέγξτε τους κανόνες που προέκυψαν και δοκιμάστε τη συνδεσιμότητα πριν κλείσετε τη διαχειριστική συνεδρία.

Εξηγήστε την έξοδο κάθε εντολής στο change record, ώστε ο επόμενος administrator να καταλάβει τι ενεργοποιήθηκε, τι αποκλείστηκε και τι αφαιρέθηκε.

<details>
<summary><strong>Περισσότερα</strong> — οι συνήθειες που αξίζει να κρατήσετε</summary>

Χτίστε από το inventory προς τα έξω: μάθετε τι ακούει πριν αποφασίσετε τι επιτρέπεται. Αφήστε το default deny να κάνει τη βαριά δουλειά και προσθέστε κανόνες μόνο όπου μια υπηρεσία πρέπει πραγματικά να είναι προσβάσιμη.

Έπειτα επαληθεύστε, δύο φορές: μία στα χαρτιά, διαβάζοντας το `ufw status numbered`, και μία στην πράξη, δοκιμάζοντας μια σύνδεση που πρέπει να πετύχει και μία που πρέπει να αποτύχει. Καταγράψτε το αποτέλεσμα, γιατί μια αλλαγή firewall που δεν καταγράφηκε είναι μια αλλαγή firewall που κανείς δεν μπορεί να αναιρέσει με ασφάλεια.

</details>
